## 0. Процедура - как этим пользоваться (сама суть ГОСТа)

1. **Перед постройкой любого UI** - прочитать этот файл. Токены, компоненты, тайминги
   и звуки берутся ОТСЮДА, не изобретаются. Если нужный паттерн здесь есть -
   копировать его буквально (вплоть до чисел), не "по мотивам".
2. **Если нужного паттерна нет** - сначала короткое предложение Владу (что добавляем
   и почему), после одобрения паттерн ДОПИСЫВАЕТСЯ в этот файл отдельной правкой,
   и только потом используется. ГОСТ - живой документ, но меняется явно, не молча.
3. **Крупная фича** (новый экран целиком) - методика "параллельные агенты-специалисты
   (дизайн / моушн / звук / дата-виз - по необходимости) + оркестратор". Каждому
   агенту в промпт передаётся ссылка на этот файл (или его выжимка: токены + запреты).
   Конфликт спеки агента с ГОСТом решается в пользу ГОСТа, либо выносится Владу.
4. **Перед сдачей** - прогнать чек-лист приёмки (раздел 10). Не прошёл пункт - не сдаём.
5. Этот файл упомянут в `CLAUDE.md` (таблица "Где что искать" + цикл после фичи) -
   каждая новая сессия обязана его увидеть.
6. **ПРЕВЬЮ = КОНТРАКТ (жёсткое правило, Влад 28.08 после трёх итераций доточки).**
   Утверждённое превью переносится в живой код 1:1 - КАЖДЫЙ блок и КАЖДАЯ деталь:
   шрифт и регистр заголовков, формат чисел (запятая!), наличие/отсутствие
   треков-подложек, строки шапки, подписи, бейджи. Частичный перенос ("этот блок
   потом, чтобы не трогать логику") ЗАПРЕЩЁН - он хуже отсутствия переноса, потому
   что ломает доверие к согласованному макету и заставляет заказчика ходить и
   сверять мелочи. Перед сдачей - открыть превью и живую страницу РЯДОМ и пройти
   блок за блоком глазами, а не только по чек-листу. Сверка обязана включать ТО,
   ЧЕГО НЕ ВИДНО НА СТАТИКЕ (пойманы Владом 28.08 уже ПОСЛЕ "полной" сверки):
   - ИНТЕРАКТИВНЫЕ состояния: провести курсором по каждому блоку - hover/cursor/
     фокус легко теряются при переносе, скриншоты и статичная сверка их не ловят;
   - ЖИВЫЕ значения: часы, "обновлено N минут назад", счётчики - всё, что содержит
     текущее время, обязано тикать (интервал), а не застывать снимком момента
     загрузки. Показ времени без тика = баг по определению.
6-бис. **СТАНДАРТ НЕ ПРИБИВАЕТСЯ К ОДНОЙ СТРАНИЦЕ (Влад, 29.08).** Если приём
   объявлен стандартом (hover-физика, курсорный свет, единый тост), его CSS/JS
   обязан селектиться ОБЩИМ правилом (`.page`, `.card`), а не `#page-main`.
   Прецедент: физика жила на `#page-main`, поэтому личная страница вышла без неё,
   и Влад ловил это вручную. Скоуп по id допустим только там, где приём
   действительно уникален для экрана, и тогда это надо назвать явно.
6-тер. **В ОБЩИЙ ЭЛЕМЕНТ ПИШЕТ ТОЛЬКО ОДНО МЕСТО (Влад, 29.08).** Шапка страницы,
   тост, сайдбар - общие на весь дашборд. Если такой элемент заполняет и навигация
   (`showPage`), и рендер конкретной страницы, значение протекает на чужие экраны.
   Прецедент: `renderMyPage()` писал ФИО менеджера прямо в `#page-title`, и на
   ГЛАВНОЙ в админском аккаунте вместо «Панель управления» появлялась фамилия.
   Правило: рендер страницы кладёт значение в СОСТОЯНИЕ, а в общий DOM его
   подставляет единственный владелец элемента (здесь - `showPage`), для текущей
   страницы. Проверка при сдаче: открыть другую страницу и убедиться, что чужие
   данные из шапки ушли.
7. **Ошибка → правило → прочесать всё (в тот же заход).** Каждая найденная ошибка
   или недопонимание немедленно оформляется жёстким правилом (сюда или в память
   проекта), и сразу же прочёсываются ВСЕ места кодовой базы с тем же классом
   ошибки - не только то, где заметили симптом. Цель - сокращать число итераций
   до идеала, а не исправлять по одной точке за раз.

## 1. Цвет

### Токены (канон)

```css
:root{
  --bg:#0f0f13;      /* фон страницы */
  --bg2:#17171d;     /* поверхность карточки/панели */
  --bg3:#1e1e26;     /* вложенная поверхность (карточка в колонке, кнопка) */
  --bg4:#252530;     /* самый верхний слой (hover, бейдж-фон, трек) */
  --border:rgba(255,255,255,0.08);
  --border-strong:rgba(255,255,255,0.16);
  --text:#e8e6df;
  --muted:#8b8980;   /* в старом files/index.html лежит легаси #888780 - при
                        редизайне выравнивать на #8b8980 */
  --green:#1D9E75; --red:#E24B4A; --amber:#EF9F27;
  --blue:#378ADD;  --purple:#7F77DD;
}
```

Тема - тёмная, единственная. Фон всегда красится явно (`background:var(--bg)`).

### Семантика (цвет = смысл, НИКОГДА не декорация)

| Токен | Значит | Примеры |
|---|---|---|
| `--green` | хорошо / план выполняется / деньги получены / "в работе" | прогресс к плану, выигранная сделка, поступления |
| `--red` | требует внимания / потеря / долг растёт / ремонт | рамка attention-карточки, растущий спарклайн ДЗ, штрафы |
| `--amber` | деньги в риске / предупреждение | ДЗ-индикаторы, прогноз 90-100% плана, "без заказа" |
| `--blue` | нейтральные данные / серия по умолчанию / канал Авито | полосы затрат, drop-подсветка |
| `--purple` | канал "звонок" / ответственный | аватар, бейдж канала |

Жёсткие правила:
- **Одна красная рамка на страницу.** Если красных карточек две - это уже не сигнал.
- Крупные заливки - 10-35% непрозрачности своего hue (area спарклайна 14%,
  прогноз-сегмент 30%, прошлые дни 35%). 100% цвета - только тонким маркам: линии
  2px, точки, тики, дельты.
- Текст не красится в цвета данных. Исключения: дельты (±%) и значение внутри
  терминального состояния (сумма выигранной сделки).
- Hero-цифра карточки ВСЕГДА `--text`, даже в attention-состоянии. Красная рамка -
  сигнал; красная большая цифра - паника.
- Бейджи по СМЫСЛУ, не по знаку: "+2,3 млн" у дебиторки = bad (красный),
  "+11%" у выручки = good. Рост не равен "хорошо".
- `--blue` и `--purple` НЕ ставить соседними кодировками в одном чарте - при
  дейтеранопии неразличимы (ΔE 0.3, проверено валидатором).

## 2. Типографика

| Шрифт | Роль | Запрещено |
|---|---|---|
| `Golos Text` | весь UI: лейблы, текст, кнопки | - |
| `Unbounded` | ТОЛЬКО заголовок страницы/секции (display) | внутри карточек, в таблицах, в лейблах |
| `JetBrains Mono` | все цифры, суммы, метки времени, счётчики | длинный текст |

- `font-variant-numeric: tabular-nums` ОБЯЗАТЕЛЕН везде, где цифра меняется
  (тикеры, одометры) или выравнивается в столбик (суммы затрат, легенды, aux-колонки).
- Шкала размеров (px): 9, 10.5, 11, 11.5, 12, 12.5, 13, 17, 19, 25, 31.
  Hero-цифра карточки 1-го яруса - 31; 2-го яруса - 25; KPI канбана - 19.
- Капс-лейблы карточек: 11px, weight 600, letter-spacing .09em, цвет `--muted`.
- Полные рубли до единицы - только в hero ("57 052 166 ₽" - сверка с 1С это фича).
  Во вторичных строках - сокращения ("57,1 млн"), десятичный знак - запятая.
  Единая точность внутри одного блока строк.

## 3. Сетка, отступы, радиусы, глубина

- Сетка страницы: 12 колонок, `gap:14-16px`, max-width 1280-1480px.
  Брейкпоинты: <=1100px (половины), <=720px (одна колонка).
- Паддинг карточки: `18px 20px`. Карточка сделки (канбан): колонка 248px,
  паддинг `10px 12px`.
- Радиусы: **12** (карточки, панели - потолок, выше нельзя), 10 (карточка сделки),
  8 (кнопки), 6 (бейджи), 3 (полосы, свотчи, юниты), 2 (мини-элементы).
- **Глубина - ступенями фона** bg → bg2 → bg3 → bg4 (+hover на полступени, #191920),
  НЕ тенями. `box-shadow` разрешён только объекту, который физически "над" доской
  (перетаскиваемая карточка - двухслойная тень `0 2px 6px rgba(0,0,0,.4),
  0 16px 32px rgba(0,0,0,.5)`).
- Hover НЕ меняет геометрию страницы: никаких раскрытий с изменением высоты.
  Скрытая деталь живёт в слоте фиксированной высоты (`.peek`, opacity 0→1).

## 4. Компоненты (анатомии - копировать из референсов)

Точные CSS-классы и разметка - в `examples/design-reference-panel.html` (префикс
`d5-`) и `examples/design-reference-kanban.html` (префикс `mx-`). Здесь - что это
и правила. Новый экран обязан переиспользовать эти анатомии.

- **KPI-карточка** (`d5-card`): шапка (капс-лейбл + бейдж) → hero-число → микро-
  визуализация → строки → peek (видна на hover). Состояние attention: тонированная
  красная рамка на всю карточку (НЕ боковая полоска), точка 6px у лейбла, бейдж bad.
- **Строка "метрика-значение"** (`d5-row`): grid `label | точечный-лидер | value |
  aux`; лидер - `1px dotted` на 12% белого; aux-колонка `min-width:5.5ch` держит
  проценты столбиком. Итоговая строка - единственная сплошная hairline сверху.
- **Табло-карусель метрик** (заменила worst-first вердикт на главной, Влад 28.08):
  ОДНА строка-плашка, карусель из 10 ключевых метрик, ротация раз в 10 сек. Смена -
  сплит-флэп как табло аэропорта: символы прокручиваются через случайные глифы
  (интервал 45ms) и волной слева направо встают на место (каскад: 3 + позиция×0.35
  + 0-2 случайных прокрута). Моноширинный шрифт обязателен (ячейки .62em). Слева
  цветная точка-тип (green/amber/red, меняется со сменой метрики), справа счётчик
  "N/10". Hover - пауза ротации (метка ПАУЗА), клик - navClick-тик + переход к
  блоку метрики. БЕЗ звука на самом перещёлкивании (Влад, 28.08: "часто будет
  шуршать, отвлекать" - карусель тикает каждые 10с весь рабочий день, тихий шелест
  на КАЖДОЙ смене превращается в фоновый шум; звук остаётся только на клике-
  переходе). При обновлении данных текущая метрика перещёлкивается, если текст
  изменился. document.hidden /
  prefers-reduced-motion - символы сразу финальные, скрытая вкладка не крутит
  ротацию.
- **Карточка сделки** (`mx-card`): клиент + точка свежести → груз · маршрут → вес ·
  дата · канал → сумма + аватар. Свежесть по принципу "тишина = норма": у здоровой
  карточки индикатора НЕТ вообще; amber-точка >2ч без ответа, red - зависла.
- **Bullet-чарт** (план/факт/прогноз в одной полосе): шкала 0-120% плана (тик плана
  всегда на 83.3%), трек 8px пилюля, факт - заливка, прогноз - тот же hue 30%
  с зазором 2px, тик плана 2x16px белый. **Цвет заливки по ПРОГНОЗУ, не по факту:**
  прогноз >=100% плана - green, 90-100% - amber, <90% - red (в середине месяца факт
  50% - норма, а не тревога).
- **Спарклайн**: высота 40px, monotone cubic (не прямые сегменты, не обычный Безье),
  линия 2px round, area-градиент 14%→0, конечная точка r4 с кольцом 2px цвета фона.
  Цвет всей линии по тренду окна (порог ±2%): для долгов рост = red. Без осей, без
  сетки, без подписей внутри поля.
- **Дни-колонки** (поступления): прошлые дни - green 35%, сегодня - green 100% +
  точка "вы здесь" 3px, будущие дни - плейсхолдеры 2px на 7% белого. Скругление
  верха <=2px.
- **Затраты / любые доли**: bar-per-row (полосы от общей левой базы), НЕ пончик.
  Одна серия = один цвет (blue); исключение - семантика (Штрафы red).
- **Вафля парка** (unit chart): юнит 12x12px r3 gap4, одна машина = один квадрат.
  в работе = green, ремонт = red, без заказа = amber, без водителя = ПУСТОЙ квадрат
  с рамкой border-strong, нет статуса = bg3. Сумма квадратов = размеру парка;
  расхождение данных показывается юнитами "нет статуса", не прячется.
- **Тост - ЕДИНСТВЕННЫЙ канал уведомлений всей системы (жёсткое правило, Влад
  28.08: "один принцип на все - неважно, поступление денег или новая заявка")**:
  полупрозрачная плитка снизу по центру, всплывает и потихоньку исчезает - вход
  320ms снизу (translateY+opacity, кривая drawer), автоскрытие 5с, выход 200ms.
  Плашка bg4 + border-strong + radius 10; слева цветная точка-тип 6px: green =
  успех/деньги, amber = информация/внимание, red = ошибка. Повторный вызов
  ретаргетит текущий тост (transition, не keyframes) и перезапускает таймер.
  При отменяемом действии - кнопка "Отменить" внутри. ЗАПРЕЩЕНО: alert(),
  браузерные диалоги для уведомлений, самодельные плашки других форм - любое
  событие (деньги пришли, заявка, сохранено, ошибка сети) идёт ТОЛЬКО этим тостом.
- **Drawer**: справа, ~280px, `translateX(100%)→0`,
  `cubic-bezier(.34,1.45,.5,1)` ~380ms, backdrop 50% черного.
- **Контекстное меню (правая кнопка мыши) - СВОЁ, не браузерное** (Влад, 29.08:
  «при нажатии... не должно возникать стандартного браузерного меню, а должно
  возникать меню нашего приложения... на пустом месте ничего не должно
  происходить»). На интерактивном элементе (плитка/карточка/строка) -
  `e.preventDefault()` на `contextmenu` + собственное плавающее меню:
  `position:fixed` у курсора (зажато в пределах окна, не уезжает за край),
  `bg3` + `border-strong` + `radius:10px` + тень как у HUD/тоста, пункты -
  текстовые кнопки, деструктивный пункт (удаление) - `--red`. Закрытие: клик
  вне меню, `Escape`, скролл ленты (меню на `fixed`-координатах - при скролле
  контента открепляется от того, над чем было вызвано). **На ПУСТОМ месте той
  же поверхности** - тот же `preventDefault()`, но без показа меню: браузерное
  меню запрещено везде на интерактивной поверхности, не только там, где есть
  своё меню взамен.
- **`autocomplete="off"` на КАЖДОМ текстовом/дата-инпуте площадки, где не нужен
  явно** (Влад, 29.08: «мы это уже фиксили в калькуляторе... нигде не должно
  вылетать из автозаполнения, навязываемого браузером»). Автоподсказки браузера
  (сохранённые ранее значения похожих полей) - не то же самое, что собственный
  `<datalist>`-автокомплит (адреса и т.п. - свой список остаётся, это
  осознанная подсказка приложения, не браузера). Правило касается любого поля
  ввода в любой шторке/форме дашборда, не только Планировки.

### Hover-физика карточки (канон, из канбана уровня 5; на панели - с 28.08)

**ДВА УРОВНЯ, ТРЕТЬЕГО НЕТ** (Влад, 29.08: «есть плитки, которые классно работают -
на главной умеренное движение и небольшой вылет, акцентирует внимание. А на других
она скачет, прыгает и сильно вылетает. Эти параметры нужно жёстко зафиксировать»).
Числа ниже - единственные разрешённые, свои значения не изобретать:

| Что | Кто это | hover-transform |
|---|---|---|
| **ПЛИТКА** | `.kpi`, `.mp-stat` - небольшой блок с одной метрикой | `translateY(-1px) translateZ(22px)` |
| **ПОВЕРХНОСТЬ** | `.card`, `.mp-status` - крупный блок, полоса, панель | `translateY(-1px)` (БЕЗ вылета) |
| **ПОВЕРХНОСТЬ С ТАБЛИЦЕЙ** | `.card:has(table)` | `none` (см. границу применимости ниже) |

- **`perspective:1400px` ставится на СЕТКУ плиток, а не на страницу.** Это не
  стилистика, а корень «прыжка»: при перспективе на всей странице величина эффекта
  зависит от удалённости элемента от центра страницы. Замерено на стенде с одним и
  тем же CSS: плитка вверху экрана уезжала на **−10,2px** по Y, точно такая же внизу
  - на **+5,8px**. С перспективой на сетке обе дают **−2,05px**, одинаково.
  Носители: `.kpi-grid`, `.grid-2`, `.p2-tier3-grid`, `.mp-tier`, `.mp-stats` - новая
  сетка плиток должна попасть в этот список, иначе её плитки не вылетают вовсе.
- **Вылет (`translateZ`) - только у плиток.** Он масштабирует элемент на +1,6%, и
  это ощущается по-разному в зависимости от ширины: плитка 242px растёт на **+4,3px**
  («умеренно акцентирует», эталон главной), а карточка 1004px - на **+16,5px**, что
  Влад и назвал «сильно вылетает». Поэтому у поверхностей вылета нет.
- фон на полступени вверх + `border-color:var(--border-strong)` - у обоих уровней;
- transition: `.12s ease-out` по background/border/transform (поимённо, не all);
- иерархия отклика (три уровня, утверждено Владом 28.08): 1) любая карточка -
  подъём+фон ("я тебя слышу"); 2) проваливаемая - ещё cursor:pointer и сдвиг
  шеврона; 3) attention - рамка дополнительно краснеет;
- курсорный свет (раздел 7) на той же поверхности - по умолчанию ВКЛЮЧЁН для
  панелей/досок: radial 600px blue 6-10%, lerp 0.12/кадр, слой z-index:-1
  относительно карточек, гаснет при уходе курсора, rAF самоостанавливается;
- `prefers-reduced-motion`: transform и свет выключены, цветовые отклики остаются.

**ГРАНИЦА ПРИМЕНИМОСТИ - карточка с таблицей НЕ поднимается** (Влад, 29.08, на
«Динамике»: «большие крупные таблицы анимировать не нужно, слишком раздражает,
когда она дёргается; на небольших плитках, как на главной панели, это приемлемо»):

- Плитка - объект, на который смотрят целиком; подъём читается как отклик на
  наведение. Таблица - поверхность, по которой глаз ВЕДЁТ строку, и сдвиг всего
  полотна на 1px под курсором сбивает эту строку. Чем крупнее таблица, тем сильнее
  раздражает - на «Статусах машин по дням» дёргается пол-экрана.
- Правило автоматическое, руками ничего проставлять не нужно:
  `.page:not(#page-crm) .card:has(table):hover{transform:none;}`
  плюс `will-change:auto` на той же карточке - лишний композиторный слой под
  большой таблицей не нужен. Любая новая таблица получает это поведение сама.
- **Цветовой отклик остаётся** (рамка + фон): он не двигает содержимое, и карточка
  по-прежнему «слышит» курсор. Подсветка строки на `tr:hover` - тоже остаётся, она
  помогает вести взгляд, а не мешает.
- Порог по числу строк намеренно НЕ вводится: «таблица» - уже достаточный признак,
  а магическое число («от 10 строк») невозможно ни объяснить, ни проверить.

### Иконки (утверждено Владом 28.08 на демо меню)

- **Только инлайн-SVG, штриховые (stroke), одноцветные** - `fill="none"
  stroke="currentColor" stroke-width="1.6" stroke-linecap="round"
  stroke-linejoin="round"`, `viewBox="0 0 20 20"`. Заливка (`fill`) допустима
  только для микроэлементов внутри иконки (точка 0.9-1.7px), не для формы целиком.
- **Цвет всегда `currentColor`** - иконка наследует цвет текста своей строки и
  меняется вместе с ним (muted → text на hover). Единственное исключение: иконка
  АКТИВНОГО пункта навигации - `--green` (маркер "ты здесь", заменяет запрещённую
  боковую полоску).
- Размеры: 17px в пунктах навигации, 15px в кнопках, 19px в брендовых местах.
  Одна толщина штриха (1.6) на весь проект - иконки из разных наборов с разной
  толщиной выглядят как мусор.
- **Emoji и цветные растровые иконки запрещены ВЕЗДЕ в UI** - не только в
  заголовках карточек (расширение запрета №2 раздела 9 на всю навигацию, кнопки,
  лейблы; было утверждено на замене emoji-меню 28.08).

### Сортируемая таблица (канон, записан 29.08 после разбора реального бага)

Анатомия: заголовок = `<th class="sortable">Подпись<span>стрелка</span></th>`,
`onclick` переключает состояние `{col, dir}`, рендер перерисовывает и заголовки, и
тело из ОДНОГО состояния.

- **`dir = -1` означает ПО УБЫВАНИЮ и рисуется `▼`. `dir = +1` - по возрастанию,
  `▲`. Неактивная колонка - `↕` с прозрачностью 0.3-0.45.** Другого значения у
  знака нет ни в одной таблице проекта.
- **Компаратор пишется знаком ПЕРЕД разностью: `(av - bv) * dir`.** Форма
  `(bv - av) * dir` выглядит эквивалентной, но она уже содержит один разворот, и
  `dir = -1` даёт ВОЗРАСТАНИЕ под стрелкой «убывание». Именно так «Дебиторка»
  месяцами открывалась с самыми мелкими долгами сверху, а «Техника» - с самыми
  убыточными машинами: код работал, врала подпись. Текст - `localeCompare(av, bv)
  * dir` (тот же знак, та же логика).
- **Первый клик по числовой колонке открывает её по УБЫВАНИЮ** (`dir = -1`) -
  человек, нажимая «Баланс» или «Выручка», ищет крупное, а не копеечное. Текстовые
  колонки - А-Я (`dir = +1`). Колонки-даты («Последний заказ») - убывание, сначала
  свежие.
- **Не подгонять дефолт под перевёрнутую формулу.** Если по факту порядок верный,
  а стрелка не та - сломана формула, а не стрелка; чинить надо знак, иначе
  следующий, кто добавит колонку, унаследует ловушку (так и случилось: комментарий
  «dir=1 - по числовым колонкам это убывание» жил в коде «Клиентов» как норма).
- **Фильтр и обрезка списка несовместимы.** Таблица с сортировкой не режется по
  `slice(0, N)`: «40 крупнейших», пересортированные по дням просрочки, - это не
  топ-40 по просрочке. Либо показываем всё, либо честно пишем, по какому признаку
  отобрано.
- Проверка приёмки - только численная: отсортировать, прочитать колонку и
  убедиться, что порядок монотонный В ТУ СТОРОНУ, которую показывает стрелка.
  Глазами такой баг не ловится - таблица выглядит «отсортированной» в любом случае.

### Плитка рейса на ресурсной ленте - «Бейдж-корпус» (утверждено 29.08, уровень 5
из 5 сравнённых вариантов, разработан через параллельных агентов - домен/анатомия/
состояния)

Канон плитки для ленты «строки-ресурсы × ось времени» (см. раздел 6, подраздел
«Ресурсная лента» - там же физика перетаскивания этой же плитки).

- **Бейдж (двое людей + маршрут) - ОДНА липкая (sticky) единица, не два разных
  элемента.** Исходный уровень 5 держал бейдж прибитым к краю плитки отдельно от
  текста маршрута, который просто уезжал под скролл - Влад поправил: маршрут
  обязан скроллиться ВМЕСТЕ с бейджем, единым блоком. Реализация - см. подраздел
  «Sticky-метка» ниже, `position:sticky` на ОБЁРТКЕ бейдж+текст целиком, а не на
  каждом по отдельности.
- **Подпись человека - первые ТРИ буквы фамилии, капсом, моноширинным шрифтом**
  (`font-family: mono`, `font-size: 9px` - на шкале типографики раздела 2, НЕ
  9.5px). И менеджер (bold), и логист (приглушённый) - обязательно оба, не только
  один. Двухбуквенный код остаётся ТОЛЬКО у смежных отделов (не людей - ОЭ/ОК/ОБ),
  сокращать их фамилией нечем.
- **Отступы бейджа от рамки плитки - обязательны, не впритык.** Найденный и
  исправленный баг: внутренняя рамка бейджа визуально пересекала/касалась внешней
  границы плитки - "буквы вылазят на границу". Правило: минимум 4px отступа со
  всех сторон + собственный `padding` бейджа считается от содержимого
  (`padding:3px 8px`, БЕЗ фиксированной `height` - иначе паддинг обрезается своей
  же высотой при более длинной подписи), плюс тонкая инсет-рамка (кромка) для
  визуального отделения от плитки.
- **Высота плитки - шире стандартной строки-метки**, чтобы бейдж не казался
  теснее самой плитки (32px, не 28px - "должны быть пошире, чем сама рамка").
- **Прогресс-бар (2px, `scaleX`)** - только у РЕАЛЬНО идущего сейчас рейса,
  пересчитывается на каждый минутный тик (тот же тик, что часы в шапке - раздел 0
  п.6, "живые значения обязаны тикать").
- **Прошедшие отрезки притушены** (`opacity:.68`) - взгляд сразу отличает
  завершённое от текущего/будущего без чтения времени.
- **"Открыто в шторке" - персистентное кольцо**, переживает перерисовку списка
  (кольцо на `id`, не на ссылку DOM-элемента - при любом ре-рендере плитка новая, а
  состояние "какая открыта" должно сохраниться).
- **Служебные плитки (ремонт/ТО/без заказа/без водителя) показывают дату
  окончания рядом с подписью** ("Ремонт · до 25.08") - не только цвет-состояние;
  дата окончания = концу плитки на шкале, читается без наведения.
- **Групповой заголовок строк (например "ТРАЛЫ 12") - разделительная линия на всю
  ширину доски, не только замороженной колонки.** Найденный баг: линия обрывалась
  на границе sticky-колонки слева - "выглядит как незаконченная таблица". Внешний
  контейнер заголовка - `width:max-content;min-width:100%` (тянется на всю
  прокручиваемую ширину), внутренняя подпись - `position:sticky;left:0` (см. ниже).
  Вся полоса кликабельна для сворачивания/разворачивания группы.

### Sticky-метка внутри широкого контейнера - `display:inline-flex`, НЕ `flex`
(правило, 29.08 - поймано дважды на одной и той же ошибке)

Любая метка/бейдж, которая должна "плыть" вместе со скроллом внутри намного более
широкого родителя (замороженная колонка ленты, подпись группового заголовка,
подпись сегмента) - **обязана быть `display:inline-flex`** у себя самой. Вариант
`display:flex` растягивает элемент на всю ширину доступного пространства (блочное
поведение), из-за чего `position:sticky` формально работает, но визуально элемент
уже занимает всю ширину контейнера и "плыть" ему некуда - эффект неотличим от
сломанного. `inline-flex` даёт элементу размер по содержимому (как у `inline`), но
сохраняет `flex`-раскладку внутренних частей (иконка+текст) - именно это сочетание
нужно sticky-меткам. Проверка при добавлении нового sticky-элемента: развернуть
браузер шире контейнера и убедиться, что метка ДЕЙСТВИТЕЛЬНО остаётся на месте при
горизонтальном скролле, а не просто технически имеет свойство `sticky` в CSS.

## 5. Моушн

### Токены кривых (объявлять один раз)

```css
--ease-out-strong:cubic-bezier(0.16,1,0.3,1);   /* входы, отклики, одометры */
--ease-out-soft:cubic-bezier(0.25,1,0.5,1);     /* hover, прорисовка линий */
--ease-in-out:cubic-bezier(0.65,0,0.35,1);      /* затухания, кроссфейды */
--ease-in-exit:cubic-bezier(0.55,0,1,0.45);     /* только уходящие, коротко */
/* + для канбана: */
--ease-flip:cubic-bezier(.22,.9,.28,1);         /* FLIP соседей, 300ms */
--ease-overshoot:cubic-bezier(.34,1.45,.5,1);   /* укладка карточки, drawer, 380ms */
--ease-drawer:cubic-bezier(.32,.72,0,1);        /* тост, undo-возврат, 320-340ms */
```

### Бюджет длительностей (жёсткий)

| Класс | Лимит |
|---|---|
| Интерактивный отклик (hover, press, тултип) | <=150ms |
| Декор (тикер, чип, блип, угасание hover) | <=400ms |
| Первая загрузка дня (вся сцена) | <=1200ms, ЕДИНСТВЕННОЕ исключение №1 |
| Победная хореография (закрытие сделки) | <=2200ms, ЕДИНСТВЕННОЕ исключение №2 |

### Правила

- Анимируются ТОЛЬКО `transform`, `opacity`, `stroke-dashoffset`. Запрещено:
  `transition: all`, анимация width/height/left/top/box-shadow (тени и свечения -
  через opacity заранее отрисованного псевдоэлемента).
- **Первая загрузка** (референс - панель): каркас виден с первого кадра; карточки
  входят stagger `80 + i*55`ms (450ms strong); одометр цифр ОТ 92% значения (не от
  нуля - "секунда лжи"), 550ms; заполнение полос - `translateX` внутри
  `overflow:hidden` (радиусы не искажаются); спарклайн - `pathLength:1` +
  dashoffset 1→0 600ms. Вход играет РАЗ В ДЕНЬ (`localStorage`-гейт по дате);
  повторный визит - фейд 120ms без спектакля.
- **Живое обновление**: тикер (старое значение 160ms exit вверх/вниз ПО НАПРАВЛЕНИЮ
  изменения, новое 220ms strong с задержкой 60ms) + дельта-чип 200ms + блип-заливка
  карточки макс 8% непрозрачности, 400ms. Строить на transitions, не keyframes
  (ретаргетятся). Неизменившиеся карточки - ноль движения.
- **Drag** (референс - канбан): lerp 0.28/кадр к курсору, наклон до ±7° от
  горизонтального лага, соседи расступаются FLIP 300ms, укладка overshoot 380ms.
- **Победа** (t=0..2200): укладка → подсветка колонки (вход 120ms, гаснет 600ms) →
  салют из верхней кромки карточки t=180 → фанфара t=200 → сумма отделяется t=260 и
  летит дугой в KPI 500ms → KPI-pop + одометр 900ms + 10 денежных тиков по 75ms →
  тост с "Отменить" t=600. Тяжёлая хореография принадлежит ТОЛЬКО победе.
- **Undo**: спокойно, 340ms drawer-кривая, БЕЗ overshoot ("отмена не праздник"),
  KPI скручивается за 300ms.
- **Attention-состояние**: постоянный пульс ЗАПРЕЩЁН (привыкание + налог на
  периферию). Статичная рамка/фон + однократный halo 300ms строго по событию
  ухудшения данных.
- **`prefers-reduced-motion: reduce`** - обязательная ветка на каждом экране:
  убрать перемещения/3D/параллакс/stagger, оставить смысловые фейды; одометры
  выключены (цифры сразу финальные).
- В скрытой вкладке (`document.hidden`) rAF не тикает - каждая rAF-анимация обязана
  иметь ветку "если hidden - выставить финальное значение сразу".

## 6. Drag & Drop - единый стандарт

**Одна физика перетаскивания для ВСЕГО дашборда** - карточка сделки в канбане,
плитка данных на панели, что угодно следующее. НЕ изобретать заново под каждый
компонент - именно так родилась находка 28.08: плитки KPI собрали слабее канбана
(прямое 1:1-следование без веса, без наклона, без overshoot), потому что стандарта
ещё не было записан. Канон - карточка сделки "уровень 5"
(`examples/design-reference-kanban.html`, класс `mx-card`). Копировать числа
буквально, не "по мотивам".

### Фазы одного перетаскивания

**1. Нажатие (t=0)** - визуальный отклик МГНОВЕННО, до того, как решится "это клик
или тащат": `scale(.97)` + `transform 100ms var(--ease-out-soft)`. Без этого первые
~500мс ощущаются как "ничего не произошло" (пойманная и исправленная путаница на
демо плиток 28.08 - долгое нажатие 550мс без немедленного отклика читалось как
нерабочая кнопка).

**2. Подъём** (стало ясно, что это перетаскивание - явный drag-старт, либо для
долгого нажатия - момент входа в режим, см. ниже):
- Элемент выходит из потока: `position:fixed`, координаты `left/top` = текущий
  `getBoundingClientRect()`, реиндексируется в `document.body` (или ближайший
  контейнер без `perspective`/`transform`-предка, если нужен 3D), `z-index` поверх
  всего (999+).
- Плейсхолдер того же размера (`width`/`height` с точностью до px) остаётся на
  исходном месте, чтобы соседи не прыгали.
- `opacity:.82` - прозрачность КАК СОСТОЯНИЕ действия, не материал в покое (переход
  `140ms cubic-bezier(.25,1,.5,1)`). Видно, куда бросаешь; в покое элемент снова
  полностью непрозрачен.
- Тень двухслойная: `box-shadow:0 2px 6px rgba(0,0,0,.4),0 16px 32px rgba(0,0,0,.5)`.
- `scale(1.03)`.
- Курсор `grabbing`.

**3. Движение** (каждый кадр, пока держат):
- Позиция элемента - **lerp к курсору, коэффициент 0.28 за кадр**:
  `cur.x += (target.x - cur.x) * 0.28` (аналогично `cur.y`). НЕ прямое 1:1-
  следование - лёгкое отставание и есть ощущение "веса" объекта, а не приклеенности
  к курсору.
- **Наклон от лага движения**: `tilt = clamp(-7, 7, (target.x - cur.x) * 0.10)`
  градусов - чем резче дёрнули, тем сильнее наклон, потолок ±7°.
- Итоговый `transform` элемента: `translate(cur.x, cur.y) rotate(tilt deg) scale(1.03)`.
- **Соседи (FLIP)**: при пересечении новой точки вставки - `300ms
  cubic-bezier(.22,.9,.28,1)` (`--ease-flip`). Реализация - снять позиции ДО
  мутации DOM, снять ПОСЛЕ, разницу отыграть transform'ом от снятого значения к 0.
- **Зона-приёмник** (колонка/группа под курсором, если зоны различимы - см. ниже
  про плоские сетки без зон): `border-color` колонки +45% в сторону акцентного
  тона, фон-подложка +6% того же тона, `inset box-shadow 0 0 0 1px` на 25% -
  все три перехода `150ms ease-out`.

**4. Отпускание / укладка**:
- Плейсхолдер заменяется реальным элементом (`insertBefore` + `remove`).
- Приём "первый-последний" (FLIP на самом перетаскиваемом элементе): снять
  `getBoundingClientRect()` ДО возврата в нормальный поток (координаты ещё
  `fixed`), снять СНОВА после (уже в потоке) - разница даёт стартовый `transform`
  без transition, на следующем кадре включить `transition: transform 380ms
  cubic-bezier(.34,1.45,.5,1)` и обнулить transform. Это единственное место во всём
  цикле, где кривая - **overshoot** (перепрыгивает цель и возвращается) - имитирует
  инерцию реального предмета, который лёг на стол.
- `opacity` возвращается к 1 за `140ms cubic-bezier(.25,1,.5,1)` синхронно с укладкой.
- Тень/scale/наклон обнуляются вместе с settle-transition (одна transition-запись,
  не рассинхронизировать).

**5. Undo / отмена** (если действие обратимо) - зеркальное движение, но **БЕЗ
overshoot**: `340ms cubic-bezier(.32,.72,0,1)` (`--ease-drawer`). "Отмена не
праздник" (см. раздел 5, Моушн) - единственная сознательная асимметрия между
"положить" и "вернуть".

### Плоские сетки без колонок (свободно переставляемые плитки)

Фазы 1-5 выше - без изменений. Разница только в шаге 3 ("зона-приёмник"): у плоской
сетки (KPI-плитки на панели) нет отдельных колонок - обратная связь о точке вставки
даёт САМ FLIP-реflow соседей, отдельной подсветки зоны не нужно. Точка вставки
определяется по ближайшей по центру плитке (`Math.hypot` до центра каждой,
не по `Y`-полосам, как в канбане - сетка двумерная).

### Долгое нажатие -> режим перестановки (свободные плитки данных, НЕ карточки сделки)

Отдельный, более редкий сценарий входа в перетаскивание - только там, где элемент
не имеет другого закреплённого смысла у жеста "зажать". **Область действия:
KPI/данные (главная панель, статистика) - НЕ карточки сделки в канбане**, у которых
"зажать и тащить" уже занято переносом по воронке продаж; накладывать второй смысл
на тот же жест на тех же объектах - конфликт, не находка (решено с Владом 28.08).

- Удержание **550ms** без сдвига курсора больше 6px (иначе - обычный клик/скролл,
  отмена).
- Отклик на нажатие - фаза 1 выше (`scale(.97)`) - действует С ПЕРВОЙ миллисекунды
  удержания, не дожидаясь итога 550ms.
- По истечении 550ms, если палец/курсор всё ещё не отпущен: **весь контейнер**
  переходит в режим - остальные плитки (кроме той, что уже держат) получают
  дрожание `rotate(-1deg) -> rotate(1deg) -> rotate(-1deg)`, у каждой свой
  фазовый сдвиг (`animation-delay`/`animation-duration` по индексу плитки, +-15%
  от базовых ~0.22-0.28s) - чтобы не дрожали синхронно. Плитка, которую держат,
  дрожание НЕ получает - она уже поднята по фазе 2.
- Grip-индикатор (маленькая иконка "точки-хват", 6 точек 2x3) появляется на ВСЕХ
  плитках при входе в режим, статично, БЕЗ анимации - единственная подсказка
  режима, которая работает и при `prefers-reduced-motion` (дрожание в этом случае
  выключено, grip остаётся).
- Кнопка "Готово" (плашка, вход/выход `opacity+translateY 200ms
  var(--ease-out-strong)`), клик по пустому месту контейнера, или `Escape` -
  выход из режима.
- Первый визит - явная подсказка на ОДНОЙ конкретной плитке (не на всех): бейдж
  "Держи здесь ~0,5 сек" со стрелкой + мягкий пульсирующий контур
  (`box-shadow` 2px, 3 цикла по 1.1s). Гасится сама через 5с ИЛИ мгновенно при
  первом реальном входе в режим (что раньше). Без неё пользователь не понимает,
  что жест вообще существует - ни один UI не должен полагаться только на текст
  инструкции над блоком.
- Хранение порядка - НЕ часть этого стандарта (инфраструктурный вопрос, не
  интерфейсный): демо использует `localStorage`, рабочая версия потребует
  серверного хранения на пользователя, чтобы раскладка не расходилась между
  устройствами. Явно писать эту оговорку на любом черновике с этим паттерном, пока
  серверное решение не выбрано.

### Ресурсная лента (протяжка по времени, растяжка, магнит) - канон плитки-рейса

Отдельный режим перетаскивания - не переупорядочивание (раздел 6 выше), а сдвиг/
растяжка отрезка по оси времени: строки = ресурсы (машины, люди), ось X = часы,
работа = отрезок-плитка. Канон - вкладка «Планировка»
(`plans/2026-08-29-logistics-planning-board.md`, перенесена в `files/index.html`
29.08). Фазы 1-2-4-5 раздела 6 - без изменений (нажатие/подъём/укладка/undo те же
числа); ниже - то, что у ЭТОГО режима устроено иначе.

- **И перенос, И растяжка обязаны проверять пересечение перед коммитом.** Найденный
  и исправленный баг (аудит 29.08): проверка "не наложился ли на соседний отрезок"
  стояла только у переноса - растяжкой можно было молча создать перекрытие. Любой
  новый способ менять `s`/`l` отрезка (не только drag) обязан идти через ту же
  проверку с откатом (`toast` + возврат старых `s`/`l`) и `S.reject()`.
- **Магнит - к соседям И к границам часа/смены, в ОБЕ стороны.** Цели для примагни-
  чивания движения - не только "моя точка касается чужого начала", но и "мой КОНЕЦ
  касается чужого начала": `moveTargets = rawTargets.concat(rawTargets.map(t => t -
  draggedLength))`. Забытое зеркалирование - конкретный найденный баг (магнит не
  работал для соседа СПРАВА).
- **Магнит-эффекты уровня 3 (Влад, 29.08 на сравнении трёх уровней: «просто супер...
  внедряем срочно»)** - при примагничивании одновременно:
  1. kiss-flash на ОБОИХ соприкасающихся краях (короткая вспышка обводки);
  2. всплеск из 4 частиц-искр в точке касания;
  3. «шов» - `stroke-dashoffset`-анимация SVG-пунктира вдоль стыка (единственное
     разрешённое анимируемое CSS-свойство сверх transform/opacity, см. раздел 5);
  4. squash/stretch плитки от скорости драга (`scaleX`/`scaleY`, коротко, тем же
     transform, что несёт наклон/lerp - не отдельная transition);
  5. звук - трёхнотное арпеджио (регистр "праздничный", см. раздел 8), не одна нота
     - усиление по фидбэку "притягивание должно ощущаться, а не щёлкать".
- **`will-change:transform` - JIT, не постоянный CSS.** Ставить свойство на элемент
  ТОЛЬКО на время реального драга (в момент подъёма, снимать при укладке), не
  прописывать в базовом классе плитки - постоянный `will-change` создаёт лишний
  композиторный слой и ломает `position:sticky` у метки/бейджа внутри плитки в
  состоянии покоя (см. подраздел "Sticky-метка" раздела 4).
- **`prefers-reduced-motion` для драга по времени - позиция обязана обновляться
  напрямую в обработчике `pointermove`, не только внутри rAF-цикла.** Тик rAF не
  выполняется под reduced-motion по определению - если единственное место, где
  плитка получает новую координату, это `tick()` внутри `requestAnimationFrame`,
  перетаскивание визуально замирает целиком (найденный баг, не единственная ветка
  reduced-motion в разделе 5 - здесь нужна ОТДЕЛЬНАЯ прямая запись 1:1 в момент
  события, помимо общей ветки "выключить transform/3D/stagger").
- **Удаление - корзина, как на смартфоне.** При подъёме плитки внизу по центру
  экрана всплывает зона-корзина; наведение на неё - "взвод" (подсветка/увеличение),
  отпускание над ней - плитка втягивается в иконку и исчезает, коммит удаления идёт
  тем же путём undo-тостом, что и любое разрушающее действие (раздел 4, компонент
  «Тост»). Тот же приём для будущих перетаскиваемых элементов с удалением - не
  контекстное меню, не отдельная кнопка "×" на каждой плитке.
- **Создание записи** - протяжка по пустому месту трека (та же физика подъёма/
  магнита/тика, что у растяжки существующего отрезка) ИЛИ двойной клик как быстрый
  путь без протяжки. Двойной клик создаёт запись стандартной длины смены (не
  минимальной единицы шкалы) - короткая заготовка "для порядка" создаёт больше
  трения (растягивать вручную), чем польза от точности умолчания.
- **Часовой тик при растяжке** - отдельный короткий звук на каждый пройденный час
  (не при обычном движении, только при изменении длины) - подтверждает пользователю
  "сколько времени сейчас захвачено", без необходимости смотреть на HUD-подсказку
  постоянно.

## 7. Объём и ГПУ

Разрешено ПО УМОЛЧАНИЮ (чистый CSS/compositor, проверено 28.08, референс - канбан):
- **3D-глубина**: `perspective:1400px` на панели, `transform-style:preserve-3d`,
  наклон доски к курсору `rotateX/Y` до ±1.6°, lerp 0.07/кадр; карточка на hover
  `translateZ(22px)`. Цикл обязан самоостанавливаться в покое (не крутить rAF).
- **Прозрачность и тени во время драга** - см. раздел 6 (Drag & Drop), фаза 2 -
  канон один, здесь не повторяется.
- **Курсорный свет - ОБЯЗАТЕЛЕН НА КАЖДОЙ СТРАНИЦЕ (Влад, 29.08: «должен быть
  строгий стандарт, чтобы уже по умолчанию все страницы были с этими эффектами»).**
  Не «разрешено», а требование: любая новая или переделываемая страница дашборда и
  CRM выходит со светом под плитками. Страница без него не принимается (пункт в
  чек-листе раздела 10).
  **Свет живёт ВНУТРИ СЕТКИ ПЛИТОК, а не на всей странице** (Влад, 29.08: «наверху
  устраивает, а внизу его отчётливо видно - хочу, чтобы везде было абсолютно
  одинаково»). Причина: карточки непрозрачны, поэтому свет виден ровно там, где
  открыт фон. В сетке это узкие зазоры - мягкий ореол, который и нужен. А на
  странице целиком ниже начинаются таблицы и пустой хвост, где то же самое пятно
  открывается полностью и читается как отдельный фонарь. Носители слоя - контейнеры
  плиток (`.kpi-grid`, `.mp-tier`, `.mp-stats`, `.p2-tier3-grid`, `.grid-2`); мышь
  вне них - свет гаснет, под таблицами его нет вовсе.
  Канон: `radial-gradient(600px circle at var(--lx) var(--ly),
  rgba(55,138,221,.07), transparent 70%)`, слой `position:absolute; inset:0;
  z-index:0` внутри сетки (`position:relative` на сетке, плитки на `z-index:1`),
  координаты - проценты от СЕТКИ, lerp 0.12/кадр, гаснет за .25s, rAF
  самоостанавливается в покое и не тикает при `document.hidden`.
  **Реализация ОДНА на весь проект** - `initCursorLight_(pageId, lightClass)`, слои
  создаются им самим при первом заходе мыши в сетку. Своей копии движка не писать:
  две реализации одного эффекта разошлись в числах ровно так, как Влад и заметил.
  Обязательный guard: при нулевой ширине/высоте сетки (скрытая вкладка) выход из
  расчёта до деления - иначе NaN молча попадает в CSS (ловилось 28.08).
  `prefers-reduced-motion` - свет не запускается вовсе.
  Схема `z-index:-1` для слоя НЕ используется: она пропадает целиком, стоит любому
  предку создать stacking-контекст.

Разрешено ПО СОБЫТИЮ (следующая итерация, отдельное решение): WebGL-эффекты,
живущие только в окне действия (шлейф за карточкой при драге, всплеск в победе).
Требование: один персистентный контекст (не пересоздавать), fps-счётчик при
прототипировании.

ЗАПРЕЩЕНО: постоянный полноэкранный шейдер-фон в рабочем экране; frosted glass /
`backdrop-filter` как материал карточки в покое (отвергнуто Владом дважды).
Постоянный ambient-шейдер возможен только точечно (полоса за хедером, виньетка),
только по отдельному "да" Влада, с яркостью ±3-4% от `--bg`.

## 8. Звук

Примитив (Web Audio, без файлов) - копировать как есть:

```js
function blip(freqFrom, freqTo, dur, vol, type, delay){ /* осциллятор с
  exponentialRamp затуханием; полный код - в обоих референс-файлах */ }
```

Два регистра - выбирать по типу экрана, НЕ смешивать:

| | "Праздничный" `sounds5` (CRM-действия) | "Деликатный" `soundsD` (BI/ежедневная панель) |
|---|---|---|
| Референс | design-reference-kanban.html | design-reference-panel.html |
| События | lift / reorder / drop / success / moneyTick / undo / open / close | boot / tickUp / tickDown / refresh / attention / toggle |
| Характер | мажорное арпеджио C5-E5-G5-C6 на успех, пентатоника на деньги | чистая квинта БЕЗ терции (не навязывает оценку), attention = "покашливание" triangle, не сирена |
| Громкости | вспомогательные 0.02-0.06, основные до 0.12 | максимум 0.07 (attention), остальное 0.015-0.045 |
| Частоты | 130-2600 Гц | 200-660 Гц (тёплая середина) |

Правила: направление тона = семантика (рост - вверх, падение - вниз, укладка -
нисходящее глиссандо); звук ТОЛЬКО по событию данных или действию пользователя -
никогда по hover в BI; на каждой странице со звуком - видимый выключатель
("Звук: вкл/выкл"), состояние учитывается внутри blip.

**ЛЮБОЙ ПЕРЕХОД ЗВУЧИТ ОДИНАКОВО (Влад, 29.08: «переключение между вкладками
должно везде сопровождаться звуком, такой же, как переход по меню... нажатие на
плитки должно сопровождаться звуками, это должно быть в ГОСТе»).** Для человека
пункт меню, вкладка таб-бара, кликабельная плитка-переход, чип-фильтр и
строка-ссылка - одно действие «я иду в другое место», поэтому звук у них ОДИН:
`navClick` (sine 392→440 Гц, 0.05с, vol 0.022).
Реализация - ОДНО делегирование на `document` со списком-селектором
(`.sidebar-nav-item, .tab-btn, .month-tab, .p2-drill, .mp-stat, .mp-ghostbtn,
.p2-board, [data-nav-sound]`), а не обработчик на каждом новом элементе. Новый
кликабельный элемент либо попадает под существующий класс, либо получает атрибут
`data-nav-sound` - и звучит сам, без правки звукового кода. Перечислять места по
одному ЗАПРЕЩЕНО: именно так звук и «терялся» на новых страницах.

**ДОСТИЖЕНИЕ СТУПЕНИ ОКЛАДА - фанфара (Влад, 29.08).** Пороги 30 000 / 50 000 /
100 000 / 150 000 ₽. Событие редкое (максимум 4 раза в месяц на человека), поэтому
ему положен праздничный регистр (`growth`, то же арпеджио, что на рост денег), а
не деликатный тик. Обязательная дедупликация по паре «сотрудник + ступень +
месяц» в `localStorage`: играет ОДИН раз, а не на каждом рендере страницы. Первый
заход только запоминает текущий уровень и молчит (иначе фанфара сыграла бы всем
при первом же открытии). Архивный период (прошлый месяц) - не празднуем: эти
достижения уже случились. `document.hidden` - не играем.

**Автоматика с периодом короче ~1 минуты (карусель, тикающие часы, авто-ротация) -
БЕЗ звука на каждый цикл** (Влад, 28.08, про табло-карусель метрик: "часто будет
шуршать, отвлекать"). Даже самый тихий тик, повторяясь весь рабочий день без
участия пользователя, превращается в фоновый шум - в отличие от звука на
событие данных (редко, что-то реально изменилось) или на клик (пользователь сам
инициировал). Правило при добавлении звука к новому элементу: спросить "кто
дёргает эту анимацию - пользователь/редкое событие данных, или таймер"; если
таймер и период короткий - звук не добавлять вообще, даже "деликатный".

### Звуковые события ДАННЫХ на панели (Влад, 28.08)

Панель запоминает ключевые значения и на каждом обновлении данных ВНУТРИ сессии
сравнивает (первый рендер молчит - базы нет):
- **Деньги выросли** (выручка ИЛИ поступления, порог >=10 000 ₽): фанфара выигрыша
  из канбана (то же до-мажорное арпеджио C5-E5-G5-C6, громкость x0.7 - BI-контекст
  тише игрового) - ОДНА на обновление, не по разу на метрику; выросшие числа
  накручиваются одометром от старого к новому (~900ms) под мажорные
  пентатонические тики (~80ms).
- **Дебиторка выросла** (порог тот же): attention-"покашливание" (деликатный
  регистр) + одометр под ГЛУХИЕ нисходящие тики (triangle, полутоновый спад) -
  рост долга не празднуется, тон обязан отличаться от денежного.
- Оба события сразу: фанфара первой, attention с задержкой ~1.2с - не каша.
- `document.hidden` - пропустить и звук, и одометры (значения уже отрисованы).
- Всё под общим выключателем звука страницы.

### Победная сцена банковского поступления (Влад, 28.08 - «как сделку двигаешь в успешные»)

Живое банковское поступление (СМС-лента, план 2026-08-28-bank-operations-live-feed)
празднуется ПОЛНОЙ победной сценой канбана уровня 5, в полной громкости (решение
Влада: поступление денег = та же победа, что закрытая сделка; это осознанное
исключение из BI-скидки x0.7). Перенос из `mxWin` 1:1, раскадровка t=0..2200:
- t=0: подсветка карточки «Сегодня» (аналог `mx-win-glow`: рамка green 45%, фон
  green 7%), гаснет с t=300;
- t=180: салют `celebrate5` (кольца+лепестки+искры, скопирован буквально) из
  верхней кромки карточки, полноэкранный fixed-canvas поверх всего;
- t=200: фанфара `sounds5.success` БЕЗ скидки громкости (uiSounds.win);
- t=300: тост; t=380: сумма отделяется от тоста и летит дугой в значение
  (`mxFlySum`: 500ms, scale 1.15→0.7, растворение на последних 15%);
- удар: KPI-pop 280ms overshoot + flash значения amber (снять через 1300) +
  одометр 900ms под кассовые тики канбанной громкости (uiSounds.winTick).
Цель сцены - видимая карточка: KPI «Сегодня» на странице Поступления, иначе
карточка «Поступления» на Панели. Списание сцену НЕ получает - attention как
раньше (если в одном обновлении и поступление, и списание - attention через
~1.4с после фанфары). Другая страница открыта / reduced-motion - фанфара + тост
без хореографии; document.hidden - вообще тихо (проверка в поллинге).

**Градация по сумме (Влад, 28.08 - после первого прогона: «нужно интереснее от
100 тыс, ещё круче от 500 тыс, совершенно крутейший от 1 млн»).** Уровень
считается по МАКСИМАЛЬНОЙ операции пачки (`bankWinLevel_`), не по сумме пачки -
одна платёжка 1,2 млн даёт «Миллионник», а десять по 15 тыс не звучат как

- **<100 тыс** - `uiSounds.win`, без изменений, 1 залп салюта;
- **от 100 тыс «Крупный клиент»** - `uiSounds.win2`: двойной трубный зов

  колокольным каскадом; 1 залп;
- **от 500 тыс «Большой день»** - `uiSounds.win3`: двойная фанфара, второй

- **от 1 млн «Миллионник»** - `uiSounds.win4`: удар литавр, три восходящие

9. Вечные циклы: пульсы, шиммеры, бегущие градиенты, мигающие "live"-точки.
   **ИМЕНОВАННОЕ ИСКЛЮЧЕНИЕ - «свечение ожидания» (утверждено Владом 30.08 на
   превью карточки сцепки).** Плашка типа техники на доске «Планировка» мягко
   светится (`box-shadow` в СВОЁМ цвете, 2,4 с на цикл), пока машина ждёт заказ.
   Почему это не нарушает правило по сути: свечение привязано к СОСТОЯНИЮ, а не
   к декору - оно живёт ровно столько, сколько длится незакрытая работа, и гаснет
   в ту же секунду, когда рейс выдан; когда парк разобран, на экране не светится
   ничего. Возвращается само, когда протяжка кончилась и время ушло за её конец.
   Жёсткие условия исключения:
   - светится ТОЛЬКО отсутствие статуса («ждёт заказ»). Ремонт и «нет водителя» -
     это статусы, они НЕ светятся: если светится всё, свечение не значит ничего;
   - **цвет и фон плашки при этом неподвижны** - анимируется одна лишь тень.
     Цвета плашек заданы по типу техники (`f-bort`/`f-koryto`/`f-rapid`/…) и не
     меняются ни от какого состояния;
   - `prefers-reduced-motion` - вместо анимации статичное свечение.
   Расширять исключение на другие экраны - только с новым «да» Влада.

   **РАСШИРЕНО 30.08 на присутствие сотрудников** (Влад: "мигание сотрудников...
   как у нас плитки мигают" - новое явное "да" на тот же приём для новой цели).
   Плитки «кто сейчас на странице» (доска «Планировка», админ-режим) мигают
   ТОЙ ЖЕ анимацией (`lpTagGlow`), но привязка к состоянию другая: не «ждёт
   заказ», а «реально взаимодействует с доской прямо сейчас» (двигал/тянул/
   создавал/сохранял в последние 12 с). То же обоснование не-декоративности:
   мигание гаснет само, как только человек перестал действовать (или ушёл со
   страницы) - оно не бежит вхолостую. Те же условия: цвет плитки неподвижен
   (мигает только тень), `prefers-reduced-motion` - статичное свечение.
   Третье, промежуточное состояние («на странице, но бездействует») - НЕ
   светится и НЕ мигает, просто залито своим цветом неподвижно - это НЕ новое
   исключение из правила №9 (постоянного цикла тут нет вообще), упомянуто для
   полноты картины трёх состояний присутствия.

   **РАСШИРЕНО 30.08 третий раз, честно БЕЗ привязки к состоянию** (Влад:
   "пусть сентябрь, слово, синим имеет свечение, как неоновая вывеска:
   бегание, затухание" - явный прямой заказ конкретного эффекта, не
   реинтерпретация существующего). Подпись месяца на границе перехода ленты
   («СЕНТЯБРЬ» над 1-м числом в «Планировке») мигает и переливается тенью
   бесконечно (`lpNeonFlicker`) - это ЧИСТАЯ декорация, в отличие от двух
   случаев выше не привязана ни к какому состоянию и не гаснет сама. Почему
   разрешено вопреки букве правила: ячейка ровно ОДНА на весь видимый диапазон
   (не тиражируется по экрану, значит не даёт "усталость от периферии", ради
   которой правило №9 и существует), и сам факт смены месяца - редкое событие,
   которое естественно хочется заметить. `prefers-reduced-motion` - статичное
   свечение без анимации, как и у первых двух случаев.
