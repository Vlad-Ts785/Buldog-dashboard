# Кастомизация меню сайдбара: долгое нажатие, перестановка, скрытие, меню сотрудника

**Статус:** сделано и задеплоено 05.09.2026 (ночью, по просьбе Влада "сделай всё сам").
**Запрос (Влад, 05.09, дословно):** "Мне нужно настроить кастомизацию меню. Только для
админа. Зажал меню перешло в режим кастома передвинуть как канбанчик скрыть и тому
подобное. Важно что при входе в просмотрщик какого-либо сотрудника я могу также настраивать
ему как будет меню у него. У сотрудника кастомизации быть не должно."

## Решения

- **Жест и физика - ГОСТ, раздел 6** ("Долгое нажатие -> режим перестановки" + "Drag & Drop
  - единый стандарт"), числа буквально, не "по мотивам": удержание 550 мс без сдвига > 6px,
  отклик `scale(.97)` с первой миллисекунды, дрожание ±1° с фазовым сдвигом по индексу,
  grip 2x3 на всех пунктах, плашка "Готово" 200 ms, drag `opacity .82` + двухслойная тень +
  `scale(1.03)` + lerp 0.28 + наклон ±7° от лага, FLIP соседей 300 ms, укладка overshoot
  380 ms, Esc/отмена - без overshoot (340 ms), подсказка первого визита на одном пункте.
  Кривые - литералами: переменные `--ease-*` объявлены не на `:root`, а внутри страниц
  (CRM/Планировка), сайдбар их не видит.
- **Хранение - на сервере** (`menu_configs`), не localStorage (ГОСТ прямо требует серверного
  хранения, иначе раскладка расходится между устройствами и админ не мог бы задать меню
  сотруднику). localStorage (`yard.menu.cfg.<key>`) - только кэш для мгновенной отрисовки.
- **Ключ конфига:** `admin` для админа, `role:фамилия` для сотрудника (та же фамилия-как-ключ,
  что везде в дашборде: `surOf_`, `COMMERCIAL_HEAD_SUR_FRONT_`). Для "Смотреть как" ключ
  строится из `viewAsEntry`, для реального входа сотрудника - СЕРВЕР сам выводит его из
  `access_users` по email сессии (клиентский `key` игнорируется у не-админа) - сотрудник не
  может прочитать чужой конфиг. Проверено: `manager:цегельников` совпадает в обоих путях.
- **Кастом поверх ролевого фильтра.** `applyRoleUI()` выставляет `display` по роли, затем
  `applyMenuConfig_()` только переставляет и дополнительно прячет. Показать пункт, скрытый
  ролью, конфиг не может. Гвард: спрятать все пункты нельзя.
- **Порядок = токены всех детей `nav`** - пункты (`data-page`) и разделители (`#park`,
  `#sales`), поэтому пункт можно унести в другой раздел. Новые пункты, которых нет в
  сохранённом порядке, встают в конец.
- **Один алгоритм "Готово"/Esc/клик по пустому месту** - выход с сохранением; "Сброс" -
  удаление конфига на сервере.
- **Сотрудник:** `pointerdown`-обработчик отбрасывает всё, кроме `D.role==='admin'` -
  никакого режима; его конфиг применяется на чтение.

## Файлы

- `files/index.html`: CSS (блок "Кастомизация меню"), разметка (`data-section` у
  разделителей, `#menu-done-bar` в конце `nav`), JS-модуль после `initSidebarCollapse_()`
  (`menu*_`-функции), хуки `applyMenuConfig_()` в обоих выходах `applyRoleUI()`.
- VPS `api/server.js`: `GET/POST /api/menu_config`, таблица `menu_configs`.

## Проверено

- API: 9 сценариев curl (admin пишет/читает любой ключ, сотрудник читает только свой даже
  при подстановке `key=admin`, 403 на запись сотрудником, 400 на мусорный ключ/конфиг,
  reset).
- Браузер (локальная копия страницы со stub `D.role='admin'`): вход через
  `menuEnterCustomize_()` и через эмуляцию долгого нажатия (650 мс -> режим + поднятый
  пункт), скрытие "глазом", перетаскивание "Динамики" над "Технику" (FLIP, без остаточных
  карточек/плейсхолдеров), "Готово" (скрытый пункт `display:none`, порядок сохранён в кэш),
  Esc. Ловушка автоматизации: координаты кликов в Browser pane - в кадре скриншота
  (800x450), не в px вьюпорта.

## Не сделано / открытое

- Автопрокрутка nav при перетаскивании к краю (список помещается на экран, не понадобилось).
- Разделители не перетаскиваются сами по себе (двигаются пункты).
- На тач-устройствах первый drag сразу из долгого нажатия может конфликтовать со скроллом
  (touch-action меняется на лету) - десктоп основной сценарий Влада.
