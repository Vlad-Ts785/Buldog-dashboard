# План: страница логиста - единый каркас с менеджером + ИИ-задачи

**Дата:** 2026-08-13
**Автор:** Клод
**Статус:** реализовано

## Цель

Влад: "Логисту также нужно структурировать страницу как мы сделали менеджеру... понятно, что
функции у сотрудников разные и информация разная, но структурно каркас должен быть
единообразным." Уточнено (AskUserQuestion):
1. ИИ-задачи (GPT-5 через kie.ai) - сразу, не откладывать.
2. "Полоска плана" у логиста, раз плана продаж в данных нет - прогресс до премии >1М маржи
   найма (порог уже есть в `calcLogist`).

Целевая структура страницы логиста (`renderMyPageLogist`), зеркально менеджеру:
1. 🤖 Задачи на сегодня (ИИ) - новый промпт под данные логиста.
2. Полоска "Маржа найма к премии >1М" - тонкая, тот же стиль/цвета, что у менеджера, с
   рекомендацией "сколько нужно добирать в день".
3. 💰 Расчёт зарплаты - та же двухуровневая вёрстка (badge-проценты), "Итого на сегодня" +
   "Итого по прогнозу" (масштабирование через paceRatio, тот же приём, что у менеджера).
4. Один блок с вкладками вместо трёх отдельных таблиц: Маржа по поставщикам / Воронка
   документов / Сделки.

## Архитектурное решение - не дублировать общее ядро

`renderMyPageManager` уже содержит нужные строительные блоки, но locally-scoped (недоступны
`renderMyPageLogist`): `planProgressBar`, `planZoneColor_`, `salRow`/`salTotalRow`/`pctBadge_`/
`mutedBadge_`/`okladNextTierNote_`-паттерн, `scaleRowForForecast_`, блок ИИ-задач (HTML+кэш).
Выносим их на module scope, чтобы оба рендера переиспользовали ОДНИ И ТЕ ЖЕ функции - не
копипаста с риском разъехаться (тот же урок, что уже был с `problemOrderRowHtml_`).

Бэкенд: `generateManagerAiTasksCached_`/`findAiTasksCacheRow_`/`deleteAiTasksCacheRow_`/
`saveAiTasksCache_`/`callKieGpt5_`/`parseAiTasksResponse_` - НЕ дублируем под логиста, выносим
в общий `generateAiTasksCached_(ss, personName, role, contextFn, promptFn, force)`, у которого
role/контекст/промпт - параметры, кэш-лист/API-вызов/парсинг - общие.

## Реализация

### Фаза 1 - вынос общих кусков на module scope (без изменения поведения)
- [ ] `planProgressBar`/`planZoneColor_` - из `renderMyPageManager` в module scope.
- [ ] `salRow`/`salTotalRow`/`pctBadge_`/`mutedBadge_`/`hex2rgba_`/`scaleRowForForecast_` -
      туда же.
- [ ] Блок рендера "Задачи на сегодня (ИИ)" (HTML + retry/regen кнопка) - в отдельную функцию
      `renderAiTasksBlock_(personName)`, вызывается и менеджером, и логистом.
- [ ] Регресс-проверка: страница менеджера рендерится идентично (синтетика, тот же вывод).

### Фаза 2 - бэкенд: общий оркестратор + контекст/промпт логиста
- [ ] `generateAiTasksCached_(ss, personName, role, contextFn, promptFn, force)` - общий кэш/
      генерация, `generateManagerAiTasksCached_` становится тонкой обёрткой.
- [ ] `aiTasksCommonRules_()`/`aiTasksOutputFormatRules_()` - вынесенные из промпта менеджера
      общие правила (числа с пробелами, готовые русские даты, род по отчеству, JSON-формат
      ответа) - переиспользуются в промпте логиста, не копируются.
- [ ] `buildLogistAiContext_(ss, orders, logistName, period)` - маржа найма к порогу премии
      1М (факт+прогноз), топ-8 поставщиков (маржа/% /документы), топ-5 последних сделок,
      никакой кросс-ссылки с ДЗ (в отличие от менеджера) - долг клиента числится за его
      менеджером по продажам, не за логистом, ложная связь была бы хуже отсутствия.
- [ ] `buildLogistAiTasksPrompt_(logistName, context)` - домен-факты логиста: "нет путёвки" -
      ЭТО его работа (в отличие от менеджера, где это зона логиста - на своей странице логист
      как раз тот, кто должен её запросить); margin_pct <23% не квалифицируется на 8% бонус -
      можно рекомендовать пересмотреть ставку/сменить поставщика; category
      "выручка/поставщики/документы" вместо "выручка/дебиторка/документы" у менеджера.
- [ ] `doGet action=generate_ai_tasks` - разрешить роль `logist` (форсит `access.name`, как и
      `manager`), ветвление на `generateManagerAiTasksCached_`/`generateLogistAiTasksCached_`.

### Фаза 3 - фронтенд renderMyPageLogist
- [ ] Блок ИИ-задач - первым, через `renderAiTasksBlock_(current)`.
- [ ] Полоска "Маржа найма к премии >1М" через `planProgressBar` (переиспользован) - factPct/
      forecastPct считаются от `salary.totalMargin`/порога 1М, с рекомендацией "сколько в
      день добрать" (та же арифметика остаток/оставшиеся дни, что у менеджера, без
      будни/выходные - под наём нет обоснованной эмпирики сезонности, как у продаж).
- [ ] Расчёт зарплаты - переверстать на `salRow`/`pctBadge_`/`salTotalRow`, добавить "Итого по
      прогнозу" через `scaleRowForForecast_(getL(sur), paceRatio)` + `calcLogist` на
      масштабированной строке (та же формула, не дублируется).
- [ ] Убрать 3 отдельных блока (Маржа по поставщикам / Воронка документов / Сделки), заменить
      одним `card` с `tab-bar` (новое state - `myPageLogTab`), переиспользовать уже готовые
      `supRows`/`funRows`/`dealRows`.

### Фаза 4 - проверка и деплой
- [ ] Синтетика: полоска (3 цветовые зоны на маржу к 1М), зарплата факт+прогноз сходятся,
      вкладки переключаются, ИИ-блок грузится/кэшируется/регенерится тем же паттерном, что у
      менеджера.
- [ ] Регрессия: страница менеджера и Васина не задеты выносом общих функций.
- [ ] Деплой (frontend + Apps Script), запись в DEPLOY_LOG.md.

## Риски

- Живой вызов kie.ai с новым (логистским) промптом - не проверен вживую в этой сессии (та же
  причина, что и у менеджерского промпта на старте - нет доступа к ключу/редактору). Кнопка
  "🔄 Заново" уже есть - Владу нужно будет проверить и дать построчную обратную связь, как с
  промптом менеджера (10 итераций до текущего состояния) - логист, скорее всего, тоже
  потребует доводки.
- "Маржа к премии >1М" не идеальный аналог "плана продаж" (порог фиксированный, не растёт с
  масштабом, как план) - но это прямая просьба Влада ("прогресс до премии >1М"), не
  самодеятельность.
