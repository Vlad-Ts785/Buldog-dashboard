# Суды: вкладка «Суды» внутри Дебиторки

Дата: 2026-09-15. Заказчик: Влад («есть страница с дебиторкой, есть клиенты которые в судах -
хотелось бы в одном окне смотреть по всем ним статусы», ссылка-пример на карточку КАД).

## Решение Влада (15.09, три развилки)

1. **Охват** - наши иски к должникам (наши 8 юрлиц в роли ИСТЦА). Дела, где мы ответчики, и
   суды контрагентов между собой - не сейчас (второе частично уже есть в светофоре риска).
2. **Глубина** - статус + ссылка на карточку КАД, обновление раз в сутки. Без хронологии
   заседаний (Электронный страж / платный парсер КАД - отложено, см. «Что дальше»).
3. **Место** - вкладка внутри страницы «Дебиторка», рядом с «ДЗ» и «План поступлений».

## Что выяснено живой проверкой (15.09, до написания кода)

**Прямой доступ к kad.arbitr.ru с нашего VPS закрыт:** GET карточки отдаёт страницу капчи
ПравоТеха (`pravocaptcha.js`), внутренний `POST /Kad/SearchInstances` - HTTP 451. Обход
антибота не рассматривается: защита стоит намеренно, это бизнес владельца КАД.

**Checko (ключ уже в `.env`, метод `/v2/legal-cases`) отдаёт всё, что нужно для MVP.**
Проверено на деле из ссылки Влада - `role=plaintiff` по ИНН 7702417768 нашёл его сразу:

```

Дата: 2026-09-14        Суд: АС Московской области

СуммИск: 150234.99      ИсходТекст: "Дело рассматривается"   ПрАктив: true
```

Объём на 15.09: Бульдог - 12 дел истца (7 активных), ЯРД Империал - 182 (13 активных на
первой странице). Остальные 6 юрлиц не замерялись.

**Дополнительно доступен `/v2/enforcements`** - исполнительные производства ФССП по
должнику (номер ИП, исполнительный лист, пристав, остаток задолженности). У ООО «КДСП» уже
висит ИП на 169 393,97 ₽ по ДРУГОМУ листу. В MVP не включаем (см. «Что дальше»).

## Инварианты

1. **Квота Checko - 100 запросов/сутки на ОДИН ключ, она общая** с ночным автопрогоном
   светофора риска (`risk-check-daily.js`, 03:10 UTC, берёт «сколько влезет» до 90).
   Синхронизация судов ставится РАНЬШЕ него (02:40 UTC) и стоит ~10-16 запросов - тогда
   рискам достаётся остаток до того же потолка 90, порядок не ломается.
2. Считаем `ПрАктив === true` как «дело идёт сейчас» - ровно та же семантика, что уже
   принята в светофоре риска (`checkoFetchLegalCases_`), другого признака у Checko нет.
3. Ссылка на КАД берётся из ответа (`СтрКАД`), не собирается вручную из UUID.
4. Роль - только `admin`. Наши иски это не то же, что список должников: менеджеру видеть
   претензионную работу не нужно, а протечка чувствительного блока в урезанную копию
   страницы уже была прецедентом (`project_dept_trals_direkcia_leak_bug`).

## Фаза 1 - MVP (готово к показу в этот заход)

- [ ] `court_cases` + `court_case_events` в MySQL (`import/court-schema.sql`)
- [ ] `courtFetchPlaintiffCases_(inn)` в `api/server.js` - страницы, пока на странице есть
      активные дела (максимум 3), возврат сырых записей
- [ ] `courtSyncRun_()` - обход `sprav_legal_entities WHERE is_own=1`, upsert по UUID,
      дельта статуса/суммы/появление/закрытие -> `court_case_events`
- [ ] `GET /api/court/cases` (admin) - дела + связка с долгом ДЗ по ИНН ответчика +
      сводка; `GET /api/court/events`; `POST /api/court/sync_now` (кнопка «Обновить»)
- [ ] `import/court-cases-sync.js` + cron `40 2 * * *`
- [ ] Фронт: третья плитка «Суды» в хабе Дебиторки + вкладка (сводка, лента изменений,
      сортируемая таблица по канону ГОСТа, ссылка на карточку КАД)
- [ ] Значок молотка в строке должника на вкладке «ДЗ» (только admin)
- [ ] Чек-лист приёмки `DESIGN_SYSTEM.md` раздел 10

## Что дальше (не в этот заход, решение за Владом)

- **Электронный страж** (guard.arbitr.ru, бесплатно, официально): подписка по ИНН наших
  8 юрлиц, письма с `guard@arbitr.ru` при каждом движении дела (назначено заседание,
  поступил документ, вынесено решение). Даёт то, чего у Checko нет - хронологию и дату
  следующего заседания. Требуется учётка на my.arbitr.ru и разбор писем (канал парсинга
  почты в проекте уже есть). Уточнить у Влада, есть ли доступ и у кого.
- **Исполнительные производства** (`/v2/enforcements`): что с делом ПОСЛЕ решения -
  возбуждено ли ИП, сколько реально осталось у пристава. +1 запрос квоты на должника,
  логично включать только по выигранным делам.
- Дела, где мы ответчики (`role=defendant` по своим ИНН) - та же таблица, признак роли.
