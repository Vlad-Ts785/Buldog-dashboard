# Прослушивание записей звонков + автоопределение ответственного по Авито-звонкам

## Зачем

Влад увидел сделку из Авито без ответственного - непонятно, кто именно разговаривал с
клиентом (менеджеры принимают все звонки на один сотовый через АТС, Авито это никак не
помечает). Спросил, есть ли записи у Авито/Манго и можно ли найти логику.

**Находка (08.09, по скриншотам Влада + CSV из Манго):** звонок "в приложении Авито" не
отдельный канал - он физически идёт через нашу основную линию Mango (`79330918978`,
"Группа тралы"). Подтверждено тремя совпавшими парами (номер телефона + время с точностью
до минуты) в скриншотах Авито/Манго и лично Владом ("играла музыка из нашей АТС"). Значит
у каждого звонка из Авито ЕСТЬ реальная запись - просто не в Авито, а в Манго.

**Как выглядит успех MVP:**
1. У звонка в карточке сделки/в треде чата, если запись есть - кнопка "Прослушать", играет
   реальный разговор.
2. Историческим Авито-звонкам (уже импортированным) там, где это технически возможно (см.
   ниже про окно данных), проставлен ответственный - автоматически, по совпадению времени
   со звонком в Mango.
3. Новые звонки из Авито - то же самое сразу, без ручного бэкфилла.

## Что НЕ делаем в v1

- Не подключаем платную выгрузку записей на FTP/Яндекс.Диск (5900₽/мес) - для разового
  "по клику" скачивания хватает уже включённого `POST /vpbx/queries/recording/post`.
- Не строим отдельный "журнал звонков" вне карточки сделки/чата - записи слушаем там же,
  где сейчас показан сам факт звонка.
- Не трогаем маппинг добавочный->менеджер (`crm_employees.extension`) - уже есть, работает
  для прямых Mango-звонков.

## Фаза 2+ - Рост (не для v1)

- Автообновление "не готова" (202) - сейчас просто просим нажать ещё раз позже.
- Показывать длительность/локально кэшировать скачанные байты в браузере, чтобы не тянуть
  повторно при повторном открытии той же карточки в течение сессии.
- Разбор, что означает `action: 'play'` у Mango в сравнении с `'download'` (сейчас всегда
  `'download'` - разницы в потреблённых нами байтах не увидели, но не проверяли глубоко).

## Итог бэкфилла (08.09)

`crm_calls` физически содержит данные только с **2026-08-27** (раньше Mango-вебхук либо не
слал эти события, либо мы их не сохраняли - для целей этой фичи неважно, важно что раньше
взять запись физически неоткуда). Импортированная история Авито-звонков (`msg_type call/
appCall`) уходит в прошлое до конца июня.

Из 284 кандидатов **265 стоят раньше 2026-08-27** - для них сопоставление математически
невозможно (в `crm_calls` для этого периода вообще ничего нет), это не баг матчинга. Из
оставшихся **19, что попадают в реальное окно перекрытия, совпало 14 (74%)** - разумный
результат: часть звонков могла не дозвониться/не подключиться (`call_state != 'Connected'`)
или выйти за пределы окна ±180с. Новым звонкам это ограничение не касается - `crm_calls`
пополняется постоянно, корреляция будет работать для всех входящих звонков Авито с этого
момента.
