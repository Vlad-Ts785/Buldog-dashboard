# Начальник автоколонн (руководитель над начальниками автоколонн) - Феськов

Влад, 23.09: "У нас новый сотрудник пробуем. Феськов Андрей Леонидович +7 916 923 99 98 он
будет начальником у барыльченко и дьячкова. Сразу логику построй правильно как мы сделали у
ахтамовой и гусейновой кто у кого то у кого руководитель, чтобы это не захаркорить в код. На
его странице он должен видеть планировку логистов, технику, динамику, зарплаты водителей,
пока без личной страницы. Почта a9169239998@gmail.com".

Повод и прецедент - `plans/2026-09-22-commercial-team-structure-not-hardcoded.md` (та же
задача для коммерческого отдела, сделана накануне). Здесь тот же паттерн (`*_head` колонка +
`refresh*Teams_()` + эндпоинт), но для отдельной, логистической иерархии - НЕ переиспользуем
`commercial_head` (разные домены логики: CRM/видимость сделок и заявок vs Планировка/Техника/
Динамика/зарплата машинистов нескольких сегментов).

## Кто есть кто (проверено в БД 23.09, Феськова нет ни в одной таблице - реально новый)

- Барыльченко - начальник автоколонны длинномеров (`COLUMN_HEAD_FLEET_.барыльченко='long'`).
- Дьячков - начальник автоколонны тралов+файмонвилей (`COLUMN_HEAD_FLEET_.дьячков='tral'`).
- Феськов - НАД обоими: `fleet_head='феськов'` у Барыльченко И у Дьячкова.
- "Кто ГОЛОВА" остаётся коротким хардкод-списком (как `COLUMN_HEAD_SUR_FRONT_`/
  `COMMERCIAL_HEAD_SUR_FRONT_` - редкое, требующее решения Влада о новой роли событие) -
  ДИНАМИЧЕСКИЙ становится только состав команды под головой (тот же компромисс, что вчера).

## 1. Схема (VPS MySQL)

`ALTER TABLE sprav_people ADD COLUMN fleet_head VARCHAR(60) NULL` - зеркало `commercial_head`
(та же форма: фамилия головы нижним регистром, или NULL). Самореференс у головы самой на себя
не нужен (Феськов - логист без персональной страницы, в `FLEET_HEAD_TEAMS_` он ключ, не
член своей же команды).

## 2. Бэкенд (`api/server.js`)

- `let FLEET_HEAD_TEAMS_ = {}` + `async function refreshFleetHeadTeams_()` - зеркало
  `refreshCommercialHeadTeams_()`, группирует `sprav_people.fleet_head`. Вызов при старте,
  раз в 5 минут, и сразу после `POST /api/sprav/person`, если `fleet_head` изменился.
- Новый `GET /api/fleet_head_teams` (`checkSession`, без ограничения роли).
- `/api/sprav/person` GET/POST - добавить `fleet_head` в `peopleCols`/INSERT/UPDATE рядом с
  `commercial_head`.
- `function fleetHeadBucketsFor_(sur)` - объединение бакетов ВСЕХ начальников автоколонн под
  этой головой: `(FLEET_HEAD_TEAMS_[sur]||[]).reduce` через `columnHeadFleetFor_`/
  `columnHeadBucketsFor_` каждого члена, уникализировать.
- `/api/my_driver_payroll` и `/api/my_driver_payroll_detail` - сейчас: `fleet =
  columnHeadFleetFor_(own); if (!fleet) 403`. Меняем на: если `own` - начальник автоколонны
  (`columnHeadFleetFor_`), буреты как раньше; иначе если `own` - голова
  (`FLEET_HEAD_TEAMS_[own]`), буреты = `fleetHeadBucketsFor_(own)`; иначе 403. `_detail`
  проверяет принадлежность запрошенного `driver` своим бакетам - логика не меняется, буреты
  просто шире.
- `/api/vehicle_timeline` (Динамика) - сейчас `requireRole_("admin")`, жёсткий отказ любому
  не-admin. Меняем на `checkSession` + ручная проверка: admin - пропустить; иначе резолвить
  `own` по `access_users` и пускать, только если `FLEET_HEAD_TEAMS_[own]` существует (то есть
  человек - голова с командой). Обычный логист/менеджер - как раньше, 403.
- `/api/avtodor_summary` - уже `checkSession` без ограничения роли, трогать не нужно.
- `/api/main_payload`, ветка `role !== 'admin'` (строка ~10519) - `payload.vehicles` сейчас
  собирается ОБРЕЗАННЫМ набором полей (`gos,marka,type,status,driver,trailer,plan,profit`,
  БЕЗ `revenue/fuel/fot/parts/fines/tolls`) - этого достаточно для Планировки, но НЕДОСТАТОЧНО
  для полноценной страницы "Техника" (`renderVehiclesTable`/`computeFuelStats` в
  `files/index.html` читают именно эти поля). У начальников автоколонн своей "Техники" не
  было (не было в `allowedPages_`), поэтому это не всплывало раньше. Для Феськова - первого
  не-admin с доступом к общей "Технике" - используем ПОЛНЫЙ набор полей (те же данные,
  `fleetSummary`/`parkHistory` уже загружены в этой ветке, лишнего запроса не добавляет):
  если вызывающий - распознанная голова автоколонн (`FLEET_HEAD_TEAMS_[surOf_(personName)]`),
  маппим `vehicles` тем же кодом, что admin-ветка (строка ~10596), а не обрезанным.

## 3. Фронтенд (`files/index.html`)

- `var FLEET_HEAD_SUR_FRONT_ = ['феськов'];` - рядом с `COLUMN_HEAD_SUR_FRONT_`/
  `COMMERCIAL_HEAD_SUR_FRONT_` (строка ~9530/9554) - короткий список "кто голова", тот же
  принцип.
- `applyRoleUI()` (~13408-13488) - новый флаг `isFleetHeadViewer = FLEET_HEAD_SUR_FRONT_.
  indexOf(curPersonSur) >= 0`. Влад явно: "пока без личной страницы" - убираем `'my-page'` из
  базового набора именно для этого вьюера (у всех остальных логистов/менеджеров остаётся).
  Итоговый набор: `['calculator', 'logistics-plan', 'vehicles', 'dynamics',
  'column-head-payroll']` - без `'order-plan'` (по аналогии с `isColumnHeadViewer` - Феськов
  не занимается заявками лично, так же как Барыльченко/Дьячков). Дефолтная страница при
  входе - сейчас жёстко `showPage('my-page')` (строка ~13488), для этого вьюера ломается (нет
  такой страницы) - меняем на `showPage(isFleetHeadViewer ? 'logistics-plan' : 'my-page')`.
- `chPayrollBuckets_()` (~24779-24782) - СЕЙЧАС хардкод-тернарник `сур==='дьячков' ? [трал,
  файмонвиль] : [длинномер]` - для Феськова оба варианта неверны (он должен видеть ОБА
  сегмента). Тот же класс бага, что `TRAL_MANAGERS` вчера - чиним сразу, не откладываем:
  добавляем ветку `FLEET_HEAD_SUR_FRONT_.indexOf(sur) >= 0` в начало, возвращает
  `['трал','файмонвиль','длинномер']`. Используется и в реальном запросе (фильтр поверх уже
  отфильтрованного сервером ответа - избыточен, но не вредит), и в admin-предпросмотре
  (единственный путь получить буреты клиентски при "Смотреть как").
- `menuTierKey_()` (~26978) - новый тир `fleet_head` (`if (FLEET_HEAD_SUR_FRONT_.indexOf(sur)
  >= 0) return 'fleet_head';`, до проверки `column_head`), + подпись в `MENU_TIER_LABEL_`
  ("руководитель автоколонн") - иначе кастомное меню Феськова делило бы конфиг с обычными
  логистами, у которых набор пунктов совсем другой.
- Справочники → Сотрудники, блок `drv-reg-manager-fields` - у Феськова роль "Логист", не
  "Менеджер", значит этот блок (виден только при роли "Менеджер") ему не подойдёт. Нужен
  АНАЛОГИЧНЫЙ блок для роли "Логист" - `drv-reg-logist-fields` с `<select id="drv-reg-
  fleet-head">` (опции - из `/api/fleet_head_teams` ключей + читаемое имя, сейчас только
  "Феськов Андрей"), видимый когда включена роль "Логист" (зеркало `drvRegToggleManagerFields_`
  -> `drvRegToggleLogistFields_`). Это ЖЕ форма используется, чтобы проставить `fleet_head`
  Барыльченко и Дьячкову (не прямым SQL - тот же принцип дожфудинга, что вчера с Гуцу/
  Кимличенко).

## 4. Онбординг Феськова - что можно через код/UI, что нельзя

- `sprav_people` - новая запись (ФИО, телефон `+7-916-923-99-98`, роль "Логист",
  `employment_status='active'`) - через реальную форму Справочники → Сотрудники → Добавить
  (дожфудинг, не INSERT).
- `access_users` (логин/роль `logist`, email `a9169239998@gmail.com`) - **НЕ через SQL**.
  `access_users` - живое ЗЕРКАЛО листа Google Sheets "Доступ" (полная перезапись раз в 5 минут,
  см. память `project_access_users_truncate_insert_lockout_incident` - прямой INSERT сотрётся
  следующей синхронизацией и может увести таблицу в рассинхрон). Строку в лист "Доступ"
  добавляет САМ Влад (email/имя/роль=logist) - без этого шага Феськов физически не сможет
  войти, дальше всё остальное (меню/данные) готово и сработает сразу после первого входа.
- `Барыльченко.fleet_head='феськов'`, `Дьячков.fleet_head='феськов'` - через UI (см. выше).

- `GET /api/fleet_head_teams` после простановки - `{феськов: ['барыльченко','дьячков']}`.
- Форджед токен под Феськовым (после того как Влад добавит доступ) или "Смотреть как" -

  Калькулятор - без "Личной страницы" и без "Задание".

  одной таблице, суммы совпадают со страницами самих Барыльченко/Дьячкова за тот же месяц.
- "Техника" - таблица не пустая, колонки выручка/топливо/штрафы/план заполнены (не нули у
  всех подряд - признак обрезанного маппинга).
- "Динамика" - лента по дням грузится, не падает в 403.
- `node --check` по всем script-блокам `files/index.html`, синтаксис `api/server.js` на VPS
  перед restart.
