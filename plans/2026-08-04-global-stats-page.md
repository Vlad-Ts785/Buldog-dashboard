# План: страница "Глобальная статистика" - ключевые метрики по месяцам + динамика за год

**Дата:** 2026-08-04
**Автор:** Клод (с Владом)
**Статус:** в работе

## Цель

Новая страница дашборда: выбрать любой месяц (не только текущий) и увидеть ключевые цифры
бизнеса за него (выручка, валовая прибыль по сегментам, выполнение планов), плюс график
этих же метрик по всем месяцам года одним взглядом - без переключения между вкладками.

## Контекст

Повод (Влад, 2026-08-04): на "Панели" карточка "Валовая прибыль" в начале августа временно
показала июльские цифры (пока не настроена рассылка августовского "Отчёта парк" - это
отдельный, уже решённый вопрос на стороне 1С, не баг дашборда). Разбирая это, Влад
сформулировал более широкую потребность: "эти ключевые данные важны, хочу видеть их по
каждому выбранному месяцу и в динамике по году".

Что уже есть и можно переиспользовать:
- Переключатель периода на "По менеджерам"/"Заказах" (план от 2026-06-30) - `changePeriod()`,
  `getOrdersDataForPeriod()`, `getGrossProfitForPeriod()`, `getAvailablePeriods()`. Уже умеет
  доставать факт/план продаж и ВП за произвольный архивный месяц.
- `computeSalesFaktPlan_(ordersData)` (2026-08-04, сегодняшний фикс) - общий расчёт
  факта/плана без задвоения внутренних, один источник для текущего и архивного периода.
- `aggregateFinHistoryForRange()` - уже умеет брать ВП по сегментам (тралы/длинномеры) за
  любой диапазон дат, источник - `Данные_1С_история` (архив по месяцам) с фолбэком на
  посуточные снимки `История_финансов`.
- Chart.js уже подключен и используется (графики на "Динамике", мини-график ДЗ на Панели).

Чего не хватает: сейчас "по каждому месяцу" данные достаются КАЖДЫЙ РАЗ заново (разбор
архивного листа заказов на лету + пересчёт ВП по диапазону дат). Для одного выбранного
месяца это нормально (так и работает "По менеджерам"), но для графика по ГОДУ (до 12 точек
разом) пересчитывать всё на лету при каждом открытии страницы - медленно и не нужно, эти
цифры не меняются задним числом (кроме текущего месяца). Нужен лёгкий кэш - сводная таблица
"месяц -> ключевые цифры", которая копится по ходу дела и не пересчитывается с нуля каждый раз.

## Фазы

### Фаза 1. Бэкенд: сводный лист по месяцам (~1 час)
- [x] Новый лист `История_месяцев`: Месяц | Выручка | План продаж | ВП | ВП тралы |
      ВП длинномеры | ФОТ | Топливо | Запчасти | Штрафы | Проходные | Прибыль найма |
      Выручка найма | Обновлено. "ВП план" сознательно НЕ включён - `PROFIT_PLAN` на фронтенде

      решают, откуда брать данные. Идемпотентно, ищет строку по месяцу перед записью.
- [x] В `runAll()` - вызов после `saveFinancialHistory()` (данные уже свежие на этот момент)

## Критерии готовности

- [ ] Можно выбрать любой месяц с архивом и увидеть его выручку/ВП/план так же, как сейчас
      видно только для текущего месяца на "Панели"
- [ ] График по году строится без ручного пересчёта, из кэша `История_месяцев`
- [ ] Текущий месяц на графике не отстаёт от реальных цифр (обновляется на каждом `runAll()`)
- [ ] Нет расхождений между этой страницей и уже существующими вкладками за один и тот же месяц

## Риски

- ВП по парку для архивного месяца зависит от `Данные_1С_история` - если за какой-то месяц
  этот архив не был создан вовремя (отчёт парка не был настроен, как ровно сейчас с августом),
  `История_месяцев` для него останется пустой/неточной. Не глушить молча - показывать явно
  "нет данных за месяц", а не 0 или устаревшую цифру.
- `saveMonthSummary_` на каждом `runAll()` - лишняя нагрузка на таблицу, если считать текущий
  месяц через полный `getOrdersDataForPeriod`-путь (разбор архива) вместо `getOrdersData`/
  `getSummaryData`, которые и так уже посчитаны в этом же прогоне - использовать готовое,
  не пересчитывать заново.
- `backfillMonthSummaries()` может быть медленной на большом числе месяцев сразу (Apps Script
  6-минутный лимит на выполнение) - если понадобится, разбить на несколько запусков по частям.

## Открытые вопросы (закрыты Владом, 2026-08-04)

- Набор метрик: **Выручка, Затраты (по категориям), ВП (тралы/длинномеры) + планы, Маржа

- "Динамика по году" = всё, что накопилось в `История_месяцев` (сейчас с июня 2026), без
  привязки к календарному году.
- Прошлые года - вне скоупа, подтверждено.
