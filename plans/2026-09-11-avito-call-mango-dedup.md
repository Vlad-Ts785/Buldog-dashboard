# Слияние дублей звонков Авито/Mango

**Зачем:** менеджер (Гуштюк) заметила, что звонок в приложении Авито создаёт ДВЕ карточки
в CRM на один и тот же реальный разговор, и вручную подписала вторую "повтор", чтобы не
запутаться. Влад: "Молча сливаем, что бы не было путаницы. Запись звонка должна быть."

**Как выглядит успех:** звонок через Авито создаёт РОВНО одну сделку с записью разговора
и грузом/маршрутом из чата Авито - без ручных пометок менеджера.

## Что не делаем в v1

- Не трогаем закрытые (won/lost) исторические дубли автоматически - бэкфилл сливает только
  identity (чат/сообщения/клиент), сделки сливает только если ОБЕ ещё открыты.
- Не расширяем окно сопоставления сверх необходимого (30 сек, не "с запасом побольше") -
  выше риск ложного слияния двух разных клиентов, позвонивших почти одновременно.
- Не трогаем платёжную логику (orders-calc.js) - задвоения денег на этих 18 случаях не
  было ни разу, но если бы было - это отдельный, более осторожный разговор с Владом.

## Фаза 0 - Диагностика (сделано 11.09)

Живой пример (Убайдуллаев, сделки 143/144) разобран по сырым данным Mango
(`crm_calls.raw_json`, `talk_time`) и Авито (`crm_messages.mango_entry_id`). Подтверждено
на ВСЕЙ истории (32 звонка): сообщение Авито о звонке приходит через 0-1 сек ПОСЛЕ конца
разговора (`call_state='summary'`), железно, без исключений. Старое окно сопоставления
(180с от момента ОТВЕТА, `Connected`) промахивалось мимо длинных разговоров - 3
подтверждённых дубля (204/240/342 сек) из-за этого не сопоставлялись автоматически, отсюда
и ручная пометка "повтор" - встроенная защита физически не могла их поймать.

## Фаза 1 - MVP (сделано 11.09)

- [x] `correlateAvitoCall_` (api/lib/avito-sync.js) - якорь сопоставления сменён с
      `Connected` (окно 180с) на `summary`/конец звонка (окно 30с) - точнее и по факту, и
      по физике процесса (Авито не может прислать событие о звонке, пока звонок не завершён).
- [x] `mergeAvitoIdentityToPhone_` - при найденном совпадении переносит
      `crm_avito_chats.client_key`/`crm_messages.client_key`/`crm_clients`/открытую
      `crm_deals` с синтетического `avito:<id>` на реальный номер. Дальше вся карточка
      (звонки, запись, переписка) строится по `client_phone` - ничего дополнительно
      подключать не пришлось, это уже готовая логика `deal_detail`.
- [x] `ensureChat` - не пересчитывает `client_key` заново на каждом синке (иначе следующий
      же проход откатывал бы слияние обратно на `avito:<id>`).
- [x] Сливается и недозвон (`talk_time=0`) - тот же реальный человек, просто без
      ответственного (отвечать было некому).
- [x] Бэкфилл истории (`import/backfill_avito_dedup_ONETIME.js`, удалён сразу после
      использования) - 32 исторических пары, 7 реальных слияний открытых сделок
      (в т.ч. 144→143, живой пример), 25 - перенос только identity (сделки уже закрыты).
      Бэкап БД снят перед прогоном (`import/backup-db.js`).
- [x] Проверено живьём: `GET /api/crm/deal_detail?id=143` - `has_recording: true`,
      151 сек разговора, ответственный Ирина Гуштюк; карточка канбана одна, ручная пометка
      "повтор" снята (стала бессмысленной после слияния).

### Прогон через 4 вопроса

1. Решает ли проблему? Да - убирает и текущий, и будущие дубли одним и тем же кодом.
2. Не "код ради кода"? Переиспользует всю существующую инфраструктуру deal_detail/ensureDeal
   ("есть открытая сделка?") - новый код только про то, ПОД КАКИМ КЛЮЧОМ её искать.
3. Не усложняет для v1? Да, минимально - один якорь события, одна функция переноса.
4. Что лишнее выкинуто? Не стали чинить "почему `Connected`-якорь был неточным" отдельным
   рефакторингом - просто заменили на надёжный `summary`-якорь, который заодно чинит и
   старую проблему недосопоставления.

## Фазы 2+ - не для v1

- Автоматическая periodic-проверка "не осталось ли новых несмёрженных дублей" (сейчас
  слияние срабатывает только в момент прихода СЛЕДУЮЩЕГО звонка/сообщения по чату - если
  чат больше никогда не тронут, дубль теоретически может дожить бесконечно; на практике
  редкий случай, не увиденный ни разу в истории).
- Расширение окна/логики на ДРУГИЕ пары каналов (Calltouch х Avito, Calltouch x Mango) -
  Calltouch пока не создаёт сделок сам (только карточка трафика в Аналитике), риска нет.
