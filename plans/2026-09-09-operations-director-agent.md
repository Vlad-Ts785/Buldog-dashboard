# ИИ-агент «Операционный директор»: каждый день отвечает, что сделать, чтобы больше заработать

**Дата:** 2026-09-09
**Статус:** Фаза 1 СДЕЛАНА 09.09 (сервер на бою, крон 07:00 МСК, первый бриф собран за 97 с; фронт в ветке `claude/operations-director-agent-b029b3`, ждёт решения Влада о публикации в main). Фазы 2+ - по отдельным «да».

## Зачем

Влад: «Нужно вырастить агента руководителя (операционного директора), который анализирует
все показатели бизнеса ежедневно и начинает учиться управлять бизнесом. Пока - в качестве
моего ассистента, пока учится. Данных полно, и они будут только прибавляться.
Каждый день он должен начинать с вопроса: а какие нам нужно сделать действия, чтобы больше
зарабатывать».

**Как выглядит успех MVP:** утром на странице «Операционный директор» лежит свежий бриф
за сегодня: главный вывод дня, состояние ключевых показателей (что в норме, что требует
внимания), 3-5 действий с оценкой в рублях, ответственным и метрикой для проверки
завтра, и отчёт по вчерашним действиям (что изменилось). Влад отвечает на каждое действие
одной кнопкой: «Согласен» / «Не согласен» (с комментарием) / «Сделано». На следующий день
агент видит эти ответы и свои прошлые заметки - и его советы становятся точнее. Это и
есть «учится»: не дообучение модели, а накопленная память о бизнесе + обратная связь
руководителя, которые подмешиваются в каждый следующий запуск.

## Что НЕ делаем в v1

- **Агент ничего не делает сам.** Ни задач сотрудникам, ни сообщений, ни правок данных.
  Только текст для Влада. Полномочия - Фазы 3-4, каждая по отдельному «да».
- **Не дообучаем модель (fine-tuning)** - на объёме «один бриф в день» бесполезно. Тот же
  вывод, что в плане агента продаж (`plans/2026-09-09-sales-agent-learning-from-history.md`):
  контекстный подход + один живой документ-память. Память агента = обычный текст в БД,
  который он сам переписывает каждый день (как плейбук продаж), не embeddings.
- **Не строим отдельный ИИ-слой с доступом к SQL («tool use»).** Контекст собирается
  детерминированно из тех же эндпоинтов, что кормят Панель (`/api/orders_computed`,
  `/api/debt_computed`, `/api/park_summary`, `/api/fleet_summary`, `month_summary`,
  `debt_history`) - агент видит ровно те же цифры, что Влад на экране (принцип «цифры
  бьются везде», `project_data_consistency_principle`). Свободный SQL - Фаза 5.
- **Не шлём в Телеграм.** На сервере нет токена бота (он в Script Properties Apps Script).
  Фаза 2, копейки работы, но требует переноса секрета - отдельный шаг с Владом.
- **Не делаем красивую страницу с графиками.** Бриф - текст и список действий в
  стандартной карточке ГОСТа (клон «Проверка контрагента»). Спарклайны, табло - потом.
- **Не анализируем CRM/звонки/Авито.** v1 - деньги, парк, долги, документы, найм,
  план продаж. CRM-воронка, плейбук продаж, телематика - Фаза 2+ (по одному источнику
  за раз, каждый - проверка «стало ли полезнее»).

- `import/risk-check-daily.js` - образец ночного крона, который дёргает свой же API с
  `SERVER_KEY`. Копируем.
- Старая вкладка «Система решений» (`plans/2026-06-26-decision-system.md`) - 8 карточек
  по жёстким правилам (собрать деньги / закрыть документы / вернуть технику / меньше

  но это готовый список «куда смотреть» - идёт в промпт как рамка мышления агента.

## Фазы 2+ - Рост (НЕ сейчас, каждая по отдельному «да» Влада)

- **Фаза 2 - канал доставки и больше источников.** Телеграм-сообщение с брифом в 07:05
  (перенести `TELEGRAM_TOKEN` в `.env` сервера, чат - `CONFIG.TELEGRAM_CHAT_ID`). Затем
  по одному источнику: CRM-воронка (`crm_deals`/`crm_deal_stage_history`), плейбук
  продаж, банковские СМС (`bank_operations`), телематика. Каждый - смотрим, стали ли
  советы точнее, иначе убираем.
- **Фаза 3 - агент ставит задачи людям (через Влада).** Кнопка «Согласен» превращает
  действие в задачу ответственному: запись в `ai_tasks_cache` (блок «Задачи на сегодня
  (ИИ)» на личной странице менеджера/логиста) или сообщение в CRM/Телеграм. Всё ещё
  ничего не уходит без нажатия Влада.
- **Фаза 4 - лестница доверия.** По каждой категории действий (дебиторка, документы,
  найм, парк...) считаем долю «Согласен». Категория, где Влад согласен N раз подряд
  (N назначает Влад), становится «автоматической»: задачи уходят людям без нажатия,
  Влад видит недельный отчёт «что агент сделал сам» и может отозвать. Именно здесь агент
  «начинает управлять» - но только там, где уже доказал, что думает как Влад.
- **Фаза 5 - агент сам ходит за данными.** Tool use: агент может задать вопрос базе
  (ограниченный набор read-only запросов) вместо готового контекста, копать причины
  («почему ВП по тралам упала - какие машины?»). Плюс недельный/месячный обзор поверх
  дневных брифов (агрегация своей же истории).
- **Фаза 6 - самооценка.** Раз в неделю агент сверяет свои прогнозы (`check_metric`)
  с фактом и пишет себе в память «в чём ошибался» - вторая петля обучения, уже без
  участия Влада.
