# План: Личная страница логиста (Прус Роман и остальные)

**Дата:** 2026-08-10
**Автор:** Клод
**Статус:** реализовано, ждёт деплоя Apps Script

## Цель

Дать логисту (начиная с Прус-Роскошного) личную страницу — по аналогии с уже существующей
личной страницей менеджера, но со своим набором блоков: маржа по поставщикам (его сделки),
воронка документов по поставщикам, список его сделок, расчёт зарплаты.

## Контекст

С июля 2026 у Прус-Роскошного больше нет двойной роли менеджер+логист — он только логист
(500₽/заказ своя техника + 8% квалифицирующей маржи найма, см. `calcLogist` в
`files/index.html`). Существующая "Личная страница" (`renderMyPage`, `files/index.html:1220`)
построена вокруг `D.orders.by_manager_detail` — там логистов нет физически (агрегация
`mgrDetailMap` в `scripts/full_script_final.js` строится только по `TRAL_MANAGERS`). Значит
Прус сейчас вообще не может увидеть свою страницу.

Влад попросил 4 блока: (1) общая маржа по поставщикам как в "Заказы → Наёмная техника", но
для его собственных сделок; (2) его сделки; (3) его воронка документов по поставщикам;
(4) блок расчёта зарплаты.

## Фазы

### Фаза 2. Фронтенд — личная страница логиста (~50 мин)
- [ ] Разбить `renderMyPage()` на диспетчер + `renderMyPageManager(...)` (старое тело функции)

## Критерии готовности

- [ ] Личная страница логиста рендерится с реальной структурой данных (не заглушка).
- [ ] Цифры маржи по поставщикам совпадают по логике с общей таблицей "Наёмная техника"
      (та же формула margin = profit из 1С, не revenue-cost).
- [ ] Зарплата на странице логиста совпадает с тем, что показывает вкладка "Зарплата" для
      того же человека за тот же период.

## Итог

- **Реализовано целиком:** да, включая опциональную Фазу 1 (`getLogistView_`/роль `logist` в `doGet`).
- **Что сделано:**
  - Бэкенд: `logistDetailMap`/`logistDetail()` в `aggregateOrdersRows`, копится в блоке "По поставщикам найма" (revenue/cost/extra_costs/margin/orders + список `deals`) и в блоке "Статус документов" (no_waybill/not_posted/no_realiz/complete по поставщику), собирается в `logist_detail` и уходит в JSON рядом с `by_manager_detail` - работает и для текущего месяца (`getOrdersData`), и для архивов (`getOrdersDataForPeriod`), т.к. оба вызывают одну `aggregateOrdersRows`.
  - `getLogistView_(ss, logistName)` + ветка `access.role === 'logist'` в `doGet` - по образцу `getManagerView_`.
  - Фронтенд: `renderMyPage()` стал диспетчером (менеджер+логист в одном списке, автовыбор своей записи по роли), старое тело переехало в `renderMyPageManager(el, current, selectorHtml, d)` без изменения логики, добавлен `renderMyPageLogist(el, current, selectorHtml, d)` с 4 блоками: KPI-шапка, маржа по поставщикам, воронка документов по поставщикам, его сделки, расчёт зарплаты (через существующие `calcLogist`/`calcVasin`, без дублирования формулы).
  - Проверено на синтетических данных прямо в браузере (`file://.../index.html` + инъекция `D` через `javascript_tool`) - все цифры зарплаты и маржи сошлись вручную; страница менеджера после рефакторинга рендерится как раньше.
- **Что не сделано и почему:** не задеплоено в Apps Script (`clasp push`) и не запрошено у Влада заполнение листа "Доступ" под роль `logist` для Прус-Роскошного - оба шага требуют его явного решения (правило репо №2 "не деплоить без команды" + деплой сразу станет виден всем).
- **Что добавить в бэклог:** "Топ поставщиков без путевых листов" для логиста (аналог менеджерской версии) можно вывести из уже собранного `by_supplier`, если понадобится; "его сделки" сейчас показывает только наёмные (не свои-паркные) заказы - уточнить у Влада, нужны ли и они.
- **Уроки:** GAS-код открывается в браузере как статический файл (`file://`) без сервера - удобный способ быстро проверить фронтенд-рендер на синтетических данных без реального деплоя бэкенда; ключевая ловушка - `let D` в топ-уровне скрипта не аліасится на `window.D`, инъектировать надо голым `D = {...}` в том же exec-вызове, что и рендер.
