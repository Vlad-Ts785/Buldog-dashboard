# Бот «Логист длинномеры» - автоматическая отправка заданий водителям

Пилот на группе «Длинномеры». Продолжение [[project_max_messenger_bot]] и
[[project_max_bot_buttons_driver_binding]].

## Контекст и решения (зафиксированы в диалоге с Владом 22-23.09.2026)

**Проблема:** кнопка «Отправить в Max» в модалке «Задание водителю» (order-plan-v2.js)
открывает ЛИЧНЫЙ MAX логиста с готовым текстом - логист сам жмёт «отправить». Водитель
видит сообщение от живого человека, но в такое сообщение нельзя встроить кнопку с
callback'ом - это умеет только бот.

**Решение (два бота, а не один):**
- **«Логист длинномеры»** (`@id7702417768_1_bot`, новый, токен получен 22.09) - общается
  ТОЛЬКО с водителями. Шлёт задание с кнопками [✅ Принял] / [❌ Отказ], при отказе -
  причина кнопками (пока 2 категории: Ремонт / Выходной, чисто информационные).
- **Спайк** (существующий) - НЕ трогаем его код этим пилотом. Уведомляет ответственного
  логиста, но ТОЛЬКО при отказе водителя (Влад: «не должен спамить логисту... сообщение
  приходит только если пришёл отказ и причина»). Принятие - тихо, только цветом.

**Матрица событие -> цвет -> уведомление:**

| Событие | Цвет в Планировке | Логисту сообщение (через Спайка) |
|---|---|---|
| Задание отправлено | ⚪ -> 🟡 (`op2-bot-sent`) | нет |
| Водитель принял | 🟡 -> 🟢 (`op2-bot-accepted`) | **нет** |
| Водитель отказался + причина | 🟡 -> 🔴 (`op2-bot-declined`) | **да** |

Отказ без причины невозможен (кнопки обязательны) - значит правило проще: сообщаем
ТОЛЬКО при отказе.

## Уже сделано (22.09, коммиты)

## Архитектура нового бот-модуля

**Изоляция от файла Спайка - осознанное решение**, а не лишняя работа: параллельная
сессия сейчас активно правит `api/lib/max-bot.js` (кнопки ремонта, привязка по телефону,
`max_pending`). Новый бот - **отдельный файл** `api/lib/logist-long-bot.js`,
**отдельная таблица** `logist_bot_chats` (НЕ трогает `max_chats`), **отдельный вебхук**
(`/api/logist_long/webhook`, свой `LOGIST_LONG_WEBHOOK_SECRET`). Общий код НЕ импортируется
из max-bot.js (риск конфликта при параллельном редактировании) - вспомогательные функции
(`digits10_`, `phoneFromVcf_`, `contactHashOk_`, `cbBtn_`) дублируются в новом файле
(контролируемое дублирование ради изоляции, оправдано - см. `feedback_economical...`
не применимо, это про другое; ближе к принципу «эксперимент не должен трогать боевой код»).

**Привязка водителя** - тот же паттерн, что уже проверен в Спайке (`request_contact` ->
вложение `contact` -> сверка последних 10 цифр телефона с `sprav_people.phone`, HMAC-подпись
СВОИМ токеном - у каждого бота свой ключ подписи, чужой не подойдёт). Пишет в
`logist_bot_chats.person_id`.

**Ответственный логист для уведомления при отказе** = `plan_order_executors.created_by`
(email того, кто назначил машину/водителя на заявку) - поле уже есть на самой строке
executor, дополнительный join не нужен. Уведомление шлётся напрямую через
`process.env.MAX_BOT_TOKEN` (токен Спайка) - raw fetch к botapi.max.ru, БЕЗ импорта кода
из max-bot.js: находим chat_id логиста в `max_chats` по email (READ-ONLY запрос к чужой
таблице, безопасно), шлём текст напрямую.

**Отправка задания** - текст собирается из тех же полей, что модалка «Задание водителю»
на десктопе (заявка №, машина+водитель, груз, погрузка/выгрузка с телефонами, логист) -
превью = контракт, тот же текст, что уже видел и утвердил Влад визуально.
