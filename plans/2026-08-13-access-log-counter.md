# План: счётчик входов сотрудников

**Дата:** 2026-08-13
**Автор:** Клод
**Статус:** реализовано

## Цель

Влад: "Я сегодня уже пробую раздать сотрудникам доступы. Они заходят на страницы. А можно
какой-либо счётчик поставить, чтобы видеть кто сколько раз заходил."

## Реализация

- Новый лист `Логи_входов` - одна строка на email (не полный лог каждого визита - рос бы
  бесконечно): Email | Имя | Роль | Первый вход | Последний вход | Заходов.
- `logAccessVisit_(ss, email, name, role)` - находит/создаёт строку, увеличивает счётчик,
  обновляет "последний вход", не трогает "первый вход".
- Вызывается в `doGet()` только когда `action` пуст - это признак ГЛАВНОЙ загрузки страницы
  (тот же принцип, что уже отличает основной запрос от мелких доп-запросов вроде
  `generate_ai_tasks`/`manager_lost_customers`) - иначе один визит на дашборд засчитывался бы
  много раз подряд (внутри одной загрузки страницы фронтенд делает несколько запросов).
  Обёрнуто в try/catch - сбой записи лога не должен ронять сам дашборд.
- `getAccessLogSummary_(ss)` - сводка, отсортирована по последнему входу (самые недавние
  первыми), отдаётся ТОЛЬКО роли `admin` вместе с основным ответом (`data.access_log`) -
  без отдельного round-trip, лист маленький и дешёвый для чтения.
- Фронтенд: карточка "👀 Активность сотрудников" на "Панели управления" - Имя/Роль/Заходов/
  Первый вход/Последний вход. Скрыта для не-admin и когда лог ещё пуст (только что раздали
  доступы - никто не заходил).

## Проверка

- Unit-тест на моке Google Sheets API (Node) - 3 визита одного email увеличивают счётчик до 3,
  "первый вход" не меняется, второй email создаёт отдельную строку.
- В браузере: карточка рендерится с тестовыми данными (2 сотрудника, разный счётчик/даты),
  корректно скрывается для роли не-admin и при пустом логе.
- Регрессия: остальной ответ `doGet()` не задет - логирование в try/catch, ошибка в нём не
  ломает основной ответ.

## Итог

- **Реализовано целиком:** да.
- **Что сделано:** см. "Реализация" выше.
- **Что не сделано и почему:** нет отдельного экрана истории всех визитов (только сводка
  "счётчик + первый/последний") - Влад просил именно счётчик, не полную историю; если
  понадобится подробный лог по датам - легко расширить, сохраняя текущую сводную таблицу.
- **Что добавить в бэклог:** нет.
- **Уроки:** "засчитывать визит только когда `action` пуст" - тот же признак "главная загрузка
  страницы, не мелкий доп-запрос", что уже использовался для похожих решений в этой сессии
  (например, для показа/скрытия `.page-header`) - удобный, уже проверенный приём для отличения
  "открыл страницу" от "внутренний AJAX-вызов".
