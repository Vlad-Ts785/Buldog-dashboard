### 3.1 Менеджер - «Мои заявки»

**Список.** День-вкладки остаются (5 лет ментальной модели), сверху лента «Сегодня /
Завтра / Неделя» + поиск по заказчику через все дни (в листе такого не было - «покажи все
заявки ДиМ за 3 месяца»). Колонки дня в этом порядке: **время подачи · тип техники · заказчик
· А -> Б (коротко) · машина/водитель · статус · стоимость**; наём - пометкой в «машине», не
колонкой; итог по дню снизу. Ячейка «машина» никогда не пустая: «машину ещё не поставили» /
«принял Кан» / «Кан поставил 12:40 · К123АА · Иванов». Новая заявка после сохранения
видна в списке МГНОВЕННО с номером (оптимистичная вставка, как уже сделано в v1).

**Карточка** (шторка - канон канбана): всё остальное (груз, контакты по точкам, документы,
переработка, примечание, оплата), история («Кан поставил машину 12 мин назад»), две кнопки
на расстоянии одного клика: «Копировать данные на пропуск», «Копировать заявку для
водителя» (WhatsApp-формат, бывшая формула колонки N).

**Форма - порядок как диктует заказчик:** дата (кнопки «Сегодня/Завтра» + календарь) ->
время (`700` -> 07:00; ряд 07:00 / 08:00 / 09:00 / 10:00 - 80% подач; «Уточнить» = пусто,
не 00:00) -> тип техники (три кнопки Трал / Длинномер / Панелевоз + список остальных) ->
заказчик (автокомплит «начинается с», есть) -> груз -> адрес погрузки -> адрес выгрузки ->
стоимость (цифровая) -> габарит -> контакты на точках -> документы, переработка, примечание,
наличные - последними.

**Обязательно для сохранения: дата, тип техники, заказчик.** Всё остальное - потом.
Без времени/адреса/контакта заявка сохраняется с флагом **«под данные»** (`needs_data`,
тот же смысл, что у `plan_segs.needs_data`), подсвечивается, попадает в вечернее
напоминание. Блокировать сохранение из-за адреса нельзя (менеджер: «заказ уже принят
голосом, точку пришлют через час»; логист: «никаких "заполните адрес"»). Это убирает
мусор «уточняется» в адресах.

**Подсказки:** контакт заказчика - из истории этого заказчика списком с телефоном; **адреса
из истории заказчика** (его точки за 3 месяца по частоте - закрывает ~60% ввода адреса,
главное, чего сейчас нет); только потом - подсказки карты (раздел 5).

**«Повторить»** - от заказчика (последняя его заявка), не только от дня. Копирует: заказчика,
контакт, тип техники, груз, оба адреса с координатами, контакты точек, документы,
переработку, стоимость, габарит. Сбрасывает: дату, время, статус, примечание, наличные, всё
логистское. Режим **«на несколько дней»**: отметил 15/16/17 или «пн-пт» - создались N
заявок (сегодня это ручное копирование строки в 5 вкладок - «самое ненавистное действие
месяца»).

**Статусы (расширены по обоим отчётам):** три из листа - «Подтверждено» (заказчик
подтвердил, едем), «Отбой», «Не закрыто» (ещё нет подтверждения/данных) + **«Выполнено»**
(рейс закрыт, можно выставлять) - ставит менеджер или логист; **«Машина назначена»** -
производный, руками не ставится; «под данные» - ФЛАГ, ортогонален статусу (заявка может быть
подтверждённой и без данных). Оплата - отдельное поле `payment_status` (список из
«Справочника») - главные фильтры конца месяца: сумма по своим заявкам, что не оплачено, что
наличкой, что «не закрыто» с середины месяца.

### 3.2 Логист - «Заявки» (таблица дня)

**Таблица** - живая (поллинг 7 с), ВСЕ логисты видят ВСЕ заявки, отсортирована по времени
подачи, поставленные строки не «прыгают». Порядок колонок как в листе слева направо (логист
читает глазами, не заголовками): **№ · время · заказчик · тип техники · груз · габарит ·
откуда · куда · документы · цена · менеджер (код + телефон)** и только потом своя часть:
**машина · водитель · телефон · наёмник · счёт · статус**. Контакт на погрузке (имя +
телефон, клик = набор) - в строке, не только в карточке (главная причина звонков менеджеру).
Слова - ровно те же, что в листе («Отбой», «Не закрыто», «Под данные», «Трал», «Габарит»,
«+ТТН», «Наличные»). Цвета - как в листе: отбой = красная строка целиком, подтверждено -
зелёная метка, не закрыто - жёлтая; строка без машины отличается от строки с машиной через
всё окно. Нумерация внутри дня («третья за пятое»).

**Шапка дня:** счётчики «без машины: 7 · под данные: 3 · новые: 2» - считаются по ВСЕМУ
дню независимо от фильтров, клик = отфильтрованный список (это же режим «Проверка дня»
вечером). Фильтры: тип техники / без машины / под данные / наёмка / мои взятые / «мой
сегмент» (запоминается, по умолчанию - мой; «Все» в один клик). **Новая заявка показывается
всегда, даже вне фильтра**, с меткой «новая» и звуком-точкой - «если я не заметил новую
заявку - это самая дорогая моя ошибка». Переключатель дат вперёд без потери фильтров, на
кнопке даты - «завтра: 4 заявки, 1 без машины».

**Колонка «Машина» - три состояния:** пусто (никто не взял) / «свой - Кан» / «наёмка - Прус».
**«Беру в работу» одним кликом** - строка сразу помечена моим кодом у всех (сегодня двое
логистов регулярно звонят по одной заявке двум перевозчикам - «самая частая потеря дня»).
Вернуть заявку обратно (машина освободилась) - тем же кликом, второй логист это видит до
того, как договорился по ставке.

**Постановка машины - РОВНО 2 клика:** клик по ячейке -> клик по машине в пикере. Никаких
подтверждающих шторок (30-50 постановок в день). Ошибся - тост «Отменить» 6 с (канон
разд. 8) или «Снять» тут же. Пикер (паттерн plan-m 4.5, адаптирован под десктоп): поиск по
3 цифрам номера и фамилии; секции строго: 1) свободные моего типа техники, 2) свободные
другого типа, 3) занятые - с текстом «занята до 13:00, Иванов, Тюмень» и **всё равно
доступны** (две подачи в день - норма), 4) ремонт / нет водителя / выходной - серым внизу,
но не скрыты. В строке пикера: госномер крупно · тип · водитель · прицеп · «до какого часа».
Поставил - в ячейке «К123АА · Иванов», на ленте отрезок сам, менеджеру Telegram. Клик по
стоящей машине - тот же пикер: сверху текущая с «Снять», пункт «Добавить вторую машину»
(заявка на 2-3 машины - все в столбик, каждую снять отдельно, пропуск менеджеру на всех).
Снял последнюю - строка обратно в «без машины» + уведомление менеджеру («иначе он поедет
с чужим пропуском»).

**«Наёмник ->» - пункт первого уровня в пикере** (наёмка - половина объёма в пик): компания
(справочник перевозчиков с поиском + «новая» на лету + **право вписать одной строкой, если
горит**) · контакт у перевозчика · госномер тягача · госномер прицепа · водитель + телефон ·
**ставка закупки** · форма расчёта (нал / б/н / НДС / отсрочка) · статус перевозчика
(договариваюсь / подтвердил / выехал / на погрузке / отказался / не приехал) · «заявка
перевозчику отправлена» (галочка + время). Маржа = цена менеджера - закупка, показывается
логисту наёмки, руководителю логистики, директору - **менеджеру НЕ показывается**
(раздел 12, вопрос 1). Заявка может быть закрыта частично своим парком, частично наёмником,
или двумя наёмниками - исполнителей у заявки СПИСОК (раздел 4), заявка закрыта, когда
закрыты все единицы.

**Обратный поиск (нет в листе, 3-5 раз в день):** тап по госномеру / фамилии водителя ->
«все заявки этой машины / этого водителя вперёд» (сегодня, завтра, дальше) - поломка и
выходной разбираются в одном списке, замена машины по каждой заявке не выходя в ленту.

**Система предупреждает, но не запрещает** (общее требование обоих логистов): занятую
машину ставить можно; при «Отбое» машину НЕ снимать автоматом - строка краснеет и
всплывает «Отбой по заявке №4 - К123АА освободилась. Снять с ленты?» с кнопкой; красное
предупреждение только при реальном наложении по часам; поле «логист» не переписывается на
того, кто просто поправил время.

**Изменения от менеджера после постановки** (5-6 раз в день): «время изменено 08:00 ->
14:00, заявка №3, машина стоит» + кнопка «Подвинуть рейс на ленте» - молча не двигать (у
машины может быть второй рейс).

**Живая совместная работа:** метка с фамилией на строке, которую кто-то открыл/правит
(присутствие, как в Планировке); чужая постановка - строка обновилась + «Кан поставил
К123АА, 12 с назад» без модалок; если я держал пикер на этой строке - «Кан уже поставил.
Показать / Поставить свою поверх» - решает человек. Последний осознанный клик побеждает, но
обе версии в истории строки.

**Перевозчик отказался** - кнопка: компания и причина в историю заявки и в счётчик отказов
справочника, поля машины очищаются (не стираются из истории), заявка **возвращается в
список красной**, менеджеру «машина снята, ищем замену», логисты своего парка снова её
видят. Ловушки на v1: «перевозчик прислал другую машину» (пропуск на старый госномер -
уведомление менеджеру о замене), «заказчик отменил, а наёмник выехал» (зафиксировать
холостой пробег и сумму).

**Планировка** остаётся как есть: созданный из заявки отрезок можно двигать/растягивать на
ленте, изменения отражаются на заявке (одна запись `plan_segs`, два представления).

### 3.3 Телефон (`plan-m`) - НЕ Фаза 5, а к 20.09 (требование логиста наёмки и менеджера)

## 4. Модель данных (сервер, MySQL, ручной SQL-скрипт - конвенция сервера)

**`plan_orders`** - заявка менеджера (строка = ОДНА запись; пара строк листа - костыль
таблицы, не переносится). Поля - 1:1 из живого Google-листа плюс координаты и служебные:

| Группа | Поля |
|---|---|
| Идентичность | `id` (PK, auto), `service_date` DATE, `day_no` (номер внутри дня), `created_by`, `created_at`, `updated_by`, `updated_at`, `deleted_at` (мягкое удаление) |
| Менеджер | `manager_name`, `customer` + `customer_key` (контрагент 1С/CRM, nullable), `customer_contact_name`, `customer_contact_phone` (ПДн - по роли) |
| Груз | `equipment_type` (Трал/Длинномер/Панелевоз/Тент/Любая модификация), `cargo`, `cargo_weight_t`, `cargo_dims` (Д×Ш×В, текст), `gabarit` (Габарит/Негабарит), `rework_terms`, `documents` (Путевой лист / +ТТН), `note`, `cash` флаг |
| Точки | `load_address`, `load_lat`, `load_lon`, `load_confirmed` (адрес из подсказок/координат = 1, «ориентир текстом» = 0), `load_contact_name`, `load_contact_phone`; то же для `unload_*` |
| Время | `service_time` (TIME, NULL = «уточнить») |
| Деньги | `price` DECIMAL (продажа), `payment_status` (список из «Справочника») |
| Статус | `status` ENUM `new` / `confirmed` / `cancelled` / `not_closed` / `done`; `needs_data` флаг (авто, если нет времени/адреса/контакта - снимается руками или при заполнении); `assigned` - НЕ колонка, производное от исполнителей |
| Кто ведёт | `taken_by` (код логиста), `taken_kind` (`own` / `hired`), `taken_at` - «беру в работу» |
| История | `plan_orders_history` - полный снимок строки перед любым overwrite/delete (приём, спасший заявку «894» 30.08) |

**`plan_order_executors`** - СПИСОК исполнителей заявки (одна заявка -> N машин, свой парк и
наёмка вперемешку): `id`, `order_id`, `kind` (`own` / `hired`), `seg_id` (для `own` - ссылка
на `plan_segs`, водитель/прицеп берутся из `fleet_assignments` на момент рейса), для `hired`:
`carrier_id` (nullable - «вписал одной строкой»), `carrier_name`, `carrier_contact`,
`tractor_gos`, `trailer_gos`, `driver_name`, `driver_phone`, `purchase_rate` DECIMAL,
`settlement` (нал / б/н / НДС / отсрочка), `carrier_status` ENUM (negotiating / confirmed /
departed / loading / refused / no_show), `sent_at`, `comment`, `found_by` (`logist` /
`manager` - «менеджер сам нашёл наёмника»), `created_by`, `created_at`, `updated_*`.
`plan_segs.order_id` (nullable, индекс) - добавляется; ничего существующего в `plan_segs` не
меняется (контракт `/api/plan/segs` потребляют два клиента - память
`project_plan_segs_fleet_state_shared_contract`).

**`plan_carriers`** - справочник перевозчиков (переезд листа «Наемники», в v1 - иначе «умрёт
на второй вкладке»): `id`, `name`, `inn`, `contacts` (JSON: имя, телефон, WhatsApp, роль),
`equipment` (JSON: тип, оси, г/п, длина площадки, низкорамник, регион), `settlement`, `vat`,
`region`, `blacklisted` + `blacklist_reason` + `blacklist_at`, `notes`, `created_*`. Последние
ставки / отказы / срывы - НЕ поля, а выборка из `plan_order_executors` (история сама себя
считает). «Доступность» перевозчика не изображаем - «любая такая цифра будет враньём».

**Права (раздел 12, вопрос 1):** `purchase_rate` и маржа - видят роль `logist` (наёмка),
руководитель логистики, `admin`; менеджеру сервер это поле не отдаёт вообще (не «скрыть на
клиенте»).

## 5. Умный ввод адресов

Влад 10.09: остаёмся на бесплатном OSM. Значит качество добираем в бесплатном контуре:
- **серверный прокси** `GET /api/geo/suggest?q=` / `/api/geo/geocode` - один общий для
  заявок И калькулятора (чиним обе точки разом), кэш повторных адресов, лимиты Nominatim
  (1 запрос/с, User-Agent);
- **цепочка** Photon (komoot, лучше переносит опечатки) -> Nominatim; нормализация под РФ
  («г.», «обл.», «р-н», регион по умолчанию Москва/МО);
- **три пути в одном поле** (менеджер): подсказка -> взял; вставил ссылку Яндекс/Google-карт
  или «55.75, 37.62» -> распарсили, точка есть; ничего нет -> сохраняю как «ориентир»
  текстом, `*_confirmed=0`, логист это видит. Сохранение из-за адреса не блокируется;
- **адреса из истории заказчика** - первый уровень подсказок, ДО карты (раздел 3.1);
- переключение на платный провайдер меняет только прокси, экраны не трогаются.

Задел (Влад, «идеи вслух», НЕ в этом плане): адреса + тип техники + цена -> автосверка с
прайсом (`.business/products/pricing.md`).

## 9. Производительность и живость - требования персон, измеримые

- Постановка машины: клик -> машина в ячейке **<= 1 с** («если думает дольше секунды - к
  обеду все вернутся в лист»); заявка целиком **< 1 мин**, сохранение мгновенно.
- Новая заявка видна логисту **<= 7 с** (поллинг), менеджеру - мгновенно (оптимистично).
- Работа без потери ввода при плохой связи: «не отправлено · повторить», не молчание (как
  `plan-m`: `apiGet_` с повтором, `sendBeacon` на `pagehide`).
- Ни одной модалки на частом действии (постановка, статус); диалог подтверждения (канон
  разд. 4) - только для редкого и дорогого (снять машину с уехавшей заявки).

## 10. Риски

- **10 дней** - реально только при v1 из раздела 8 и превью, утверждённом за день. «Идеи
  вслух» - в бэклог сразу.

  20.09, двусторонние уведомления). Если не успеваем к 19.09 - режем в таком порядке:
  полная карточка перевозчика -> «повторить на N дней» -> вечерние напоминания. НЕ режем:
  2 клика, «беру в работу», «под данные» без блокировки, импорт сентября, пропуск+Telegram.
- **`files/index.html` 29 тыс. строк, параллельные сессии** - экраны заменяют вкладку

- **ПДн** (контакты, водители, паспорт на пропуск) - только через сервер по роли; закупочная
  ставка - сервер не отдаёт менеджеру.

  живыми токенами по SSH; скриншот - финальная сверка.

## 12. Открытые вопросы к Владу (после персон)
