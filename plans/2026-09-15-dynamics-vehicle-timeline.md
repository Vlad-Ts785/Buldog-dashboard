# Динамика: лента жизни машины + деньги (гибрид A+B)

Дата: 2026-09-15. Ветка: `claude/interactive-machine-visualization-004437`.
Решение Влада 15.09: берём **гибрид A+B** и **переливаем историю статусов из Штатки на сервер**.

## Зачем

Страница «Динамика» сейчас показывает четыре числа на машину (в работе / ремонт / без заказа /
без водителя) и общий график тенденции. По ней нельзя посмотреть на машину и понять, КАК она
прожила период: когда встала, сколько простояла подряд, приносила ли деньги в рабочие дни.
Нужна визуальная картина «день за днём» плюс деньги рядом.

## Что утверждено (превью = контракт)

Три превью на реальных данных (16 машин, 01.06-15.09, ни одной выдуманной цифры):
- `examples/preview-dynamics-a-lenta-parka.html` - лента парка (эволюция текущей таблицы)
- `examples/preview-dynamics-b-pasport-mashiny.html` - паспорт одной машины
- `examples/preview-dynamics-c-matrica-prostoya.html` - матрица простоя (не берём, оставляем как
  источник идей: цена простоя, спарклайны справа, сортировка перестановкой)

**Гибрид**: экран A - основной (лента парка, сортировка, фильтры, полоса дня). Клик по машине
открывает паспорт из B (календарь-heatmap, подневные деньги с фоном статуса, водопад
выручка→ФОТ→топливо→запчасти→ВП, bullet план/факт).

Перед реализацией собирается ОДИН файл гибридного превью и утверждается Владом - иначе контракта
нет, а частичный перенос двух превью запрещён ГОСТом (раздел 0, п.6).

## Ограничения данных (выяснено разведкой 15.09, не обходить молча)

1. **Подневной валовой прибыли не существует.** Топливо и запчасти приходят от 1С только месячной
   строкой (`park_reports`). По дням есть: выручка и прибыль заказа (`orders_normalized` /
   `orders_archive`, госномер разбирается из поля `machine` через `normalizeGosServer_`), оплата
   водителю (`driver_payroll_trips`, только с 01.08), проходные (`avtodor_transactions`).
   В UI день и месяц обязаны быть разведены подписями: «выручка за день» против «ВП за месяц, 1С».
2. ~~**Статусы по дням (`vehicle_status_daily`) ведутся с 30.08.2026** - 16 дней из 107.~~
   **Снято 15.09 Фазой 1**: история из Штатки перелита, теперь 23.06-14.09 (84 дня) на
   сервере, `/api/vehicle_status_history` отдаёт всё одним куском, подмешивать Apps Script
   больше не нужно. Остаток: до 23.06 истории нет нигде.
3. **`plan` в 1С задан по выручке, не по ВП.** Bullet «план/факт по ВП» построить не из чего;
   подписывать честно «план по выручке», пока план по ВП не заведён отдельным полем.
4. Июль и август лежат И в `orders_archive`, И в `orders_normalized` с одинаковыми суммами -
   двойной счёт при склейке. Граница: по 30.06 - archive, с 01.07 - normalized.
5. Прибыль за январь-май недостоверна (`data_quality_warning`) - только выручка.
6. Машины с непустым `sprav_assets.department` исключены из всех расчётов парка.

### Фаза 3. Перенос в живой дашборд (идёт)

**Контракт данных (зафиксирован 15.09, собирается ровно как датасет превью):**
`GET /api/vehicle_timeline?from=YYYY-MM-DD&to=YYYY-MM-DD`, сессия admin (`checkSession`), ответ:
```
{ generated_at, range:{from,to},
  coverage:{ status_from, status_to, pay_from, pay_to },   // чтобы фронт честно писал «нет данных»
  vehicles:[ { gos, type, marka, plan,
               days:   { "2026-09-01": { st, src, rev, prof, pay, toll } },
               months: { "2026-08": { revenue, fot, fuel, parts, fines, tolls, profit, plan } } } ] }
```
`st` = work|repair|no_order|no_driver, `src` = shtatka|plan_segs. День без статуса в `days` не
попадает вовсе (фронт рисует «нет данных»), день только с деньгами - попадает без `st`/`src`.

  фолбэком при недоступности `/api/vehicle_timeline`, как во всём остальном переезде.

- Брейкпоинты плиток сдвинуты на ширину хрома (220px сайдбара + отступы): 1240/1100/720 ->

**Найдено и починено живым замером (в превью эти дефекты есть):**
- Полоса подсветки колонки вставала на 14px правее своего дня: `offsetLeft` считается от
  бордер-бокса `.dv-inner`, а абсолютный слой - от паддинг-бокса. Вычитается `padding-left`,
  сверено на 4 позициях и 3 значениях горизонтального скролла - сдвиг 0
- Лента шире экрана «протекала» наружу через `min-width:auto` и давала горизонтальный скролл
  ВСЕЙ страницы (тот же класс бага, что на «Планировке»): добавлено
  `main:has(> #page-dynamics.active),.main-wrap:has(#page-dynamics.active){min-width:0}`
- Полные рубли в плитке паспорта обрезались многоточием вместо шага вниз по шкале: `dvFitNum_`
  теперь шагает вниз ПО ФАКТУ замера, прикидка по длине строки осталась запасным путём

**Фолбэк и честность (по замечанию серверной сессии, 15.09):** новый путь и старый отдают
РАЗНЫЙ состав парка - `/api/vehicle_timeline` режет по `sprav_assets.department` и по датам,
`/api/vehicle_status_history` не режет ничего. Период мы дожимаем сами (строки вне окна
отбрасываются), а «отдел» на клиенте узнать не у кого - он на том же сервере, который молчит.
Поэтому фолбэк не притворяется нормой: плашка называет число машин и говорит, что состав шире
обычного и итоги НЕ обязаны сходиться с Панелью; точка свежести становится янтарной и
подписывается «резервный источник»; все деньги - прочерк («нет данных», не ноль). Текст ошибки
сервера (400 на кривых датах, 401/403) показывается пользователем, а не глотается. Границы
покрытия берутся из `coverage` ответа, а не считаются по выборке - иначе «в этот день ноль» и
«источника за эти даты нет» неразличимы.
