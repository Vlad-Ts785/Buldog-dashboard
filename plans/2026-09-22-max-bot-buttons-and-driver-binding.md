# Бот MAX «Спайк»: кнопки в сообщениях, привязка водителей по телефону, личные путевые

Дата: 2026-09-22. Влад: «внедряй» на четыре пункта из мозгового штурма
(см. память `project_max_messenger_bot`, план `plans/2026-09-11-max-messenger-bot.md`).

## Зачем

Бот до этого дня почти полностью текстовый и односторонний: человек набирает команду,
бот отвечает текстом. Кнопки использованы один раз (брони под обратку, параллельная
сессия 22.09). Люди ничего не могут ответить боту, кроме команд, а водители вообще не
привязаны лично - напоминания уходят в группы на 49 человек.

## Что делаем (4 фичи, одной волной)

### 1. Ремонт: «Взял / Готово / Причина» - статус обратно в Планировку
- `notifyRepairSet()` шлёт уведомление С КНОПКАМИ: `🔧 Взял в работу`, `✅ Готово`, `📝 Причина`.
  payload `rep:take:<seg_id>` / `rep:done:<seg_id>` / `rep:reason:<seg_id>`.
- `plan_segs` + 3 колонки: `repair_status` (`in_progress` | `done`), `repair_status_by`,
  `repair_status_at` (UTC, отдаётся ISO+Z, см. CLAUDE.md «Время»).
- «Взял» - ставит `in_progress`, кто и когда. «Готово» - ставит `done` и УКОРАЧИВАЕТ
  отрезок до текущего момента (машина в Планировке становится свободной сразу), снимок
  строки - в `plan_segs_history` как `overwrite` (защита №3, `overwritten_by =
  max-bot:<имя>`). «Причина» - второе сообщение с кнопками-категориями (двигатель,
  ходовая, гидравлика, электрика, прицеп, шины, ТО, другое); «другое» - бот ждёт
  следующий текст этого человека в этом чате (`max_pending`, 10 минут).
- Сообщение с кнопками редактируется через `POST /answers {message}` - в тексте
  появляется строка статуса, отработавшие кнопки исчезают.
- Кто может жать: любой участник группы механиков (тот же принцип, что у `/ремонт` -
  Влад 16.09 «оставить открытым»), имя пишется из привязки или из профиля MAX.
- Планировка: `/api/plan/segs` отдаёт новые поля; подпись плитки (`segLabel`) -
  «Ремонт · причина · в работе (Велиев)» / «· готово»; шторка отрезка - строка
  «Механик»; страница механика - тот же статус в колонке причины; `plan-m.html` - подпись.
- При смене kind на repair/maint заново (`repairJustSet`) статус сбрасывается.

### 2. Путевые листы: привязка по телефону, личные напоминания, «Сдал», фото
- Привязка: кнопка `request_contact` («📱 Поделиться номером») - в `/помощь` для
  непривязанных и по команде `/привязать`. Приходит вложение `contact` с `vcf_info` и
  `hash`; проверяем HMAC-SHA256 токеном бота (документация dev.max.ru), телефон
  сверяем с `sprav_people.phone` по последним 10 цифрам среди действующих водителей.
  Совпало - `max_chats.person_id`, `linked_at`. Email/роль не трогаем (водитель -
  не офисный пользователь).
- Личное напоминание: в том же кроне пн/ср после групповых - каждому привязанному
  водителю с долгами свой список рейсов (дата, заказчик, адрес коротко) и кнопки
  `✅ Сдал · <дата> <заказчик>` (`wb:done:<order_id>`) + «Сдал все». Список -
  `computeNoWaybillAged_` (тот же расчёт, что раздел на странице) - дополнен
  списком заказов на водителя (`orders-calc.js`, `opts.withNoWaybillOrders`,
  аддитивно, только по флагу).
- Команда `/путевые` - водитель сам смотрит свой список в любой момент.
- «Сдал» пишется в `waybill_claims` (месяц, номер заказа, person_id, кто/когда, chat).
  Это ЗАЯВЛЕНИЕ водителя, не факт из 1С: источник истины `has_waybill` не меняется.
- Фото в диалоге от привязанного водителя: скачиваем по `payload.url` (лимит 8 МБ,
  JPG/PNG/WEBP), кладём в `uploads/waybill_photos/`, спрашиваем «к какому рейсу?»
  кнопками (если рейс один - цепляем сразу), запись - в ту же `waybill_claims`.
- Дашборд: `GET /api/waybill_claims?month=` (admin/manager/logist), `GET
  /api/waybill_claim_photo?id=`; в таблице «Не сданные путевые (свои)» - пометка
  «водитель отметил: сдал N · фото M» и ссылки на фото.

### 3. Помощь: клавиатура по роли вместо шторки
- `/помощь`, `/start`, `bot_started` - текст + inline-кнопки по ЖИВОЙ роли. Кнопки
  типа `callback` с payload `cmd:<команда>` - бот выполняет команду как будто её набрали
  (единый `handleCommand`). Менеджер - только его набор (Влад 14.09), непривязанный -
  ремонт + «Поделиться номером», водитель (person_id без email) - «Мои путевые»,
  «Поделиться номером».
- Команда без аргумента (например кнопка «/данные») - бот отвечает «напиши фамилию» и
  ЖДЁТ следующий текст (`max_pending`, 2 минуты) - не нужно набирать `/данные` второй раз.

### 4. Поиск по фамилии: несколько совпадений - кнопки
- `resolvePerson_` вернул `ambiguous` - вместо «уточни, кого именно» список кнопок
  с полными ФИО, payload `pick:<cmd>:<person_id>`. Нажатие - повторная проверка
  роли/категории (та же `resolvePerson_` по id, `driversOnly` для не-admin), потом
  та же ветка, что и при однозначном совпадении (`runPersonCommand_`).
- То же для `/аренда <номер>` с несколькими машинами: `pickgos:<asset_id>`.

## Инфраструктура (общая для всех четырёх)
- Диспетчер `message_callback`: свой префикс - своя ветка, чужой payload - `null`
  (договорённость с сессией «БОТ», её `handleBookingCallback_` не трогаем).
- `max_pending (chat_id, user_id, action, payload JSON, expires_at)` - «бот ждёт от
  этого человека следующий текст». В группах бот по-прежнему молчит, КРОМЕ ответа на
  свой же ожидаемый вопрос (причина ремонта).
- `answerCallback_(callback_id, {notification, message})` - обёртка над `/answers`.
- SQL: `api/max-bot-buttons.sql` (миграция), выполняется руками один раз.
