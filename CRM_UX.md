# CRM_UX.md - ЯРД Hub CRM

**Дата:** 2026-08-27. Битрикс24 - функциональный ориентир (плотность, статусы, счётчики,
быстрые действия), НЕ визуальный (без фиолетового, без градиентов Битрикса).
Визуальный язык - существующая дизайн-система YARD Hub (`:root` в `files/index.html`
- `--bg`/`--bg2`/`--bg3`/`--bg4`, `--green`/`--red`/`--amber`/`--blue`/`--purple`,
`.card`/`.tab-btn`/`.kpi-*`).

## Режимы (переключатель сверху вкладки CRM)

`Сводка` (эта реализация) · `Канбан` (есть, дорабатывается) · `Чаты` (переделывается
полностью) · `Список` (Фаза 2) · `Клиенты` (Фаза 2 - возможно, переиспользовать
существующую вкладку "Клиенты" дашборда вместо новой) · `Аналитика` (Фаза 2)

Не делаем все 6 сразу - см. границы в `CRM_ARCHITECTURE.md`. В этой реализации:
Сводка + Канбан (дополнен) + Чаты (пересобраны).

## Сводка (новый блок над канбаном)

Три плашки в ряд (переиспользуем `.stamp`-подобный паттерн из уже существующей
дизайн-системы дашборда, `.kpi-grid`):
- Сумма и количество по каждой стадии воронки (компактно, не 7 отдельных плашек - one
  строка чисел под канбаном или прямо в заголовках колонок, которые УЖЕ показывают
  count - расширяем до count+сумма, где ещё не показана).
- Топ-3 причины отказа за текущий месяц, с количеством.
- "Недозвонов сегодня: N" - отдельно, ярко (это прямые потерянные деньги по вине
  нашей стороны, не клиента).

## Канбан (дорабатываемая карточка)

Сейчас: `avito:467952731` / `0 ₽` / `1 зв.` - имя = сырой ключ, нет груза/маршрута.

**Новая анатомия карточки** (плотность как в Битриксе, но по нашим полям):
```
┌───────────────────────────────┐
│ [канал] ООО «Стройтранс»       │  ← название/имя, канал-бейдж слева
│ Экскаватор · Москва → Тула     │  ← бриф груза (если извлечён/введён)
│ 32 т · 15 сентября             │  ← вес/дата, если известны
│ 180 000 ₽              [ЕФ]    │  ← сумма (жирным, зелёным) + аватар ответственного
│ "Сколько будет стоить..."      │  ← превью последнего сообщения (если есть чат)
│ 🟢 недавно         💬 📞       │  ← статус-точка + быстрые иконки действий
└───────────────────────────────┘
```
Поля показываются УСЛОВНО - если брифа нет (звонок без переписки, ничего не
извлечено), карточка деградирует до сегодняшнего вида (имя/сумма/аватар), не
показывает пустые строки. Плотность появляется там, где есть данные, не заранее.

Статус-точка (не дублирует стадию колонки - показывает СВЕЖЕСТЬ):
🟢 сегодня отвечали · 🟡 больше 2 часов без ответа (только если есть чат) · 🔴
зависла >48ч на стадии (SLA-бейдж, см. `CRM_ARCHITECTURE.md`).

Быстрые действия (иконки, останавливают всплытие клика по карточке):
💬 открыть чат (если есть переписка) · 📞 позвонить (`tel:` ссылка) · 📋 открыть
полную карточку сделки (текущая модалка - остаётся, становится "глубоким" режимом).

## Чаты (полная пересборка - три колонки)

```
┌──────────────────────────────────────────────────────────────────────┐
│ 💬 ЧАТЫ    [Все] [Новые] [Жду ответа] [Мои] [Без ответств.] [Фильтр▾] │
│ 🔍 Поиск по имени/телефону                                            │
├───────────────────┬──────────────────────────┬───────────────────────┤
│ СПИСОК (280px)     │ ПЕРЕПИСКА (гибкая)        │ КОНТЕКСТ (280px)      │
│                    │                            │                       │
│ 🟦 Авито      🔴2  │ ООО «Стройтранс»           │ КЛИЕНТ                │
│ ООО «Стройтранс»   │ +7 999 ...  · Авито         │ Имя, телефон, компания│
│ Сколько будет...   │ ────────────────────────  │ История заказов       │
│ 2 мин · ЕФ         │  [входящие слева, тёмный   │ (число, сумма, дата   │
│ ──────────────     │   пузырь]                  │ последнего - тянем из │
│ 🟦 Авито           │  [исходящие справа,        │ client_analytics)     │
│ Александр          │   зелёный пузырь]          │                       │
│ Уточнила маршрут    │                            │ ЗАЯВКА                │
│ 14:20 · Без ответ.  │                            │ Маршрут, груз, вес,   │
│                    │ ──────────────────────────  │ дата, техника (та же  │
│  +N диалогов...     │ [Написать сообщение...] [Отправить] │ форма, что в модалке  │
│                    │                            │ сделки - переиспольз.)│
│                    │                            │                       │
│                    │                            │ СДЕЛКА                │
│                    │                            │ Стадия, сумма,        │
│                    │                            │ ответственный         │
│                    │                            │                       │
│                    │                            │ БЫСТРЫЕ ДЕЙСТВИЯ      │
│                    │                            │ 📋 Открыть карточку   │
│                    │                            │ 📞 Позвонить          │
│                    │                            │ 👤 Назначить          │
└───────────────────┴──────────────────────────┴───────────────────────┘
```

**Строка списка чатов** (плотнее сегодняшней): канал-бейдж + имя/номер + превью
последнего сообщения (обрезано) + время + непрочитанные (красный кружок с числом,
если >0, поднимает диалог наверх списка) + инициалы ответственного. Активный -
подсвечен левой полосой (уже есть паттерн `.crm-chat-row.active`, сохраняем).

**Правая панель** - НЕ новая форма с нуля: поля "Заявка" - это те же
cargo/route/weight/date/vehicle поля из карточки сделки (переиспользуем разметку и
запрос сохранения), просто в контексте чата, не модалки. "Клиент" - мини-версия
клиентского профиля (переиспользуем `client_analytics` по номеру, как уже решено в
`CRM_ARCHITECTURE.md`).

**Фильтры** (видимые сразу, по фразе Влада "не 50 фильтров сразу - основные видны,
остальное за 'Фильтр'"):
Видимые: Все / Новые / Жду ответа / Мои / Без ответственного.
За кнопкой "Фильтр▾": канал (Авито/звонок), ответственный (конкретный, не только
"мои"), период, статус сделки, просроченные.

## Каналы - цвет в НАШЕЙ палитре, не битриксовской

Авито - `var(--blue)` (уже есть в палитре). Звонок - `var(--purple)` (аватар
ответственного уже фиолетовый - согласовано). Будущие каналы (WhatsApp/Telegram,
Фаза 2, не сейчас) получат свой оттенок из той же палитры (`--green`/`--amber`), не
заимствуют брендовые цвета мессенджеров - остаёмся в своей системе.

## Уведомления (дополняют push, не заменяют)

Пока открыта вкладка "Чаты" и опрос (10-15 сек, см. `CRM_ARCHITECTURE.md`) находит
новое сообщение - лёгкий тост внутри страницы (не браузерный `alert`, не блокирует)
+ звук (тот же, что уже проигрывает системное уведомление push - не дублируем
разными звуками) + обновление счётчика в шапке режима "Чаты". Настройка выключения
звука - переключатель рядом с уже существующей кнопкой "Включить уведомления"
(единое место управления оповещениями, не два разных).

## Состояния (согласовано с остальным дашбордом)

Загрузка/ошибка/пусто - тот же паттерн, что уже используется (`color:var(--muted)`
для пустых состояний, `color:var(--red)` для ошибок, без иконок в заголовках блоков
- см. `project_dashboard_icon_style` в памяти проекта, соблюдается и здесь).

## Критерий приёмки (сценарий Влада, дословно из его сообщения)

Влад открывает CRM утром → видит счётчики по стадиям сразу → жмёт "Чаты" → видит все
диалоги → открывает один → сразу понимает: кто клиент, что нужно, откуда/куда, груз,
вес, дата, сколько стоит, кто ответственный, что уже обсуждали → отвечает не открывая
пять окон → CRM сама обновляет состояние. Это и есть проверка "сделано", не список
выполненных пунктов.
