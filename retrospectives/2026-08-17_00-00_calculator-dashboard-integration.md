# Ретроспектива: Калькулятор → вкладка дашборда

Дата: 2026-08-17

## Что сделали

Проанализировали весь код проекта `ЯРД_Калькулятор_v1.3` (нашли, что README описывает
устаревшую v1.3, а реальный рабочий код - v1.7, с зонами сопровождения, Faymonville и
трал-корытом, которых в README нет - методику доставали из кода, не из документации).
Встроили калькулятор как вкладку «Калькулятор» в `files/index.html`, переоформив интерфейс
под нейтральную тёмную тему дашборда (переиспользованы существующие `.card`/`.tab-bar`/
`.grid-65`, а не скопирован навы/золото стиль оригинала). Расчётная логика перенесена без
изменения формул - только переименованы id/классы (префикс `clc-`) и код обёрнут в IIFE
(`window.Clc`), чтобы не засорять глобальное пространство 8800-строчного файла. Написали
методику расчёта в `.business/products/pricing.md` (была пустым шаблоном) - теперь любой
чат по дашборду может её прочитать, не разбирая код заново.

Детали и что именно проверено - `plans/2026-08-17-calculator-dashboard-integration.md`.

## Решения, принятые по ходу (спросили Влада)

1. История расчётов/лог КП - пока в `localStorage`, не переносим в Google Sheets (отдельная
   задача на будущее, если понадобится).
2. Доступ - всем менеджерам/логистам и директору, не только админ-панели (калькулятор не
   зависит от серверных данных).
3. Карта и авто-км (Leaflet+OSRM+Nominatim) - сохранены как в оригинале.

## Что вызвало затруднение

- Реальный код калькулятора (v1.7) обогнал собственный README - пришлось читать минифицированный
  JS построчно (переформатировал через `perl -pe`, чтобы читать), а не доверять документации.
- Перенос ~2000 строк плотного JS вручную через Edit был бы рискован (100+ позиций базы
  техники, кириллица, легко опечататься). Написал одноразовый Node-скрипт с точечными
  regex-заменами (id/классы/localStorage-ключи), прогнал `node --check` + собственные
  sanity-проверки "не осталось ли непрефиксованных id" - вместо ручной перепечатки.
- **Забыл добавить сам DOM-элемент `#clc-toast`** в разметку (перенёс только JS, а
  статический div для тоста придумывал заново и упустил) - поймал только при интерактивном
  тесте в браузере (`toast()` падал на `null.classList`). Раньше поймать это можно было бы
  чек-листом «на каждый `getElementById` в движке должен быть соответствующий элемент в
  разметке» - не делал такой сверки явно, повезло что баг всплыл сразу при первом клике по
  технике.
- CSS-коллизия, которую поймал ДО вставки, а не после: оригинальный калькулятор переопределял
  `.card`/`.btn` собственными правилами (навы/золото). Если бы просто скопировал CSS
  оригинала в общий `<style>` дашборда, это сломало бы `.card` НА ВСЕХ страницах дашборда
  (последнее CSS-правило в файле побеждает). Проверил заранее через grep, что дашборд уже
  использует `.card` глобально, и полностью выбросил CSS оригинала вместо переноса.

## Обучающая подсказка (по CLAUDE.md - расти вместе с работой)

Когда переносишь plain-JS движок между HTML-страницами и рискуешь опечататься в объёмных
данных (у нас - 100+ позиций техники с кириллицей) - не редактируй руками. Напиши маленький
одноразовый transform-скрипт (Node/Python), примени к оригиналу regex-заменами, прогони
`node --check` на выходе и грепни на "не осталось ли старых паттернов" ДО вставки в целевой
файл. Это тот же принцип, что «не редактировать сгенерированные файлы руками» - если процесс
переноса можно описать как набор точных правил, лучше закодировать правила и прогнать их,
чем вручную ретранскрибировать тысячу строк.
