# План: страница «Готовность парка» (для Феськова)

**Дата:** 2026-09-25
**Автор:** Клод по задаче Влада
**Статус:** ВЫКАЧЕНО 26.09 (VPS b52131d + сайт) - Феськову (роль fleet_head, галочка в матрице) и директору

## Цель

Руководитель автоколонн (Феськов) за минуту видит по каждой колонне (тралы, длинномеры, АМ
прикрытия): сколько машин всего, сколько завтра на линии, сколько в ремонте и сколько дней, сколько
без водителя - из них вакансий и по каким причинам остальные, сколько водителей не хватает; и одной
кнопкой копирует отчёт для Телеграма в формате вечернего отчёта собственнику.

## Задача словами Влада (25.09)

Первая постановка: «Дашборд по состоянию готовности автопарка к эксплуатации на завтра, включи эту
страницу только для Феськова. По колоннам тралов, длинномеров: количество техники в колонне; на
линии; в ремонте с указанием количества дней; без водителя с указанием количества дней;
отсутствующих водителей исходя из техники без водителя (1 машина = 1 человек). Таблица, каждая
колонна в отдельной строке. Сначала покажи, что получается. С этой страницы скопировать отчёт для
Телеграма, похоже на мой ежедневный отчёт.»

Правки после первого превью (тот же день):
- «Без заявки в этом отчёте не нужно указывать... это отчёт коммерческого отдела. Убери оттуда» -
  убрано и из текста, и со страницы.
- «Без водителя - сколько из них вакансий, сколько других причин? По тралам и по длинномерам» -
  в тексте под «Без Водителя» вакансия и каждая причина отдельной строкой; на странице подколонки
  «вакансий» / «другие причины» + список причин в развороте.
- «Эти ср. убери, средние непонятные, и с готовности парка вообще убери» - средних за 30 дней нет
  ни в тексте, ни на странице (из первой постановки снято самим Владом).

## Как это сделал бы архитектор (разбор до кода)

**Где живёт:** отдельный модуль страницы `files/fleet-readiness.js` + `.css` (как «Найм»), сервер -
`api/lib/fleet-readiness.js` + `GET /api/fleet_readiness`. В `index.html` - только пункт меню,
контейнер, подключение файлов и одна строка в `showPage` (не +500 строк в монолит).

**Откуда данные - ничего нового не заводим:** состав парка - `sprav_assets` (`fleet_scope='own'`,
«Отдел» пуст), тип и колонна - `vehicle_types_effective` (Борт -> длинномеры, Прикрытие -> АМ
прикрытия, остальное - тралы), статус дня - `plan_segs` (Планировка), водитель на машине на конец
дня - `fleet_assignments`, история до 31.08 для «сколько дней стоит» - `vehicle_status_daily`,
начальники колонн - `user_access` (column_head + fleet_segment), доступ - матрица «Доступ и роли».

**Варианты:**
- **А. Сервер считает всё одной функцией, страница рисует (выбрано).** Правило статуса - то же, что
  у вечернего отчёта собственнику: ремонт и «без водителя» на завтра совпадают с ним один в один
  (сверено 25.09 дважды). Текст для Телеграма собирает тоже сервер - его потом без переделки может
  слать бот.
- Б. Считать в браузере из `/api/plan/segs` + `/api/fleet/state`. Минус: третья копия одной
  категоризации (уже есть в Планировке и «Статусе парка»).
- В. Только бот-сообщение, без страницы. Минус: нет разбора по машинам.

**Какую палку здесь НЕ ставим:** фамилию Феськова в коде (доступ - галочка роли в матрице); расчёт
в браузере. Подписи причин «без водителя» пока лежат и в Планировке (`DRIVEROFF_REASONS_`), и в
серверном модуле - при выкате перенести на сервер рядом с `ALLOWED_REASONS`, Планировку потом
перевести на серверные подписи (одна копия).

## Определения (что значит каждая цифра)

- **Статус машины на день** (как в вечернем отчёте): ремонт/ТО -> без водителя (нет закреплённого
  ИЛИ отрезок «выходной/отпуск/...» в Планировке) -> на линии.
- **На линии** = машина исправна и с водителем, как «В работе» в шапке Планировки (правило 01.09).
  Есть ли на неё заявка - здесь не важно (это зона коммерческого отдела). В вечернем отчёте
  собственнику «В работе» - только машины с рейсом, там это число меньше на «Без заявки».
- **Без водителя** (Влад, 25.09, вариант 2 из двух) = ВСЕ машины, на которых завтра нет водителя:
  вакансия (водитель не закреплён - в том числе у машин, стоящих в ремонте) + каждая причина отрезка
  Планировки (выходной, отпуск, приёмка, больничный, тахограф, без пропуска, переоформление).
  Машина в ремонте без водителя считается и в «В ремонте», и в «Без водителя» - поэтому
  **всего = на линии + в ремонте + без водителя − (в ремонте без водителя)**; в тексте это
  подписано у вакансии: «(все в ремонте)» / «(из них в ремонте N)». Отвергнутый вариант 1 - машина
  только в одной строке (так считает вечерний отчёт: у длинномеров 25.09 там «Без Водителя: 3», а
  вакансия выходила 0, хотя на 3 машинах в ремонте водителя нет вовсе).
- **Дни** - в списке машин: сколько полных дней подряд машина в этом статусе. Вакансия - с конца
  последнего назначения водителя. «80+ дн.» - серия упирается в начало истории (не меньше).
- **Нет водителей, чел.** = машин без водителя (1 машина = 1 человек). **Вакансий** = сколько
  водителей нужно найти (строка под таблицей).
- **Готовность** = на линии / всего.
- **Средних за период нет** (снято Владом 25.09).

## Текст для Телеграма (26.09, Влад: госномера только у машин не в работе, без повторов)

## Найдено попутно (решение за Владом, на эту страницу уже не влияет)

Дневной снимок `vehicle_status_daily` (его читает «Динамика») ставит **рейс важнее ремонта**, а
вечерний отчёт - **ремонт важнее рейса**. Пересчёт 31.08-24.09: 64 из 1312 машино-дней расходятся
(36 - из-за разного приоритета: рейс+ремонт в один день, рейс+выходной; 28 - правки Планировки
задним числом после снимка). Правильно - одна функция статуса дня на всех (отчёт, снимок, эта
страница); какой приоритет верный - решает Влад.

## Критерии готовности

- [ ] Феськов видит страницу, никто кроме него (и директора) - нет, сервер отвечает 403
- [ ] Всего = на линии + ремонт + без водителя − (в ремонте без водителя) в каждой строке, колонны
      складываются в «Итого»
- [ ] Ремонт на завтра совпадает с вечерним отчётом; «без водителя» = его «Без Водителя» + машины в
      ремонте без водителя
- [ ] Кнопка копирует текст, в Телеграме он читается как вечерний отчёт
- [ ] Чек-лист ГОСТ (раздел 10) пройден, живая страница сверена с превью поблочно

## Риски

- **Мусор в назначениях водителей** - страница покажет то, что внесено в Справочники/Планировку.
  Лечится тем, что колонники правят своё (тот же риск, что в плане «Водители по машинам»).
- **Жирный и отступы при вставке** зависят от приложения Телеграма - если не держатся, остаётся
  обычный текст.
