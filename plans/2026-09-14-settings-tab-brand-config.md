# Вкладка «Настройки» - конфигурация бренда (первый шаг к white-label «коробке»)

**Статус:** в работе
**Одобрено:** Влад, 14.09 - продолжение разговора про защиту кода/лицензирование ПО. Цель -
чтобы название/логотип дашборда стали настройкой, а не строкой в коде (сейчас "ЯРД HUB" и
логотип-медведь прибиты гвоздями по `index.html`/статическим файлам - сегодня утром это уже
доставляло неудобства, когда переключали название туда-обратно). Модель - как «коробочная
версия» Bitrix: движок один и тот же, но конкретный покупатель разворачивает у себя копию и
настраивает бренд под себя. Полная white-label картина (мультиарендность, вынос бизнес-правил
типа зарплатных формул в настройки) - НЕ входит в эту задачу, отдельная, гораздо более крупная
работа на будущее.

## Архитектура (по образцу уже существующего `/api/menu_config`)

- **Таблица `dashboard_settings`** (VPS MySQL) - гибкое хранилище ключ-значение
  (`setting_key` PK, `setting_value` TEXT/JSON, `updated_by`, `updated_at`) - не только под
  бренд, задел на будущие настройки.
- **`GET /api/brand_config`** - **ПУБЛИЧНЫЙ, без сессии** (сознательно, не забытая дыра) -
  отдаёт ТОЛЬКО узкий белый список полей бренда (name/logoUrl/primaryColor), ничего
  чувствительного. Нужен публичный доступ, потому что название дашборда должно быть видно
  ДО входа - на экране логина и в `<title>` вкладки браузера.
- **`GET /api/settings`** - `checkSession` + `admin` - вся таблица целиком, для вкладки
  "Настройки".
- **`POST /api/settings/set`** - `checkSession` + `admin` - upsert одной или нескольких
  настроек (`ON DUPLICATE KEY UPDATE`, тот же приём, что `menu_configs`).

## Фазы

### Фаза 1. Сервер
- [ ] Таблица `dashboard_settings` на VPS.
- [ ] Три эндпоинта выше в `api/server.js`.
- [ ] Дефолты "как сейчас" - если настройка не задана, `/api/brand_config` отдаёт
      `{ name: "ЯРД HUB", logoUrl: null, primaryColor: "#1D9E75" }` - ничего не меняется
      визуально, пока Влад явно не поменяет через вкладку.

### Фаза 2. Клиент - вкладка "Настройки"
- [ ] Пункт меню сайдбара "Настройки" - **только для admin** (как большинство
      административных разделов).
- [ ] Простая форма: название бренда (текст), URL логотипа (текст - без загрузки файла в
      этой итерации, проще и достаточно для начала), основной цвет (color picker).
- [ ] Сохранение через `POST /api/settings/set`.

### Фаза 3. Клиент - подключение к уже существующим местам
- [ ] При загрузке дашборда (`loadData()`/ранняя инициализация, ДО экрана логина) - запрос
      к `/api/brand_config` (без сессии, публичный).
- [ ] Заменить хардкод "ЯРД HUB"/"ЯРД" в: `<title>`, тексте сайдбара, тексте экрана входа -
      подставлять значение из конфига (с тем же дефолтом "ЯРД HUB", если не задано).
- [ ] Favicon/`manifest.json` - **НЕ трогаем в этой фазе** (это статические файлы, полноценная
      динамическая подмена сложнее - для модели "своя коробка на своём сервере" достаточно
      сгенерировать их один раз при разворачивании нового экземпляра, не обязательно "на
      лету"). Зафиксировать как осознанно отложенное, не забытое.
