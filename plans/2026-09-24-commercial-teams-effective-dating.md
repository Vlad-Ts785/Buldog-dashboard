# Команды продаж с датами + новый руководитель группы автоматически (этап 4.2б)

**Статус:** СДЕЛАНО 24.09 (VPS 42678fd + сайт). Родитель - `plans/2026-09-23-access-roles-in-spravochniki.md` (этап 4.2б).

## Решения Влада (24.09)

- «Условия руководителей групп одинаковые» - новый руководитель (роль `sales_head` в «Доступ и
  роли») автоматически получает тот же пакет, что Ахтамова/Гусейнова: оклад 20 тыс. + 0,8% +
  2% с найма + премия за укомплектованность + премия за объём (`calcHead_`, `calcVolumeBonus`).
- Зарплата за любой месяц - по составу команд и руководителям ТОГО месяца («с датами»).

## Как это сделал бы профессиональный архитектор

**Проблема.** Состав команд (`sprav_people.commercial_head`) и роль руководителя хранятся без
дат - «кто у кого сейчас». Вкладка «Зарплата» за прошлый месяц считает по текущему составу:
после перестановки прошлые месяцы молча пересчитываются (новый руководитель получает долю задним
числом, у старого пропадают переведённые менеджеры). `sprav_audit_log` пишет только факт правки,
без значений - прошлое не восстановить, история начинается с момента внедрения.

**Термин:** *effective dating* (атрибут с датой начала действия) - вместо «значение сейчас»
хранится ряд «значение с такой-то даты», ответ на «как было в месяце X» - последняя запись не
позже X. Тот же механизм нужен для «машина в отделе с даты» (дорожная карта, 2.4а).

**Варианты:**
1. Таблица истории + расчёт «на месяц» на сервере, сайт спрашивает состав нужного месяца.
   Плюс - один источник, работает для всех потребителей (зарплата, «По менеджерам», личная
   страница руководителя). Минус - больше кода. **Рекомендую.**
2. Снимок состава при закрытии месяца. Минус - текущий месяц всё равно без истории, ещё один
   крон-«снимок» (класс бага `_archive`, который не пополняется сам).
3. Ручная дата в форме на каждую перестановку. Минус - лишний шаг для людей, ошибки ввода.

**Правило даты - простое и объяснимое:** перестановка действует с месяца, в котором её внесли
(МСК). Назначили 1 октября - октябрь по-новому, сентябрь по-старому. Внесли 15 октября - тоже
весь октябрь по-новому (зарплата помесячная, дробить месяц не нужно).

**Что НЕ делаем (палки, которые профессионал не поставил бы):** не копируем список голов на
фронт (сайт спрашивает сервер); не пишем историю в двух местах (единственный писатель поля -
`/api/sprav/person`, история - в той же транзакции); не заводим вторую палитру (новый цвет
отдела - из утверждённой `AVATAR_PALETTE_`, ГОСТ 2.12, вынесена в общую константу).

## Шаги

### Сервер (VPS)
- [x] Миграция `sprav_people_team_history (person_id, valid_from DATE, commercial_head, changed_by,
      changed_at)`, уникальный `(person_id, valid_from)`. Засев: текущие значения с
      `valid_from='2000-01-01'` (= «так было всегда» - до сегодня перестановок с датами не было).
- [x] `/api/sprav/person`: в той же транзакции прочитать прежнее `commercial_head` (FOR UPDATE),
      при изменении - upsert строки истории на первое число текущего месяца МСК.
- [x] История руководителей - из `access_audit` (seed = всегда; grant/role/revoke/restore/edit -
      с месяца события, время в БД UTC -> месяц МСК).
- [x] Чистая функция `commercialTeamsAsOf_(period)` (в памяти, данные подгружаются тем же
      `refreshCommercialHeadTeams_`), `COMMERCIAL_HEAD_TEAMS_` = состав на текущий месяц.
- [x] `GET /api/commercial_head_teams?period=YYYY-MM` - `{ teams, current_heads, heads: {фамилия:
      {name, female}} }`; без `period` - как раньше.
- [x] `buildManagerPayload_` - команда руководителя на месяц `orders.period`.

### Сайт
- [x] `ensureCommercialHeadTeams_` - по месяцу `D.orders.period`, кэш по месяцу; `DEPT_CFG` и
      `COMMERCIAL_DEPTS` перестраиваются ПО МЕСТУ (объекты отделов - из реестра, адреса стабильны):
      отделы руководителей этого месяца, новые - автоматически (цвет из палитры, «Отдел <фамилия
      в род. падеже>»), Рыщанов/Ратников не трогаются.
- [x] Текущие руководители (не месяц просмотра): `COMMERCIAL_HEAD_SUR_FRONT_`, список в карточке
      сотрудника (Справочники), «План поступлений», подпись должности.
- [x] Подсказка под выбором команды в карточке сотрудника: «Перевод действует с текущего месяца».

   зарплатная карточка строится тем же `renderCommercialDeptCardHtml_`.

## Итог проверки (24.09)
- Сервер: 10 сценариев модуля прошли (`node api/lib/commercial-teams.test.js`); живьём до/после -
  всё байт в байт (состав сейчас и на 07/08/09, меню, план поступлений, суды, main_payload
  руководителей, пробная рассылка); SQL истории - на живой базе в транзакции с откатом.
- Сайт (подставные данные): на реальном составе DEPT_CFG/COMMERCIAL_DEPTS совпали со старым
  алгоритмом поле в поле, объекты отделов те же; «Гуцу руководитель с октября» - в октябре свой
  отдел («Отдел Гуцу», цвет из палитры, тот же пакет: 20т + 0,8% + 2%), в сентябре её нет, Савиток
  и Гуцу в команде Гусейновой, после отрисовки сентября всё возвращается к октябрю; список в
  карточке сотрудника - текущие руководители (Рыщанов больше не предлагается, чужая ссылка не
  сбрасывается молча); мобильные страницы читают список из хранилища браузера.
- Выбор месяца на сайте не перезагружает данные (D.orders подменяется на время отрисовки в
  renderSalesTabsForPeriod/renderMyPage) - отделы подменяются тем же приёмом
  (commercialTeamsEnter_/Exit_), состав месяца догружается и перерисовывает страницу.
