# План: перенос ИИ-задач (kie.ai) с Apps Script на сервер

**Дата:** 2026-09-07. **Запросил:** Влад, тем же вечером, что чинили модель kie.ai
(`gpt-5-4` -> `gpt-5.6-luna`, см. `scripts/DEPLOY_LOG.md`): "А ну и у нас я так понял вся
движуха через скрипт идёт, нужно сделать через сервер" - продолжение общей стратегии
проекта (см. `CLAUDE.md`, "ГЛОБАЛЬНО переходим на работу с сервера, не с Google Таблиц").

## Что переносим

Генерация блока "🤖 Задачи на сегодня (ИИ)" на личных страницах - сейчас ПОЛНОСТЬЮ в
Apps Script (`doGet`, `action=generate_ai_tasks`, `scripts/full_script_final.js:5741`):
сбор контекста -> сборка промпта -> вызов kie.ai -> разбор ответа -> кэш на день (лист
"ИИ_Задачи" в Google Таблице). Касается ЧЕТЫРЁХ ролей, каждая со своим контекстом и
промптом (см. функции ниже) - НЕ путать с самими цифрами заказов/ДЗ, которые эти функции
используют как ВХОД (те уже на сервере, см. таблицу ниже).

| Роль | Контекст | Промпт |
|---|---|---|
| manager (обычный менеджер) | `buildManagerAiContext_` (:10455) | `buildAiTasksPrompt_` (:10569) |
| logist | `buildLogistAiContext_` (:10690) | `buildLogistAiTasksPrompt_` (:10749) |
| commercial_head (Ахтамова/Гусейнова) | `buildCommercialHeadAiContext_` (:10352) | `buildCommercialHeadAiTasksPrompt_` (:10407) |
| ryschanow | `buildRyschanowAiContext_` (:10845) | `buildRyschanowAiTasksPrompt_` (:10885) |

Плюс общий оркестратор `generateAiTasksCached_`/`generateAiTasksCached_` (:11026-11065),
вызов kie.ai `callKieGpt5_` (:10963), разбор ответа `parseAiTasksResponse_` (:10995), кэш
`findAiTasksCacheRow_`/`saveAiTasksCache_`/`deleteAiTasksCacheRow_`/`ensureAiTasksSheet_`
(:10270-10335, лист "ИИ_Задачи").

## Что УЖЕ на сервере (входные данные - не переносим второй раз)

- Заказы (`orders`, `by_manager`/`by_logist`/`problem_orders`/...) - `/api/orders_computed`,
  `USE_SERVER_ORDERS_CALC=on`, сверено 8/8 месяцев.
- ДЗ (`debt`, `by_customer`) - `getDebtData()` в Apps Script уже сама пробует сервер первым
  (`USE_SERVER_DEBT_CALC=on`) - контекст-билдеры вызывают `getDebtData(ss)`, а НЕ читают
  лист напрямую, значит порт контекст-билдеров на сервер может звать
  `/api/debt_computed`-эквивалент напрямую (нужно проверить его существование/добавить,
  см. Фазу 0 ниже) вместо HTTP-похода Apps Script -> VPS -> обратно.

**Требует проверки ДО порта** (Фаза 0): читает ли что-то из перечисленных функций Google
Таблицу НАПРЯМУЮ, а не через `orders`/`debt`, переданные параметром - в частности
`computeLostCustomersForManager_` (список пропавших клиентов) и `calcPaceRatioServer_`
(коэффициент темпа для прогноза) - если да, нужен отдельный маленький порт ИЛИ решить, что
эта часть считается на сервере из уже перенесённых `orders_archive`/`orders_normalized`.

## Архитектура (предлагается)

```
Google-лист "ИИ_Задачи" (кэш)          ->  MySQL ai_tasks_cache (date_key, person_name,
                                            role, tasks_json, plan_advice, model,
                                            generated_at) - PK (date_key, person_name, role)

Apps Script callKieGpt5_ (kie.ai)      ->  api/lib/kie-ai-tasks.js: callKieGpt5_ (Node fetch),
                                            тот же payload/URL/модель

buildXxxAiContext_/buildXxxAiTasksPrompt_ ->  ПОРТ 1-в-1 (транскрипция, не переписывание -
(4 роли x context+prompt)                     тот же принцип, что orders-calc.js/debt-calc.js),
                                               в api/lib/kie-ai-tasks.js

doGet action=generate_ai_tasks         ->  GET /api/ai_tasks?person=&role=&force=
                                            (checkSession - свой человек читает СВОИ задачи по
                                            имени из токена, admin может передать person=
                                            любого для просмотра "Смотреть как")

files/index.html loadAiTasksIfNeeded_/ ->  пробует новый серверный путь ПЕРВЫМ, тихий
retryAiTasks_                              фолбэк на action=generate_ai_tasks (Apps Script) -
                                            тот же паттерн, что везде в проекте
```

**KIE_API_KEY на сервере** - сейчас лежит ТОЛЬКО в Script Properties Apps Script. Нужно
добавить в `.env` VPS-сервера (`grep "^KIE_API_KEY=" .env`, никогда в код) - Влад должен
взять значение из редактора Apps Script (Настройки проекта -> Свойства скрипта) и добавить
на сервер сам, ИЛИ дать команду это сделать в следующей сессии с доступом к обоим местам.
Не просить присылать ключ текстом в чат (секрет).

## Риски

- **Промпты - не "просто текст", а результат десятков точечных правок Влада** (грамматический
  род, форматирование дат/чисел, правила эскалации по ДЗ, разделение "рост продаж" и "порядок
  в документах" и т.д. - см. сам промпт, вставленный Владом в чат 07.09, и историю правок в
  DEPLOY_LOG). Копировать СИМВОЛ В СИМВОЛ, не "восстанавливать по смыслу".
- **KIE_API_KEY - секрет** - переносить только через .env на обеих сторонах, никогда через чат
  или код.
- **Кэш "на день"** - если сервер и Apps Script одновременно пишут в РАЗНЫЕ хранилища (MySQL и
  Google-лист) для одного и того же человека в переходный период, кнопка "Сгенерировать заново"
  на одном пути не увидит кэш другого - на время Фазы 1-2 это ожидаемо (тот же класс временного
  несовпадения, что уже был при переносе `manager_plans`).
