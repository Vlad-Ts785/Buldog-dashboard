# Ретро: перенос «Планировки» на дашборд + сворачивание сайдбара

**Дата:** 2026-08-29 21:00
**Длительность:** заключительная часть очень долгой сессии (весь день - исследование
таблицы, прототип, десятки раундов правок, брейншторм плитки/магнита через агентов,
и в конце - сам перенос)
**План:** `plans/2026-08-29-logistics-planning-board.md`

## 1. Задача

Перенести полностью итерированный прототип «Планировки» (`examples/prototype-logistics-board.html`)
на боевой дашборд как реальную вкладку, плюс сворачивание бокового меню и название
тягача перед госномером - по прямому запросу Влада («пришло время выкатить это в жизнь»).

## 2. Как решал

Механический перенос по частям: CSS (scoping через `#page-logistics-plan`-префикс всех
селекторов вместо переименования классов - 18 совпадений имён, из них 1 не-scoped),
HTML (обёртка в `.page`-div, `lp-`-префикс всем id), JS (IIFE + `window.LP.init()`,
переписан слой данных - живой `D.vehicles`/`D.orders` вместо замороженного снимка и
RNG-генерации демо-рейсов). Все правки скриптовал Python-ом (find-and-replace с
проверкой количества вхождений), не руками - для файла такого размера это единственный
надёжный способ не промахнуться.

Затем - git-координация: `origin/main` ушёл на ~20 коммитов вперёд, пока шёл перенос
(параллельная сессия задеплоила настоящий глобальный переключатель темы и рефакторинг
ролей/ленивого рендера). `git merge-file` дал один конфликт на весь файл - пересобрал
`files/index.html` заново поверх свежего `origin/main` тем же набором точечных вставок.

## 3. Решил?

- [x] Да, полностью (в рамках этой сессии) - вкладка задеплоена в код (не запушено в
  main, ждёт решения Влада), сворачивание меню работает, тягач перед госномером есть,
  роль-гейтинг проверен, интеграция со свежей глобальной темой проверена.

## 4. Что можно было лучше

- **`window.D` vs bare `D` - поймано только на втором раунде проверки.** Первый smoke-тест
  дал ложно-позитивный результат из-за грязного состояния той же вкладки браузера
  (случайный `window.D = {}` от предыдущей попытки теста замаскировал баг). Урок:
  перезагружать вкладку между раундами проверки, не переиспользовать состояние. Записано
  в память отдельным файлом - `project_window_global_let_const_gotcha`.
- **Стоило раньше проверить, не ушёл ли `origin/main` вперёд.** Полтора часа работы
  (CSS/HTML/JS подготовка) были сделаны на устаревшей базе `bea15fb`, и всё пришлось
  пересобирать поверх свежего `origin/main` в конце. `git fetch`+`merge-base` стоило
  сделать раньше, а не только перед самым коммитом - см. правило репо о параллельных
  сессиях, которое сам же и знал, но применил поздно.
- **Реальных данных для проверки не было** (нет доступа к api.yardhub.ru/Google-логину
  из локального smoke-теста) - вся проверка на подставных 1-2 машинах. Первая реальная
  проверка будет только после деплоя на yardhub.ru.

## 5. Как было / как стало

- **Было:** Планировка - Google Таблица 5-летней давности, логисты правят руками,
  копируют помесячно, «мусор от помесячного копирования» (цитата Влада). Никакой
  вкладки на дашборде.
- **Стало:** вкладка «Планировка» в коде дашборда (не запушено) - живой парк, драг/

  раскраска, фильтры, сворачиваемое меню. Рейсы пока пустые - логисты заполняют сами.
