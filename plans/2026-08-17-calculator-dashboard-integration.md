# Калькулятор стоимости перевозки → вкладка дашборда

Статус: v1 реализован (2026-08-17), ждёт живой проверки Владом на реальном дашборде.

## Зачем

Отдельный файл `ЯРД_Калькулятор_v1.3/yard-calc-v1.7.html` (навигатор + карта + расчёт
стоимости + генерация КП) жил сам по себе, в фирменном стиле ЯРД (тёмно-синий/золото),
никак не связан с остальной системой. Менеджеры считают стоимость перевозки отдельно от
дашборда, на котором и так работают весь день. Плюс: методика расчёта нигде не
задокументирована для остальных чатов по дашборду — каждый раз пришлось бы заново читать
код калькулятора.

Встраиваем как вкладку `Калькулятор` в `files/index.html`, переоформленную под нейтральную
тёмную тему дашборда (токены `--bg2/--bg3/--green/--muted` и переиспользованные компоненты
`.card`/`.tab-bar`/`.grid-65`), без изменения самой методики расчёта.

## Решения по объёму (согласовано с Владом, 2026-08-17)

1. **История расчётов и лог КП** - пока остаются в `localStorage` браузера, как в оригинале.
   Не расшарено между сотрудниками, не переживает чистку кэша. Перенос в Google
   Sheets/Apps Script - отдельная задача на будущее, если понадобится.
2. **Доступ** - вкладка видна всем менеджерам, логистам и директору (в один ряд со
   «Штатка»/«План задание»), потому что калькулятор не читает серверные данные (`D.role`) -
   считает полностью офлайн в браузере.
3. **Карта и авто-км** - сохранены (Leaflet + OSRM + Nominatim, все публичные API без ключей).

## Что сделано

- `files/index.html`:
  - `<head>`: подключён Leaflet (CSS+JS, тот же CDN, что был в оригинале).
  - `<style>`: новый блок `.clc-*` (карта, форма, автокомплит, мини-статы маршрута,
    ценник, разбивка, список техники/истории, тост) на токенах дашборда. Категорийные
    вкладки техники и общая рамка карточек переиспользуют существующие `.card`/`.card-title`/
    `.tab-bar`/`.tab-btn`/`.grid-65` - не изобретали параллельную систему компонентов.
  - Пункт меню «🧮 Калькулятор» (`data-page="calculator"`) между «План задание» и «Клиенты».
  - `PAGE_TITLES.calculator`, `applyRoleUI()` пускает менеджеров/логистов на неё же, где
    `my-page`/`order-plan`.
  - `showPage()`: `Clc.initPage()` при открытии вкладки - лениво инициализирует карту
    Leaflet (в скрытом `display:none`-контейнере она бы не отрисовалась) и пересчитывает
    размер при повторном заходе.
  - Разметка страницы `#page-calculator` - полностью статична (не грузит данные с сервера).
  - Движок (`<script>` перед основным скриптом дашборда, чтобы `window.Clc` уже
    существовал к моменту первого вызова `showPage()`): портирован из `yard-calc-v1.7.html`
    один в один - цены, тарифы, база техники (100+ единиц), формулы округления не менялись
    ни на цифру. Изменения только в "поверхности":
    - все `id` элементов с префиксом `clc-` (нет ни одного совпадения с существующими id
      дашборда, но защищаемся от будущих);
    - весь код обёрнут в IIFE, наружу торчит только `window.Clc = {...}` с обработчиками,
      на которые ссылается разметка (`Clc.calc()`, `Clc.fltr()`, `Clc.genKP()` и т.д.) -
      никакого захламления глобального пространства;
    - категорийные вкладки техники используют `.tab-btn`/`.active` дашборда вместо
      собственных `.tt-btn`/`.act`, поиск по `.clc-page .tab-btn` не задевает вкладки других
      страниц (проверено - клик по вкладке техники не резетит активную вкладку на «Клиенты»);
    - ключи `localStorage` переименованы в `yrd_calc_history`/`yrd_calc_kp_num`/
      `yrd_calc_kp_log` (было `ycH`/`ycKPn`/`ycKPlog`).
  - Генерация КП (`genKP()`) не тронута вообще - собственный изолированный HTML/CSS внутри
    строки, никогда не попадает в DOM дашборда, поэтому не могла ничего сломать и не
    участвовала в переносе стилей.
- Транформация оригинального кода в `clc-`-версию сделана скриптом
  (не руками) - `node`-скрипт с точечными regex-заменами id/классов/localStorage-ключей,
  прогнан с `node --check` на выходе и sanity-проверками "не осталось ли непрефиксованных
  id" перед вставкой в `index.html`. Сам скрипт не сохранён в репозитории (одноразовый,
  правило 3 - удалять одноразовый код), но логика описана здесь на случай повторного
  переноса при обновлении калькулятора.

## Проверено локально (`npx serve files`, без живого Apps Script)

- Ни одной ошибки в консоли, специфичной для калькулятора (единственная ошибка
  `Cannot set properties of null` воспроизводится и на `main`/`global-stats` без калькулятора
  - это реакция остального дашборда на недоступный Apps Script в офлайн-тесте, не регрессия).
- Карта инициализируется только при первом открытии вкладки (`leaflet-container` появляется
  на DOM-элементе).
- Расчёт: смена/километраж/сопровождение/итоговое округление до 5000 в диапазоне
  100к-1М ₽ - воспроизведены верно на ручном вводе км (137000 → 135000, как и должно
  быть по `rn()`).
- Категорийные вкладки техники (клик "Краны" → 40 позиций) не трогают вкладки других
  страниц («Клиенты» осталась на своей активной вкладке).
- Выбор техники из базы подставляет вес/габариты и показывает тост.
- Сохранение расчёта пишет в `localStorage` под новым ключом и рендерит в списке истории.
- Адаптив: на 375px нет горизонтального скролла, `.grid-65` схлопывается в одну колонку
  (переиспользован существующий media-запрос дашборда, ничего нового не понадобилось).

## Совместимость с «План задание» (другой чат, в работе параллельно)

Не связывали код напрямую - разные вкладки, разные модели данных (калькулятор не знает о
заказах/планировке). Когда «План задание» стабилизируется, следующий шаг - прокинуть
рассчитанную стоимость калькулятора в черновик заявки одним кликом (открыть «План задание»
с предзаполненным маршрутом/грузом/ценой). Не делали сейчас, чтобы не блокировать эту задачу
чужой незавершённой работой - зафиксировано как желаемое следующее сближение кусочков системы.

## Доработки по первому фидбеку (2026-08-18)

Влад прислал скриншот с реальной выбранной буровой (110 т, Faymonville) - обнаружены три проблемы:

1. **Категория Faymonville не подбиралась под вес** - при выборе техники/ручном вводе массы
   поле "Категория Faymonville" оставалось на прошлом значении, расчёт шёл по заниженному
   тарифу (110 т считало по ставке 75-100 т вместо 100-120 т). Исправлено -
   `faymonCatByMass()`/`syncFaymonCat()` подбирают категорию при каждой смене веса/типа
   техники (в `onWChange()`); свыше 120 т - вне каталога, тост "согласуйте с руководителем",
   выбор не трогается (авторасчёта для такого веса нет).
2. **История расчётов должна сохраняться на сервер, с привязкой к менеджеру** - решение из
   первой итерации (localStorage) отменено по прямой просьбе. Добавлен новый лист Google
   Sheets "Калькулятор_История" + `action=calc_save`/`action=calc_history` в Apps Script.
   Автор строки - `access.name`, определяется сервером из уже проверенного `id_token` (тот
   же механизм, что и везде в дашборде) - клиент не может подделать, от чьего имени сохранён
   расчёт. `manager`/`logist` видят в списке "История расчётов" только свои сохранённые
   расчёты, `admin` - все (последние 300), у каждой строки виден менеджер. localStorage
   оставлен как офлайн-фолбэк (если Apps Script недоступен, список не пустеет).
3. **Форма КП полностью переделана** - вместо навы/золота с эмодзи-бейджами теперь тот же
   фирменный бланк, что и в приказах компании (`Приказы/*.md`): шапка ОБЩЕСТВО С
   ОГРАНИЧЕННОЙ ОТВЕТСТВЕННОСТЬЮ «БУЛЬДОГ» / ОГРН / ИНН / КПП / адрес, разделительная
   черта, Times New Roman, простая табличная разбивка параметров, строка подписи
   "Менеджер - <имя>" (реальное имя из `D.managerName`/`D.logistName`, если известно).
   Логика расчёта самого КП (номер, состав таблицы, сумма) не менялась.

**Обнаружено и устранено при деплое:** перед push в живой Apps Script оказалась чужая
недокоммiченная работа (сессионные токены на 48ч + live-источник заказов с
`api.yardhub.ru`, задеплоено той же датой в обход git другой параллельной сессией) - по

и только потом поверх - изменения калькулятора. Ничего не потеряно и не откачено.
