# Ретро: скорость дашборда, долгая сессия, свой домен + разведка архитектуры 2.0

**Дата:** 2026-08-17 16:00
**Длительность:** ~5 часов (длинная сессия, несколько тем подряд)
**План:** [plans/2026-08-13-dashboard-main-payload-precompute.md](../plans/2026-08-13-dashboard-main-payload-precompute.md),
[plans/2026-08-17-session-token-persistent-login.md](../plans/2026-08-17-session-token-persistent-login.md)

## 1. Задача

Началось с "дашборд долго грузится" и "надоело логиниться через Google каждый час" - закончилось
переездом на свой домен (github.io недоступен из офиса Влада) и разведкой, потянет ли Beget
будущую миграцию с Google Таблиц на нормальный сервер+БД.

## 2. Как решал

- **Скорость главной страницы**: нашёл, что `doGet()` пересчитывал всё с нуля на каждый визит.
  Вынес тяжёлые поля в `buildHeavyMainPayload_()`, кэш - скрытый лист (не CacheService, там
  лимит 100KB/ключ), наполняется в `runAll()`. Штатка-производные поля (статус машин) оставил
  живыми - её правят руками, кэш на 3 часа сломал бы это.
- **Долгая сессия**: свой подписанный токен (HMAC) поверх Google-логина, 48ч со скользящим
  окном, вместо часового `id_token` от Google. Роль/доступ по-прежнему проверяется каждый раз
  по листу "Доступ" - длинная сессия не даёт лишних прав, только не требует пересвода.
- **Оба фикса деплоил в один день, дважды подряд обнаружил чужую незакоммиченную работу**
  (коммерческая выручка v171-172, потом План задания + архив Поступлений v174-209) при `clasp
  pull` перед пушем - протокол координации из CLAUDE.md сработал как задумано: sync-коммит
  сначала, свои правки поверх, ничего не затёрто.
- **Сайт не открывался на рабочем компе** - оказалось не связано с кодом: ISP/DPI режет
  `github.io` конкретно из офисной сети (работает через VPN/телефон). Решение - свой домен
  (`yardhub.ru`, куплен через Beget за 199₽) как CNAME-обёртка над тем же GitHub Pages.
- **По ходу разговора Влад поднял вопрос "не пора ли на свой сервер"** - вместо того чтобы
  просто согласиться или просто отговорить, проверял утверждения руками вместо "наверное":
  - SSH на shared-хостинге Beget - подключился, поставил Node.js через `nvm`, но фоновый
    процесс (и `nohup`, и `tmux`) хостинг убивает при разрыве сессии - только cron-скрипты.
  - Влад переспросил "уверен, что VPS это исправит?" - честно признал, что не проверял, нашёл
    через `WebFetch` описание VPS (KVM, root, полноценная ОС) - логичнее, но тест руками ещё
    не сделан (отложили, чтобы не терять бесплатный период хостинга).
  - Домен не заработал сразу - разобрал по слоям (DNS/WHOIS-задержка, потом `origin_mismatch`
    в Google OAuth из-за смены домена, потом HTTP vs HTTPS для origin) вместо одной причины.

## 3. Решил?

- [x] Да, полностью - все три исходных запроса (скорость, сессия, "сайт не работает") закрыты
      и подтверждены Владом ("все заработало").
- Разведка архитектуры 2.0 - осознанно не доведена до решения: договорились не мигрировать
  сейчас, копить факты (Node.js на shared - подтверждено с оговоркой, VPS - не проверено,
  мобильное приложение как будущее требование - учтено в плане фаз).

## 4. Что можно было лучше

- **Не предупредил заранее про `origin_mismatch`** при добавлении своего домена - это
  предсказуемое следствие смены origin для Google OAuth, стоило сказать сразу при настройке
  CNAME, а не когда Влад уже наткнулся на ошибку и решил, что "Google-логин надоел".
- **Первая версия ответа про "уверен ли я насчёт VPS"** была недостаточно честной - написал
  "давай так и сделаем" до того, как реально проверил; переспрос Влада был по существу и заставил
  сначала посмотреть факты (WebFetch), а не просто более уверенным тоном повторить то же самое.
- Несколько раз подряд отвечал слишком длинно/технично там, где Влад прямо просил "давай проще" -
  стоило калибровать длину ответа под сигнал с первого раза, не после повтора просьбы.

## 5. Как было / как стало

- **Было:** дашборд пересчитывал всё с нуля на каждый визит (долгая загрузка); логин через
  Google слетал каждый час; сайт не открывался с части рабочих компов без объяснения причины;
  не было ответа на вопрос "что вообще возможно на Beget, если решим переехать".
- **Стало:** главная страница грузится из готового кэша (пересчёт - раз в 3 часа в фоне);
  сессия входа держится 1-2 суток; сайт на своём домене `yardhub.ru`, независим от блокировок
  `github.io`; есть первые проверенные руками факты про Beget (Node.js по cron - да,
  постоянный сервер - нет на shared, вероятно да на VPS - не подтверждено) для будущего плана
  миграции.
