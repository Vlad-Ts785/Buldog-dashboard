# «Умный звонок»: полноценный плеер записи + расшифровка + автозаполнение брифа сделки

## Зачем

Влад (08.09, после того как увидел кнопку «Прослушать»): нужен нормальный плеер с
перемоткой (как у Mango/почти у любого плеера записи), и расшифровка звонка с сутью
разговора + автозаполнение карточки сделки (груз/откуда/куда), «как в Битриксе»
(https://helpdesk.bitrix24.ru/open/27105168/ - справка Битрикса про распознавание речи).

**Как выглядит успех MVP:**
1. У записи - реальный плеер: играть/пауза, шкала с перемоткой (клик/тащить), время
   тек./общее - не просто одна кнопка «Прослушать»/«Пауза».
2. Кнопка «Расшифровать» рядом - показывает текст разговора + короткую суть (2-3
   предложения) под записью.
3. Если в разговоре прозвучало «что везём»/«откуда»/«куда» - поля брифа сделки
   заполняются САМИ, той же меткой `brief_source='auto'`, что уже есть у автоизвлечения из
   переписки - НЕ затирая то, что менеджер ввёл вручную.

## Что НЕ делаем в v1

- Не транскрибируем ВСЕ звонки автоматически фоном - платно (кредиты kie.ai) и не нужно,
  пока менеджер сам не попросил («Расшифровать» - по клику, не по факту звонка).
- Не делаем разделение по говорящим (diarization - «кто что сказал») - для сути разговора
  и извлечения брифа хватает сплошного текста; можно добавить позже, если понадобится.
- Не трогаем распознавание тональности/оценку качества звонка (у Битрикса это тоже есть) -
  отдельная фича, не запрошена.

## Фаза 1 - MVP

Проверка через 4 вопроса:
- Решает проблему? Да - именно то, что попросил Влад, с прямой отсылкой на Битрикс.
- Не код ради кода? Да - расшифровка добавляется только рядом с УЖЕ существующей кнопкой
  «Прослушать», автозаполнение переиспользует ГОТОВЫЙ механизм `applyCargoBriefToDeal_`
  (уже есть для брифа из переписки) - не пишем вторую параллельную систему.
- Не усложняет v1? Да - по клику, не фоном; без diarization/тональности.
- Что выкинуто? Фоновая транскрипция всех звонков, разбивка по говорящим, оценка качества.

### 1.1 Плеер с перемоткой (независимо от транскрипции - можно сдать первым)
- [ ] Заменить кнопку play/pause (`playBtnHtml_`/`setPlayBtnState_` в `files/index.html`)
      на мини-плеер: play/pause + шкала (клик/перетаскивание = перемотка через
      `audio.currentTime`) + время тек./общее. Состояние по-прежнему переживает
      перерисовку drawer/треда так же, как сейчас (проверка `S.audioEntry` при рендере).
- [ ] `timeupdate`/`loadedmetadata` на `<audio>` обновляют шкалу и время в DOM напрямую
      (не через полный `renderDrawer()`/`renderThread()` - это огонь по воробьям каждые
      250мс).

### 1.2 Транскрипция по клику
- [ ] Новая таблица `crm_call_transcripts` (`entry_id` PK, `transcript` TEXT, `summary`
      TEXT, `brief_json` JSON NULL, `kie_task_id`, `created_at`) - кэш, чтобы не платить
      кредитами за повторный клик по той же записи.
- [ ] Временная публичная ссылка на скачанную запись - отдельный короткий эндпоинт
      (случайный токен в URL, не session_token; запись уже лежит у нас как байты после
      первого скачивания через `/api/crm/mango/recording`, кэшировать в `crm_call_transcripts`
      или временный файл на диске) - **точный механизм решить после Фазы 0** (зависит от
      того, обязателен ли `audio_url` именно у kie.ai, или там есть путь без публичной
      ссылки - ПРОВЕРИТЬ доки/живым тестом, не строить вслепую).
- [ ] `POST /api/crm/mango/transcribe?entry_id=` (checkSession) - создаёт задачу в kie.ai
      (если её ещё нет в кэше), опрашивает `recordInfo` (с разумным таймаутом и понятной
      ошибкой по образцу `callKieGpt5_`/nginx 150с - см. README сервера 07.09), сохраняет
      результат.
- [ ] Кнопка «Расшифровать» рядом с плеером - при готовом кэше просто показывает текст,
      иначе запускает и показывает состояние ожидания (без спиннера - тот же принцип ГОСТа).

### 1.3 Суть разговора + автозаполнение брифа
- [ ] Один вызов уже работающего `callKieGpt5_` (codex/v1/responses, `gpt-5.6-luna`) с
      транскриптом на входе - промпт просит СТРОГИЙ JSON `{summary, cargo_type,
      cargo_weight_tons, route_from, route_to, wanted_date, vehicle_hint}` (те же поля,
      что и `extractCargoBrief_`/`applyCargoBriefToDeal_` для брифа из переписки - поля
      LLM может пропустить, если в разговоре не прозвучало, промпт должен явно это
      разрешать, не выдумывать).
- [ ] `applyCargoBriefToDeal_(dealId, brief)` - **тот же существующий вызов**, что и для
      чата (см. `server.js:3139`, `avito-sync.js:203`) - никогда не трогает сделку, если
      `brief_source='manual'`. Сумма/суть в UI показываются независимо от того, применился
      ли автозаполнение (можно один раз распознать полезное "суть разговора", даже если
      деталей груза там не прозвучало).
- [ ] Показ сути + текста расшифровки в таймлайне рядом со звонком; если бриф применился -
      те же метки «авто» (`dr-auto`), что уже есть у брифа из переписки.
