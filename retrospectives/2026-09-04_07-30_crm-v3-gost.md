# Ретро: CRM v3 по ГОСТу - переписка Авито целиком, канбан уровня 5, Чаты в три панели

**Дата:** 2026-09-04 07:30
**Длительность:** одна ночная сессия (~6 ч), автономно по мандату Влада
**План:** `plans/2026-09-03-crm-v3-gost.md`

## 1. Задача

Влад: «полностью сам отработал блок СРМ с учётом ГОСТа... уровень Bitrix/amoCRM... чат
работает непонятно: сообщения не приходят, историю не видно - обрезки разговоров...
иконки со звуками... подключив агентов».

## 2. Как решал

1. **Диагноз по данным до кода.** `SELECT ... GROUP BY client_key, direction` показал
   корень за минуту: все 11 исходящих лежат под ключом `avito:410252765` - это НАШ
   аккаунт. Вебхук брал `author_id` как ключ клиента, а у исходящих автор - мы.
   Живые вызовы API Авито: 1100 чатов с октября 2025 против 22 сообщений в базе,
   имена/аватары/объявления доступны, но никогда не забирались.
2. **Два агента параллельно** (методика ГОСТа раздел 0 п.3): исследователь по
   amoCRM/Pipedrive/Intercom/Front/Bitrix (полка won/lost вместо колонок, rotting по
   стадиям, inbox с сортировкой по времени ожидания, «Новые сообщения», Enter/Shift+Enter,
   undo-тосты) и дизайнер - анатомия «Чатов» по ГОСТу с числами (`cx-*`). Бэкенд и
   фронтенд писал сам - склейка кода от многих авторов дороже самой работы (урок 27.08).
3. **Бэкенд отдельным модулем** `api/lib/avito-sync.js`: ключ клиента всегда из
   участников чата, полный импорт истории (фон, ~10 мин, 4 запроса/с), инкремент каждые
   2 мин как страховка от пропущенных вебхуков, типы сообщений/вложения/оператор из
   префикса Битрикса, сделки при импорте - только живым чатам (14 дней).
4. **Фронтенд одним модулем** `CRM` вместо россыпи `crm*`: канбан по `mx-` канону
   буквально (lerp .28, наклон ±7°, FLIP 300, settle 380, победа через уже живущие в файле
   `bankCelebrate5_`/`bankFlySum_`/`uiSounds.win`), полка won/lost при драге, шторка сделки
   с таймлайном, «Чаты» по спеке дизайнера, оптимистичная отправка, единый `p2Toast` с
   кнопкой «Отменить» (расширил общий компонент, не завёл свой).
5. Проверка: SQL на проде, тестовая сессия, выписанная тем же HMAC на сервере (реальные
   ответы всех ручек), синтетика в браузере с подменой `elementFromPoint` для драга.

## 4. Что можно было лучше

- Патч сервера через Python-строки с регэкспами дважды сорвался на экранировании
  (`"\b"` → backspace; heredoc с `'` внутри `-c`). Правило: любые патчи с JS-регэкспами
  писать raw-строками и через Write-инструмент, не heredoc.
- Первый прогон импорта упал на одном чате из-за даты «2026-40-02» и остановил ВЕСЬ
  обход - изоляцию ошибок по чату надо закладывать в цикл сразу, а не после падения.
- Скрытая панель браузера не считает геометрию (все `getBoundingClientRect` = 0,
  скриншоты таймаутят) - полчаса ушло, прежде чем подменил `elementFromPoint` и проверил
  логику драга без геометрии. Записано в память.
- Старые строки вебхука хранили id КОНВЕРТА (`body.id`), а не сообщения
  (`payload.value.id`) - дедупликация с API не совпала бы никогда; нашёл только сравнив
  `raw_json` с API. Урок: при первой же интеграции сверять «наш уникальный ключ» с тем,
  что отдаёт read-API источника, а не только с вебхуком.

## Чек-лист приёмки ГОСТа (раздел 10) - по коду

Токены только из `:root` - да (новых hex нет, `color-mix` от токенов); шрифты по ролям,
цифры mono+tabular - да; компоненты из референсов (`mx-`, `.chip`, `p2-toast`, drawer,
ctxmenu, `.kpi`) - да; отклики ≤150ms, декор ≤400ms, исключение - победа - да;
drag буквально по разделу 6 - да (lerp .28, ±7°, тень двухслойная, opacity .82, settle
380 overshoot, FLIP 300, Esc-отмена без overshoot); курсорный свет через общий
`initCursorLight_` на `.crm-kpis`/`.kb-board` - да, на «Чатах» осознанно нет (в ГОСТ 2.2
как исключение на утверждение); hover-физика двух уровней (`.kpi` вылет, панели без) -
да; reduced-motion и `document.hidden` - да; звук - регистр sounds5 через общий
выключатель, без hover-звука - да; 21 запрет - emoji/alert/border-left/тени-декор/
радиусы>12/transition:all - ни одного; фильтры реально фильтруют со счётчиками и
сбросом - да; цифры сводки бьются с `/api/crm/summary` - да; новые паттерны дописаны в
ГОСТ (2.2) с пометкой «на утверждение» - да; превью=контракт - превью в этот раз
заменяла спека дизайнера с числами, живой экран сверен с ней по классам.
