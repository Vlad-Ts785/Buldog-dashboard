# План: Телематика Omnicomm на дашборд (живые координаты/статусы техники)

**Дата:** 2026-08-31
**Автор:** Клод
**Статус:** в работе (Фазы 1-3 сделаны, Фаза 3 не задеплоена и не проверена вживую;
Фаза 4 - масштабирование на весь парк, уже фактически покрыто, т.к. поллер сразу
завели на все 32 машины)

## Цель

Тянуть с Omnicomm Online (GPS/CAN-мониторинг тралов и длинномеров) живые координаты,
скорость, зажигание и пробег техники на наш сервер (api.yardhub.ru), чтобы показать
на дашборде без захода в отдельный кабинет Omnicomm.

## Контекст

- Разведка 2026-08-31 (см. `retrospectives/` за эту дату): гостевая ссылка
  `public-report/...` годится только для просмотра человеком в браузере - без
  браузера отдаёт `401 Unauthorized` (проверено четырьмя вариантами заголовков).
  Причина - у гостевой ссылки урезанный JWT (`PublicLinkReportUser`, TTL access
  10 мин / refresh 24 ч), плюс скрытый обмен, который работает только внутри
  живой браузерной сессии.
- Прямое управление терминалом Navtelecom Flex через SMS-команды/RCS-конфигуратор
  (`wiki.navtelecom.ru`) - тупиковый путь: нет команды "пропиши сервер" в списке
  стандартных, только через отдельный конфигуратор, доступа к которому у нас нет.
  Terminal = железка (аналог роутера), Omnicomm = провайдер - тянуть данные нужно
  с провайдера, не с железки (инсайт Влада, подтверждён).
- Аналогичная система коллеги («Ресурс», Дмухайло П.М.) подтвердила рабочую схему:
  Flutter/UI никогда не ходит в Omnicomm напрямую, весь логин и опрос - на бэкенде.
  Оттуда же предупреждение (важно!): **опрос координат не чаще раз в 30 сек** -
  чаще либо банит Omnicomm, либо не имеет смысла (сам терминал репортит не чаще).
- Найден настоящий (не гостевой) эндпоинт логина - вытащен из JS-бандла формы
  входа (`login-page/610.b57d4745.js`):
  ```
  POST https://online.omnicomm.ru/auth/internal/login?jwt=true
  Content-Type: application/json
  {"login": "...", "password": "..."}
  ```
  Поля тела подтверждены (`"login"`, `"password"` встречаются в том же бандле).
  Реальный логин должен возвращать JWT с полными правами (не `PublicLinkReportUser`).
- Пример внутреннего эндпоинта данных по одной машине (уже опробован в браузере,
  живой JSON): `GET /ls/api/v1/vehicles/{id}/info` -
  `{fuelLevel, speed, engineWork, parseAddress, mileageCAN, ignition, ...}`.
  Также замечен `POST /ls/api/v1/activity/vehicles` - возможно, отдаёт список/статус
  сразу по всем машинам одним вызовом (не проверено) - если да, экономит N запросов.
- Решение Влада (2026-08-31): использовать боевой логин `yardtral`/`tral1501` сразу,
  отдельный технический аккаунт у Omnicomm не запрашивать.
- **Логин/пароль засветились открытым текстом в Telegram-переписке** (этот чат +
  групповой с Дмухайло) - после того как интеграция заработает, стоит сменить
  пароль в кабинете Omnicomm.

## Фазы

### Фаза 1. Проверка логина и разового опроса на одной машине (~1 час) - ГОТОВО 31.08
- [x] `yardtral`/`tral1501` -> `.env` на VPS (`OMNICOMM_LOGIN`, `OMNICOMM_PASSWORD`).
- [x] `POST /auth/internal/login?jwt=true` с боевым логином - `200 OK`, реальный
      JWT (54 permissions, включая `maps.omnicomm.map`), TTL access **3600 сек**
      (не 600, как у гостевой ссылки), TTL refresh 86400 сек (те же 24 ч).
- [x] **Найден настоящий механизм авторизации данных** (после серии 401 на любых
      вариантах `Authorization: Bearer`/`X-Auth-Token`/UA-подделки): API ждёт JWT
      **в куке**, не в заголовке - `Cookie: jwt=<token>`. Это же объясняет, почему
      гостевая ссылка не работала headless - мы пробовали её тоже через заголовок.
  - [x] `GET /ls/api/v1/vehicles/1138032400/info` с `Cookie: jwt=...` -> `200 OK`,
        живые данные без браузера (652 ХН, скорость 82.9 км/ч, Самарская обл.,
        `mileageCAN: 612259.25`, `fuelLevel: 1.3`, `ignition: true`).
  - [x] **Массовый эндпоинт разгадан** (31.08, через перехват живого запроса в
        браузере по гостевой ссылке + подбор на VPS): `POST /ls/api/v1/activity/
        vehicles` с телом `{"ids": ["1138032400", "..."]}` - **ID строками**, не
        числами (это и было причиной пустого `[]` раньше). Один вызов на все 32
        машины разом - `latitude`/`longitude`/`speed`/`direction`/`ignition`/
        `voltage`/`fuelVolume`/`engineWork`/`gpsDataValid` и т.д., ~1.9 сек на
        весь парк. Один "битый" ID в массиве роняет весь запрос в `500` - список
        ID должен быть чистым (сверен со Штаткой). Одна машина (К 709 СМ 750,
        id 1104000915) не вернулась в ответе при тесте - трактовать как "нет
        свежих данных", не как ошибку.
  - [x] **Полная таблица ID -> госномер на все 32 машины** снята с
        `POST /ls/api/v1/vehicles/namesbyids` (виден в сетевых запросах гостевой
        ссылки) - тот же список, что и в `config.vehicles` самой гостевой ссылки.
        Экономит Фазу 2 - маппинг уже есть, не нужно сопоставлять руками.
  - [ ] `POST /auth/refresh` с `Cookie: refresh=<refresh_token>` -> `401` при
        первой попытке - формат запроса ещё не подобран. Не блокирует MVP:
        можно просто перелогиниваться заново (логин быстрый и рабочий) каждые
        ~50 мин вместо тонкого рефреша.
- [x] **Session collision - риска нет.** Влад подтвердил (31.08): у Omnicomm
      несколько человек сидят под этим логином целыми днями одновременно,
      проблем не было. Сделали 5+ логинов подряд за тест - никого не выбило.
      Можно свободно перелогиниваться по расписанию, не переживая за живых
      пользователей в браузере.
- [x] Тестовые скрипты с сервера удалены после снятия находок (правило репо).

## Риски

- ~~Session collision~~ - снято 31.08, Влад подтвердил: несколько человек сидят
  под этим логином одновременно целыми днями, проблем нет.
- **Троттлинг/бан:** слишком частый опрос (чаще 30 сек, предупреждение коллеги)
  может привести к блокировке аккаунта Omnicomm - жёстко закладываем интервал.
- **Скрытый механизм авторизации:** реальный логин может обнаружить тот же скрытый
  шаг, что и гостевой (401 при попытке без браузера) - тогда придётся повторить
  разведку сетевых запросов (аналогично тому, что делали для гостевой ссылки) уже
  для боевого логина.
- **Утечка пароля в переписке:** `yardtral`/`tral1501` уже видели минимум 2 чата
  в Telegram/Max - сменить пароль сразу после стабилизации интеграции.
- **Двойники в списке машин:** один госномер - несколько объектов Omnicomm
  (Влад предупредил 31.08) - без фильтра дашборд может показать мусорные записи.
