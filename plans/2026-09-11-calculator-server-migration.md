# Перенос формулы калькулятора на сервер

**Статус:** в работе
**Одобрено:** Влад, 2026-09-11 - продолжение разговора про защиту кода от кражи
(см. память `project_dashboard_ip_ownership_strategy.md`). Прямо сейчас тарифная методика
(`ESC_ZONE`/`ESC_CAT`/`P{}` и вся `function calc()` в `files/index.html`) отдаётся ЛЮБОМУ
анонимному запросу к `yardhub.ru` без логина - проверено `curl` 11.09, конкурент или
клиент читает точные ставки одним `Ctrl+U`.

## Зачем и почему НЕ так, как остальной переезд на сервер

Все прошлые переезды (зарплаты, ДЗ, Парк) делались ради скорости/единого источника данных,
с тихим фолбэком на старый канал при сбое сервера - это стандартный паттерн проекта.

**Здесь цель другая - секретность, не скорость.** Значит фолбэк должен быть ДРУГИМ:
- Во всех прошлых переездах фолбэк = "старый канал (Google Таблицы) тоже знает формулу,
  не страшно посчитать там же". Здесь старый канал = формула ПРЯМО В БРАУЗЕРЕ - тот самый
  канал, который мы закрываем. Тихий фолбэк на клиентский расчёт при недоступности сервера
  вернёт дыру обратно.
- Поэтому: **после переключения - формулы в `files/index.html` не остаётся вообще.** Если
  сервер недоступен - калькулятор показывает "сервис временно недоступен", не считает сам.
  Это осознанное отступление от правила "тихий фолбэк" (см. `CLAUDE.md`), и именно поэтому
  оно отдельно проговорено здесь, а не молча.

## Что остаётся на клиенте (не секрет, просто UI/карта)

- Ввод параметров груза, чипы баз, ручной км-режим - форма как есть.
- Leaflet-карта, геокодирование адресов в координаты, построение маршрута и километража
  (`d1`/`d2`/`d3` -> `a1`/`a2`/`a3`) - это работа с публичным картографическим сервисом,
  не бизнес-логика ценообразования. Клиент по-прежнему считает расстояния и шлёт их
  ЧИСЛОМ на сервер вместе с координатами точек погрузки/выгрузки.
- Каталог `TECH` (габариты спецтехники под авто-подбор Faymonville-категории по массе) -
  публичные паспортные данные техники (Caterpillar/Komatsu и т.д.), не тариф. Остаётся
  на клиенте, в этот план не входит (можно вынести отдельно позже, не приоритет).
- Рендер табла (`renderBoard_`, `renderBoardPending_`) - подаётся на вход тот же формат
  `Clc._last`, что и сейчас, просто заполняется из ответа сервера, а не из локального
  расчёта. Разметку и вид табла не трогаем.

## Что переносим на сервер (Фаза 1 - вся ценовая формула)

Из `files/index.html`, район строк 5000-5412 (сверять по живому файлу, не по номерам -
они уже сдвигались от параллельной работы):

- Константы: `P{}` (ставки по типам техники), `FAR_LIMIT`, `FAR_SHIFT`, `K_COEF`, `OV_COEF`,
  `EMPTY_RATE`, `ESC_ZONE`, `ESC_FAR_BASE`, `ESC_FAR_MIN`, `ESC_CAT`, `MSK_LAT`/`MSK_LON`,
  `SAD_R`, `FAR_R`, `MKAD_POLY`.
- Функции: `escortBand()`, `tralByMass()`, `faymonCatByMass()`, `rn()`, `ptDist()`,
  `inMkad()`, `mskZone()`, и главная - `calc()` (переименовать в чистую функцию без DOM,
  например `computeQuote(input)` - сейчас она читает `document.getElementById` напрямую,
  это придётся распутать на входные параметры).
- Перенос 1-в-1 - те же числа, тот же порядок округлений (`rn()` вызывается в конкретных
  местах не просто "для красоты" - порядок влияет на итог из-за округления). Никаких
  "улучшений" формулы по дороге - если увидим что-то похожее на баг в текущей логике,
  фиксируем находку отдельно, не чиним молча внутри переноса.

## Контракт нового эндпоинта

`POST /api/calculator/quote`, `checkSession` (любой залогиненный - механику это тоже нужно,
без ограничения по роли).

Вход (JSON body) - всё, что раньше `calc()` читала из DOM:
```
{
  weight, length, width, height,        // числа, как clc-weight/len/wid/hei
  cargoType,                            // 'negabarit' | иное
  vehType,                              // 'board'|'panel'|'tral'|'tral_crane'|'korito'|'faymon'
  faymonCat, koritoType, koritoExt,     // доп. параметры по типу техники
  trips, loopCount,
  manual,                               // ручной км-режим вкл/выкл
  a1, a2, a3,                           // километраж (клиент уже посчитал через карту)
  escZone,                              // если manual - выбор пользователя
  loaded: {lat,lng}, unloaded: {lat,lng} // если !manual - для авто-определения зоны
}
```

Выход - тот же набор полей, что сейчас складывается в `Clc._last` (total, sub, shiftEff,
shiftRaw, coefOver, e1, ldAll, loopBackTotal, e2, esc, escNote, escortCar, escortNeed,
coef, coefs, rateName, a1/a2/a3, loopCount, mskOnly, isFar, manual, neg, over, w, vt, wid,
len, hei) - клиент кладёт ответ прямо в `Clc._last` и зовёт `renderBoard_()`, разметку не
трогаем.
