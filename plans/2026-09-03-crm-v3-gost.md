## Зачем (одна строка)

Сегодняшний CRM функционально работает, но неудобен и некрасив (Влад), а мессенджер
показывает обрезки переписок - менеджеры не могут им пользоваться вместо Битрикса.

## Как выглядит успех

Сценарий приёмки из `CRM_UX.md` выполняется на живом сайте руками Влада: утро → CRM →
сводка → «Чаты» → ВСЕ диалоги Авито с ПОЛНОЙ историей (включая наши ответы из Битрикса
и историю до подключения вебхука) → открыл один → понял клиента/груз/маршрут/цену →
ответил, не открывая пять окон → CRM обновилась сама. Плюс: канбан ощущается как
«Канбан на ощупь» уровня 5 (физика, звук, победа, undo), чек-лист приёмки ГОСТа
(раздел 10) пройден по каждому пункту.

## Диагноз бага чата (найдено 03.09 в данных сервера, до кода)

1. **Наши ответы теряются.** Вебхук Авито берёт `author_id` как ключ клиента. У исходящих
   сообщений автор - НАШ аккаунт (410252765), поэтому все 11 наших ответов лежат под
   фиктивным клиентом `avito:410252765` в 5 разных чатах, а в треде клиента видны только
   его реплики. Именно это Влад называет «обрезки разговоров».
2. **Истории до вебхука нет.** Никогда не подтягивали переписку через API Авито - в базе
   22 сообщения, а в аккаунте Авито 1100 чатов с октября 2025 (проверено живым вызовом
   `GET /messenger/v2/accounts/{id}/chats`, 12 страниц по 100).
3. **Клиенты без имён.** `avito:418847604` вместо «Кирилл» - хотя API чатов отдаёт имя,
   аватар и объявление, о котором пишут.
4. Типы сообщений кроме text (image 7, system, appCall/call 209 чатов) не хранятся и не
   показываются - «пересланное не прочитать» из антипаттернов amoCRM.
5. «Сообщения не приходят» - вебхук живой (7 хитов 03.09, ответы 200), но без пункта 1
   ответы менеджеров в чат не попадают, и это выглядит как «не приходят».

## Что НЕ делаем в этой итерации (сознательно)

- WebSocket/SSE - опрос 10 с остаётся (CRM_ARCHITECTURE.md, v2).
- LLM-извлечение брифа (kie.ai) - только по отдельному «да» Влада (стоимость на каждое
  сообщение).
- Отправка фото/файлов в Авито из нашего композера (приём и показ - да).
- Список/таблица сделок, Аналитика как режим, роли доступа, задачи/КП в карточке,
  React.
- Cmd+K командная палитра (бэклог, из исследования).
- WebGL-шлейф за карточкой (ГОСТ раздел 7 - по отдельному решению).

## Внешний анализ (агент-исследователь, 03.09, источники в transcript и ниже)

Взято в работу: (1) won/lost не колонки, а «полка» внизу, видимая только во время
перетаскивания (amoCRM/Pipedrive) - доска не расползается; (2) «гниение» карточки по
дням без активности с порогом на стадию (Pipedrive rotting) - у нас уже есть точка
свежести, доводим до порогов по стадиям; (3) карточка = кто / сколько / что дальше,
остальное в шторке; (4) inbox: Ждут ответа (N) / Мои / Неназначенные / Все, сортировка
по времени ожидания, «Новые сообщения»-разделитель, группировка подряд идущих
сообщений, разделители дней, подгрузка истории вверх с сохранением скролла,
Enter/Shift+Enter, `/` для шаблонов, черновик в localStorage, «Взять себе» из треда;
(5) undo-тост вместо подтверждений, оптимистичные обновления с откатом; (6) сводка:
Ждут ответа (+худшее ожидание), Зависшие (число+сумма), Недозвоны сегодня, Открытый
пайплайн, конверсия по стадиям - клик = фильтр доски. Антипаттерны, которых
избегаем: перегруз, спиннеры на весь экран, неуведомлённый ответственный,
неподдерживаемые вложения, финальные стадии колонками.

## Риски

- Лимиты API Авито на массовый импорт неизвестны - импорт с паузами и возобновлением
  по `last_synced_at`, при 429 - пауза и повтор.
- Параллельная сессия правит `server.js` - перед каждой правкой перечитывать живой файл.
- Первый реальный логин Влада - единственная проверка, которую синтетика не заменяет
  (`feedback_verify_before_claiming_done`).
- `client_key varchar(20)`: `avito:<id>` укладывается (15 символов), телефоны 11.
