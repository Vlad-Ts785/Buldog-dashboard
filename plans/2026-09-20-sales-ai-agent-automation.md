# ИИ-агент продаж: от квалификации к автономии

**Зачем:** Влад, 20.09 - "люди не надёжны... нужно идти в сторону снижения человеческого
фактора до минимума. Менеджер может подхватить на этапе когда мы уже почти договорились".
Живой повод - разбор его личного диалога с Рустамом (песок на палетах, деал 148,
`avito:113387903`): Влад сам вёл лид до почти-закрытой сделки, потом передал Ахтамовой.
За ту же неделю - 44% всех отказов (33/75) с причиной "Клиент не отвечает", и в 85% из
них (28/33) была РОВНО ОДНА попытка контакта с нашей стороны - см. разбор недели 20.09
в переписке сессии.

**Как выглядит успех MVP:** ИИ-агент отвечает на первый вопрос о цене (через калькулятор,
не выдумывает), отрабатывает "дорого" одним заходом по методике Влада (ценность, не
скидка), и либо эскалирует человеку по жёсткому списку триггеров, либо явно передаёт
"клиент прогрелся, дальше вручную" - без единого случая, когда клиент узнал цену или
факт мимо реальных данных системы.

## Методика Влада (извлечена из диалога с Рустамом, деал 148)

1. Цена сразу, конкретным числом, без "уточню" - доверие с первой секунды.
2. На просьбу скидки - НЕ давить ценой, продавать ценность (свой парк, персональный
   логист на проект, порядок в документах/НДС). Символическая уступка, не капитуляция.
3. Перед финальной ценой - квалифицирующий вопрос (оплата, реальный график), не
   увиливание, а сбор данных, от которых зависит правильная цена.
4. Твёрдая цена ПОСЛЕ уточнения - может быть ниже первой (была 35000, стала 33000),
   потому что теперь обоснована, не взята с потолка. Простои - отдельно, защита маржи.
5. Переход в личный канал (мессенджер) - соглашаться мгновенно.
6. Передача человеку - в момент "почти готов", не раньше и не позже.

## Что НЕ делаем в v1

- Агент НЕ пишет клиентам сам в Фазе 0 - только скоринг для приоритета уведомления.
- Агент НЕ ведёт объёмные/стратегические сделки НИКОГДА (см. правило ниже) - это не
  следующая ступень автономии, это сознательная постоянная граница.
- Агент НЕ звонит (только текст) до отдельного решения о голосовом канале.
- Агент НЕ трогает договорные условия, отсрочки платежа, претензии, споры.
- Не пытаемся дать полную автономию сразу - только после недель наблюдения на каждой
  ступени (см. фазы).

## Жёсткие правила (не переговорные, действуют с первого дня агента)

- **Цена** - только от калькулятора. Агент получает нижнюю границу (себестоимость +
  минимальная маржа) и стартовую (себестоимость + целевая маржа), двигается ТОЛЬКО
  между ними и ТОЛЬКО вниз от стартовой. Нижнюю границу клиенту не озвучивает никогда.
- **Скидка** - потолок 10-12% от стартовой за один диалог, без комбинирования оснований
  (объём + предоплата + постоянный клиент = одна скидка, не три подряд).
- **Объёмные сделки (аналог Рустама, 10+ рейсов вперёд или "рейсов в месяц/год") -
  НАВСЕГДА зона Влада/руководителей.** Агент даёт рамочную цену за один рейс и сразу
  передаёт - не пытается сам считать оптовую скидку.
- **Сроки** - только из реального состояния парка/планировки (API), никогда "на глаз".
- **НДС/документы** - только из фиксированного, утверждённого текстового блока, не
  генерируются заново каждый раз (юридическая формулировка не должна "плыть").
- **Каждое число в ответе клиенту должно трассироваться к вызову инструмента в этом же
  диалоге** - post-processing фильтр на сервере вытаскивает числа из черновика, сверяет
  с последним результатом калькулятора/API; расхождение - ответ блокируется, не уходит.
- Только человек: оплата постфактум/отсрочка, нестандартный/опасный груз, договорные
  условия, штрафы/претензии, повторные клиенты с историей споров.

## Триггеры автоэскалации (любой один - сразу к человеку)

Молчание клиента >2ч после названной цены (не додавливать самому новой ценой);
агрессивный/эмоциональный тон; юридические слова (договор, претензия, суд, штраф,
страховка); груз вне матрицы типов калькулятора; явная просьба человека/номера
менеджера; 3+ круга торга без сближения позиций хотя бы вдвое; упоминание конкурента с
конкретной ценой; объёмная/долгосрочная сделка (см. правило выше).

## Аудит и откат

Каждое сообщение агента - отдельная запись (цена, id вызова калькулятора/API её
обосновавшего, версия промпта, timestamp). Директору - ежедневная сводка на первой
неделе. Обязателен персональный kill-switch (выключить агента этому клиенту) и
глобальный (выключить для всех новых лидов) - тумблер в CRM, без деплоя. Еженедельный
ручной разбор всех эскалаций и всех диалогов со скидкой у потолка.

## Фазы

### Фаза 0 - эта неделя, БЕЗ автономных ответов клиенту

Расширяем уже задеплоенный (20.09) идл-детект/автоответ в чат Авито: добавляем
классификатор сообщения клиента на признаки готовности к сделке (озвучен объём, сроки,
запрос документов/реквизитов). При срабатывании - уведомление руководителю через MAX
(уже готовый канал, ротация Ахтамова/Гусейнова) помечается как "горячее", не рядовое
"завис чат". Ничего клиенту от ИИ не уходит.

*4 вопроса:* Решает проблему? Частично - ускоряет реакцию человека на самые горячие
случаи уже сейчас. Не код ради кода? Да - переиспользует существующий триггер и канал
уведомлений целиком. Не усложняет? Да, минимальный шаг. Что выкинуто? Сам диалог с
клиентом - агент пока молчит.

### Фаза 1 - MVP, 2-4 недели

Агент отвечает автономно строго в двух точках: (1) первичная квалификация +
цена через калькулятор, (2) один круг отработки "дорого" по методике Влада (ценность,
не скидка). Все жёсткие правила и триггеры выше - активны с первого сообщения. Неделя 1
внутри этой фазы - агент отвечает только на типовые вопросы (габариты/парк/документы/
ориентировочная цена), любой торг сразу к менеджеру, Влад смотрит 100% диалогов
постфактум. Недели 2-3 - разрешаем торг в пределах потолка скидки, финальную передачу
менеджеру всё ещё делает человек вручную по сигналу из CRM.

*Не делаем в Фазе 1:* торг сверх калькулятора; работу с юрлицами/тендерами; больше
одного круга возражений подряд без эскалации; голос.

### Фаза 2 - месяц-два

Расширяем дерево возражений реальными формулировками клиентов из расшифровок Nexara
(RAG для тона/формулировок - плейбук продаж, НИКОГДА для цифр, это разделено строго).
Агент получает доступ к истории звонка того же клиента, если был - не переспрашивает.

### Фаза 3 - при стабильной статистике (0 инцидентов, доля эскалаций в норме)

Агент сам доводит до "передаю менеджеру" без построчного просмотра - только выборочный
аудит (10-20% + все эскалации). Проактивный повторный контакт по расписанию (закрывает
исходную проблему "одна попытка и в отказ" - теперь повторную попытку по времени делает
агент, не зависит от того, вспомнит ли человек).

### Полная автономия (не раньше, отдельное решение)

Расширение на входящие звонки через тот же Nexara-пайплайн в реальном времени.
Объёмные/стратегические сделки как у Рустама - не автоматизируются никогда, это
сознательная постоянная граница, не следующая ступень.

## Метрики успеха (причинные, не общие KPI)

Сравнение "до/после" по существующим когортам, где это возможно (A/B по группам лидов
на Фазе 1): доля отказов "клиент не отвечает" среди чатов с >=2 попытками контакта
(должна расти - это и есть цель, не общая конверсия); доля чатов, дошедших до передачи
менеджеру с уже подтверждённым объёмом/сроками (разгрузка менеджеров); время от первого
сообщения клиента до первой попытки контакта (должно упасть почти до нуля в чатах с
агентом); доля сделок, закрытых после хэндофа из ИИ-диалога, относительно полностью
ручных, при равном контроле по источнику и сегменту груза.
