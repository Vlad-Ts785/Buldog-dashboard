# Договор-заявка из «Задания» - генерация PDF по кнопке

**Зачем:** кнопка «Договор-заявка ⤓» в карточке заявки («Задание», `order-plan-v2.js`)
сейчас placeholder (`soon('Договор-заявка...')`). Влад, 14.09: «пора нам сделать так, чтобы
можно было скачать договор в PDF. Печать подпись у тебя есть, шаблон тоже есть».

**Как выглядит успех v1:** менеджер/логист/admin открывает заявку с заполненным
«Исполнитель (от кого)» (юрлицо своё, например Бульдог), жмёт «Договор-заявка ⤓» - через
пару секунд браузер скачивает настоящий PDF («Разовая договор-заявка на организацию
внутрироссийской автоперевозки грузов»): шапка, реквизиты Бульдога с печатью+подписью
картинками, реквизиты заказчика (что есть в справочнике - остальное пустыми строками, как в
образце Влада), табличная часть с суммой и НДС 22%, таблица условий перевозки, фиксированный
текст «особых условий» 1-10, подпись заказчика (пустое место под роспись). Работает НА ЖИВОМ
VPS без установки чего-либо нового на сервер.

  браузере, без сервера. `doc.addImage(...)` (стандартный метод jsPDF, в проекте пока не
  использован) добавляет печать/подпись картинками.

## Почему НЕ путь из исходного спека 10.09 (docx-шаблон + LibreOffice headless на VPS)

Спек 10.09 предполагал сервер: `.docx` из шаблона (`docx`-библиотека) + конвертация в PDF
через LibreOffice headless. Проверено сегодня на живом VPS:
- `which soffice`/`which libreoffice` - **пусто, не установлен**;
- `api/package.json` - нет `docx`/подобной библиотеки, только
  `cors`/`dotenv`/`express`/`multer`/`mysql2`/`web-push`.
Значит этот путь = ставить LibreOffice на прод-сервер. У этого VPS уже был инцидент нехватки
памяти (MySQL уронило ядро, чинили подкачкой, `project_server_architecture`) - лишний
тяжёлый пакет на маленьком сервере ради рендера одного PDF по кнопке - риск, которого можно
избежать, раз есть рабочая браузерная альтернатива. **Откладываю на v2/по явному запросу**
(например если реально понадобится редактируемый .docx, а не только PDF).
