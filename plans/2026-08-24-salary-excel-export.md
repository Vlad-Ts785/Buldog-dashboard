# Экспорт вкладки «Зарплата» в Excel с живыми формулами

**Создан:** 2026-08-24. **Запросил:** Влад — «нужна возможность выгружать в эксель данные
со страницы зарплата, чтобы сохранялась логика и были прописаны формулы».

## Согласовано с Владом

1. **Формат** — снимок текущего месяца: базовые цифры (выручка, база % своего парка, маржа
   найма и т.д.) вставляются как обычные числа, а каждый шаг расчёта (оклад по сетке, %,
   пороговые премии, итог) — как настоящая Excel-формула, ссылающаяся на эти числа. НЕ полный
   живой движок, который можно скормить произвольным месяцем — это следующий, более рискованный
   шаг, если вообще понадобится.
2. **Охват** — только коммерческий отдел: Ахтамова + Гусейнова (руководители, их личные продажи,
   их команды). БЕЗ Рыщанова/логистов/Васина (другая формула, calcLogist/calcVasin) и БЕЗ
   скрытой строки Цуцурина.

## Почему не «полностью живой» экспорт

Вся эта логика уже дублируется в двух местах (JS во фронтенде здесь, что-то похожее могло бы
понадобиться и в Apps Script) — плодить третью независимую копию через generic IF-деревья в
Excel, которые должны сами определять пороги/группы/историческую версию правил (`useNewRules`
меняется по дате, правила уже минимум дважды точечно правились в этом году), — то же самое
разъезжание копий, что уже дважды роняло зарплату Сурковой (TRAL_MANAGERS) и один раз
INTERNAL_CLIENTS. Снимок с формулами даёт прозрачность и проверяемость («как посчитан оклад»)
без риска, что чужая копия логики в Excel когда-нибудь молча разойдётся с настоящей.

## Источник истины — НЕ переписывать логику, транскрибировать её

Экспорт строится **поверх уже посчитанных и проверенных на экране** объектов `calcHead()` /
`calcMgr()` (см. `files/index.html` ~7642-7772, `renderSalesSalary()` ~7773) — те же вызовы,
что уже рендерят таблицу. Экспорт НЕ пересчитывает бизнес-логику самостоятельно — берёт готовые
числа (`ownProfitBase`, `qualMargin`, `total` и т.д.) и раскладывает их по ячейкам + формулам,
которые при пересчёте Excel'ем ОБЯЗАНЫ дать то же число, что уже показано на экране (это и есть
критерий проверки, см. ниже).

## Устройство листа (на отдел)

Один лист на отдел («Ахтамова», «Гусейнова»). Колонки:

| Колонка | Что | Источник |
|---|---|---|
| A | Сотрудник | `capName(sur)` |
| B | Оборот (месячный, свой+найм) | число, `m.amount` |
| C | Своя выручка | число, `m.own_amount` |
| D | База % своего парка (выручка минус 3 статьи затрат 1С) | число, `m.own_profit` |
| E | Маржа найма квалиф. (≥23%) | число, `m.hired_margin_qualified` |
| F | Оклад (сетка по обороту B) | **формула**: `=IF(B>=10000000,150000,IF(B>=8000000,100000,IF(B>=5000000,50000,IF(B>=2000000,30000,0))))` |
| G | % своего парка (ставка 1.5% или 2% — Цегельников/Савиток) | **формула**: `=ROUND(D*ставка,0)` |
| H | % найма (8% от E) | **формула**: `=ROUND(E*0.08,0)` |
| I | Премия за оборот ≥15М (100т) | **формула**: `=IF(B>=15000000,100000,0)` |
| J | ИТОГО | **формула**: `=F+G+H+I` |

Строка руководителя — **две строки**: «Команда» (агрегат по отделу через `SUM`/`COUNTIF` по
диапазону строк команды на этом же листе) и «Личные продажи» (та же формула-схема, что и
обычный менеджер, но `F=0` всегда — `includeOklad:false` в `calcMgr`). Плюс отдельная строка
«Премия за объём отдела» (порог 30М, `10т × INT(деп.выручка/10М)`) и «ИТОГО по отделу».

Агрегаты руководителя — тоже формулы, не числа:
- `deptOwnProfitBase` = `SUM(D2:D6)` (диапазон строк команды)
- `deptQualMargin` = `SUM(E2:E6)`
- `above2m` (сколько активных ≥2М оборота) = `COUNTIF(B2:B6,">=2000000")`
- `activeCount` = `COUNTIF(B2:B6,">0")`
- `pct08` = `=ROUND(deptOwnProfitBase*0.008,0)`
- `margin2` = `=ROUND(deptQualMargin*0.02,0)`
- `mgrBonus` = `=IF(activeCount>=4,above2m*20000,0)`
- Оклад руководителя фикс. 20000 (число, не формула — не зависит ни от чего).
- Строка «Команда» ИТОГО = `=20000+pct08+margin2+mgrBonus`
- `deptRevTotal` (для премии за объём) = `=SUM(B2:B6)+headOwnTotal` (оборот команды + свой оборот руководителя из строки «Личные продажи»)
- Премия за объём = `=IF(deptRevTotal<30000000,0,INT(deptRevTotal/10000000)*10000)`
- ИТОГО по отделу = `=[Команда]+[Личные продажи]+[Премия за объём]+SUM(J2:J6)`

## Что осознанно НЕ делаем в этом заходе

- Логисты/Рыщанов/Васин/Цуцурин — не в охвате (может стать отдельным планом позже).
- Выбор произвольного периода для экспорта — экспортируем ТЕКУЩИЙ загруженный на экране период,
  тот же что видит Влад. Если понадобится «выгрузить прошлый месяц» — отдельная итерация.
- Старые правила (`useNewRules=false`, до июля 2026) — формулы пишутся под ДЕЙСТВУЮЩИЕ
  (`useNewRules=true`) правила; если Влад попробует экспортировать более старый период, код
  должен явно отказать («экспорт доступен только для периодов с июля 2026») — не тихо генерить
  формулы под другую версию правил без явного второго прохода тестирования.
