## Контекст

Влад параллельно с приложением сотрудников попросил эту фичу как «очень важную вещь».
Настроил ЖИВЬЁМ (03.09, при мне) две ежедневные выгрузки из 1С через FTP-рассылку
отчётов (тот же механизм, что уже несёт заказы/ДЗ/поступления/парк):
- Отчёт «Расшифровка начислений машинистам», отфильтрован по подразделению.
- Два отдельных сценария рассылки - «Водители тралов» и «Водители длинномеров» -
  каждый раз в день, оба льются в `ftp://api.yardhub.ru/uploads_payroll/` под тем же
  логином `receipts_upload`, что уже использует канал поступлений.
- Формат - .xlsx, папка на VPS `/home/receipts_upload/uploads_payroll/` уже создана и
  принимает файлы (первый тестовый файл получен и разобран 03.09 в 16:53 МСК).

**Структура файла (разобран вручную, `openpyxl`):** иерархический 1С-отчёт с
группировками, НЕ плоская таблица:
```
Отдел (3 строки-рефрена: Автотранспортный блок / Автоколонна / Водители тралов)
  Машинист (ФИО) - строка с итогами за период
    [пустая строка - якорь блока "Штрафы ГИБДД"]
      деталь: дата/дата, "Ввод начислений и удержаний водителям NNNNN от ...", сумма
    Машина (марка+модель+госномер) - строка с итогами по этой машине
      деталь: дата, "Таблица заказов NNNNN от ...", оборудование, адрес, км за МКАД,
              часы, сумма
```
Колонки по машинисту (I-U): Км за МКАД, Часы, Работа по заказам, Выслуга лет,
Километраж за МКАД, Начисления (=сумма первых трёх), Выплата аванса/Наличка,
Штрафы ГИБДД, Прочие удержания, Удержания (=сумма трёх), Итого (=Начисления-Удержания),
НДФЛ, К начислению (=Итого-НДФЛ).

Строка 2 листа - "Период: DD.MM.YYYY - DD.MM.YYYY", строка 3 - "Отбор: Подразделение
Равно "X"" (по этой строке различаем тралы/длинномеры в файле, НЕ по имени файла -
шаблон имени в 1С может быть одинаковым для обеих рассылок).

**UI-решение (не переспрашивал у Влада - совпадает с уже established паттерном):**
НЕ отдельное всплывающее окно-каталог, как в 1С на скриншоте, а тот же tab-bar canon,
что уже дважды использован в дашборде («Справочники» - showDirTab, «Поступления» -
showReceiptsTab): страница «Зарплата» получает вкладки сверху «По менеджерам» /
«По машинистам», контент переключается снизу. Однообразно с остальным дашбордом
(см. память feedback_clone_existing_visual_pattern).

## Риски

- **Хрупкость распознавания строк** - иерархия в Excel определяется НЕ явным
  признаком, а тем, какие колонки заполнены/пусты в конкретной строке. Один
  нестандартный случай (машинист без единой поездки за период, отдел без машинистов)
  может сломать парсинг молча. Митигация - санити-гвард (Ревизор-паттерн, как у
  snapshot-vehicle-status.js): сумма всех распознанных машинистов ДОЛЖНА совпадать с
  итоговой строкой отдела - если нет, импорт этого файла падает в errors, не пишет
  частично неверные данные.
- **Деньги реальных людей** - зарплата, не премия/бонус поверх. Ошибка в парсинге
  напрямую искажает то, что человек видит про свою зарплату. Не полагаться на
  визуальную проверку "выглядит похоже" - строго сверять суммы построчно с исходным
  файлом при первой реализации.
- **Имя файла может быть одинаковым для обеих рассылок** - различать ТОЛЬКО по
  содержимому (строка "Отбор"), не по имени.
