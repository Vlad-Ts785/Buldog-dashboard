# Ретроспектива: калькулятор - фидбек по скриншоту, сервер, новый бланк КП

Дата: 2026-08-18

## Что сделали

Влад прислал скриншот реального использования (буровая 110 т, Faymonville) и три правки:
1. Категория Faymonville теперь подбирается автоматически по весу (была причина занижения
   цены - реальный баг, не выдумка: 110 т считало по тарифу 75-100 т вместо 100-120 т).
2. История расчётов сохраняется на сервер (Google Sheets, новый лист "Калькулятор_История")
   с автором, определённым сервером из id_token - не то, что клиент прислал.
3. КП полностью переверстан на фирменный бланк компании (как в приказах), убраны
   декоративные золото/эмодзи прежней версии.

Детали - `plans/2026-08-17-calculator-dashboard-integration.md` (секция "Доработки по
первому фидбеку").

## Что вызвало затруднение

- **Обнаружена чужая недокоммiченная работа при подготовке к деплою Apps Script** -
  сессионные токены (48ч) + перевод чтения заказов на api.yardhub.ru, задеплоено той же
  датой в обход git другой параллельной сессией. По правилу координации из `CLAUDE.md`
  (сравнение `clasp pull` с git HEAD перед push) - сохранил чужую работу отдельным
  sync-коммитом, потом перенёс свои правки поверх через `git apply` (применилось чисто, зон
  пересечения не было). Аналогично при push в `main` - `origin/main` тоже уехал вперёд (та
  же параллельная сессия успела запушить в git), решилось обычным `git merge` без конфликтов
  (auto-merge на всех трёх пересекающихся файлах).
- **Нашёл настоящую stored-XSS сам, при обязательном цикле проверки после фичи** (пункт 4
  CLAUDE.md - "Security review: ПДн, внешние запросы, токены в коде") - `renderServerHist()`
  вставляла адреса/имя менеджера из Sheets прямо в `innerHTML` без экранирования. В старой
  чисто-localStorage версии это было неопасно (атаковать можно было только себя), но теперь
  эти же строки видит ДРУГОЙ человек (admin - вообще все расчёты всех менеджеров) - это
  готовый вектор для внедрения скрипта в чужую авторизованную сессию через обычное поле
  адреса. Исправил (`escHtml_()`) до того, как показывать/пушить фичу как готовую - не
  дожидался, пока Влад заметит сам.
- Бланк КП (`.doc` через HTML-трюк) проверял не кликом по кнопке, а перехватом
  `URL.createObjectURL`/`.click()` в браузерном тестовом инструменте - так видно точное
  содержимое сгенерированного файла без реального скачивания. Этим же способом поймал баг
  задвоенного "г. г." в дате (`toLocaleDateString('ru-RU',{...year:'numeric'})` уже сама
  добавляет "г." - моя ручная добавка была лишней).

## Обучающая подсказка (по CLAUDE.md - расти вместе с работой)

Когда фича становится ОБЩЕЙ (несколько людей видят одни и те же сохранённые данные, не
только сам автор) - старые допущения о безопасности перестают работать автоматически, даже
если код скопирован из уже работавшего места. localStorage-версия истории расчётов была
безопасна не потому, что кто-то её продумал, а потому что единственная жертва возможной
XSS - сам пользователь. Как только те же строки полетели на сервер и стали видны ДРУГИМ
(особенно роли выше - admin), это же самое место кода стало уязвимостью. Правило простое:
при любом переходе "было только моё - стало общее" - отдельно перепроверять экранирование,
даже если сам расчёт/логика не менялись ни на строчку.
