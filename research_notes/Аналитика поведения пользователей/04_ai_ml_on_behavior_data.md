# ИИ/ML на данных о том, как люди работают в интерфейсах: как это обучают лидеры и что реально в 2026

Дата сбора: 26.09.2026. Пометки: [ВЕНДОР] - заявление производителя/маркетинг, не проверено независимо; [НАУКА] - рецензируемая статья или препринт с методикой; [ВТОРИЧНО] - агрегатор/пересказ, первоисточник не открыт; [СТАРОЕ] - данные до 2025 года.

## 1. Классический ML на поведенческих данных: кластеризация, последовательности, отток, фрустрация, task mining

### Takeaway
«Обучение на поведении» в классическом виде - это в основном обучение БЕЗ учителя (кластеризация пользователей по похожести их кликстримов, поиск частых последовательностей, цепи Маркова переходов) плюс правила-эвристики для «фрустрации» (rage click и т.п.). Настоящий ML с учителем (отток, фрустрация) у лидеров работает на сотнях тысяч сессий и часто обучается на метках, которые сами получены правилами. В task mining (UiPath) задачи находят через OCR экрана + векторные представления слов + кластеризацию шагов и поиск повторяющихся последовательностей.

### Cited Findings
- [НАУКА][СТАРОЕ] Wang et al. (CHI 2016, UCSB) - система кластеризации кликстримов без учителя: граф похожести, где узлы - пользователи, рёбра взвешены похожестью их последовательностей кликов; иерархическая кластеризация с итеративным «вырезанием» доминирующих признаков, кластеры подписываются через статистику хи-квадрат; проверено на двух реальных трассах соцсетей (142 млн событий); нашла ранее неизвестные типы поведения («спящие» пользователи, «враждебные болтуны»); пользовательский тест показал, что люди легко интерпретируют найденные группы - [ACM DL](https://dl.acm.org/doi/10.1145/2858036.2858107); [PDF](https://gangw.cs.illinois.edu/click_ch16.pdf)
- [НАУКА][СТАРОЕ] Там же - обоснование, зачем вообще ML вместо опросов: опросы ограничены масштабом, люди не умеют сами себя классифицировать, опрос проверяет только заранее известные гипотезы; ранние работы изучали «пути навигации» и цепи Маркова для предсказания популярных страниц - [PDF](https://gangw.cs.illinois.edu/click_ch16.pdf). Код проекта (рекурсивная иерархическая кластеризация) выложен - [Clickstream Project](https://sandlab.cs.uchicago.edu/clickstream/index.html)
- [НАУКА][СТАРОЕ] Цепи Маркова / матрицы переходов, построенные из частых последовательных паттернов, используются для предсказания следующего шага пользователя (например, следующей страницы) - [Clickstream Prediction Using Sequential Stream Mining Techniques with Markov Chains, IDEAS 2016](https://dl.acm.org/doi/10.1145/2938503.2938535); есть готовый R-пакет `clickstream` для анализа кликстримов цепями Маркова - [ResearchGate](https://www.researchgate.net/publication/308984888_R_Package_clickstream_Analyzing_Clickstream_Data_with_Markov_Chains)
- [НАУКА] Прогноз оттока: CNN и трансформеры на временных рядах взаимодействий «пользователь-продукт» для раннего предсказания ухода - [arXiv 2309.14390](https://arxiv.org/abs/2309.14390)
- [НАУКА] Фрустрация ML-моделью (препринт, 23.12.2025, J. Joseph): 5,4 млн событий, 304 881 сессия реального e-commerce; метка «фрустрация» задана ПРАВИЛАМИ (серии яростных кликов, «U-развороты» навигации, брошенная корзина, мучения с поиском, долгие блуждания); XGBoost на табличных признаках - ~90% точности, ROC AUC 0,958; LSTM на полной последовательности - ~91%, ROC AUC 0,971; по первым 20-30 действиям LSTM уже надёжно предсказывает - [arXiv 2512.20438](https://arxiv.org/abs/2512.20438)
- [ВЕНДОР] FullStory определяет сигналы фрустрации правилами, а не обучением: Rage Click - несколько быстрых кликов в одну область; Dead Click - клик по неинтерактивному элементу без эффекта; Error Click - клик прямо перед JS-ошибкой; Thrashed Cursor - хаотичное/круговое движение мыши (признак растерянности или ожидания загрузки) - [FullStory Help Center](https://help.fullstory.com/hc/en-us/articles/360020624154-Rage-Clicks-Error-Clicks-Dead-Clicks-and-Thrashed-Cursor-Frustration-Signals). Есть отдельная инструкция, как вручную исключать элементы из классификации rage/dead click (ложные срабатывания) - [FullStory Help](https://help.fullstory.com/hc/en-us/articles/360020622734-Prevent-elements-from-being-classified-as-Rage-or-Dead-Clicks-via-Fullstory-Settings-or-via-code)
- [ВЕНДОР] LogRocket Galileo: модели «обучены на миллиардах точек данных», чтобы предсказывать, ВАЖНА ли найденная проблема (по импакту, частоте и «годам обратной связи пользователей»); проблема считается серьёзной только если случилась минимум 3 раза; LLM пишет человеческое описание проблемы; разметка людьми («высокий импакт/низкий/игнор») дообучает приоритизацию; модель серьёзности использует только обезличенные счётчики действий, данные сессий, отправленные в LLM, «не используются для обучения» - [LogRocket Docs: Galileo](https://docs.logrocket.com/docs/galileo)
- [ВЕНДОР] UiPath Task Mining: движок объединяет OCR экрана и word2vec-представления слов в единое представление всего экрана, затем кластеризует шаги/скриншоты, чтобы решить, какие действия «одинаковые» - [патент US 11934416](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11934416). В режиме Unassisted алгоритм «ищет повторы одной и той же последовательности шагов», без бизнес-контекста; значимой считается задача от 5 действий, 3 шагов и 30 секунд; результаты могут дробить одну реальную задачу на несколько и содержать «нерелевантные для бизнеса» задачи; «не гарантирует обнаружение всего» - [UiPath Docs: Unassisted Task Mining](https://docs.uipath.com/task-mining/automation-suite/2023.10/user-guide/unassisted-task-mining-analysis-guide). Модели не нужно, чтобы задачу выполняли несколько записываемых пользователей - [UiPath FAQ](https://docs.uipath.com/task-mining/automation-suite/2024.10/user-guide/faq)
- [НАУКА] Robotic Process Mining (академическая линия task mining): конвейер из 5 шагов - предобработка/нормализация, сегментация лога на «рутины», выделение кандидатов, оценка автоматизируемости, агрегация - [Robotic Process Mining: Vision and Challenges, BISE](https://link.springer.com/article/10.1007/s12599-020-00641-4). Сегментация - ключевая сложность (какие действия относятся к какой задаче); подходы: word2vec + поиск мотивов во временных рядах без предварительных знаний - [Springer 2025](https://link.springer.com/chapter/10.1007/978-3-032-02936-2_20); кластеризация по совместной встречаемости типов операций - [Springer 2021](https://link.springer.com/chapter/10.1007/978-3-030-85469-0_18); интерактивная сегментация с человеком - [Springer](https://link.springer.com/chapter/10.1007/978-3-030-91431-8_5)

### Inferences
- «Модель фрустрации» с AUC 0,97 во многом воспроизводит правила, из которых сделана метка (метка = правила rage burst/U-turn и т.д.). Независимой «правды» о раздражении человека там нет. Практический вывод: правила и есть основной детектор, ML лишь обобщает их и срабатывает раньше.
- Лидеры рынка используют ML не столько для ОБНАРУЖЕНИЯ трения (это правила), сколько для РАНЖИРОВАНИЯ (что важно) и для текста (LLM-описание). У LogRocket ранжирование обучено на данных тысяч клиентов - маленькая компания такую модель сама не повторит, но может повторить логику «порог повторов + ручная разметка важности».
- Кластеризация пользователей (Wang et al.) имеет смысл при тысячах-миллионах пользователей; при ~15 сотрудниках «кластер» - это 2-3 человека, и его проще описать глазами.

### Gaps
- Не найдено первичных описаний ML у Quantum Metric и Contentsquare (как именно считаются их «frustration scores») - только маркетинговые страницы.
- Не найдено хорошего первичного источника по детекции аномалий в журналах UI-событий именно для внутренних бизнес-систем (есть общая литература по аномалиям, но не проверялась в этом сборе).

## 2. Волна LLM/агентных функций в инструментах аналитики 2024-2026: что именно делают, насколько точны, ограничения

### Takeaway
К 2025-2026 все крупные вендоры (PostHog, Microsoft Clarity, Amplitude, Contentsquare, FullStory, LogRocket, Mixpanel, Quantum Metric) добавили три типа функций: (1) пересказ одной/нескольких записей сессий текстом, (2) вопрос на естественном языке → фильтры/график, (3) «агенты», которые сами регулярно просматривают выборку сессий и присылают находки со ссылками на доказательства. НИ ОДИН вендор не публикует количественную точность своих пересказов; в документации стоят оговорки «ИИ может ошибаться», а у лучших - ссылки на конкретные моменты-доказательства и оценка уверенности.

### Cited Findings
- [ВЕНДОР] PostHog AI (бывш. Max): пересказ сессии строится по ПОТОКУ СОБЫТИЙ (просмотры страниц, клики, ввод, прокрутка, ошибки, кастомные события), а не по видео - поэтому быстро даже на длинных сессиях; полезно для сравнения групп A/B-теста - [PostHog Docs: Session summaries](https://posthog.com/docs/session-replay/session-summaries-ai); запрос словами («кто rage-кликал на странице цен») превращается в фильтры записей - [PostHog Docs: Find replays with AI](https://posthog.com/docs/session-replay/find-replays-ai); анонс пересказов - июль 2025 - [PostHog в X](https://x.com/posthog/status/1950859281231745137)
- [ВЕНДОР] PostHog Replay Vision: «сканеры» из трёх частей - промпт (что искать), тип ответа, фильтры записей; модель «смотрит каждую подходящую запись непрерывно», отправляя ВИДЕО + сырые события в Google Gemini; результат пишется как событие `$recording_observed` с рассуждением модели, ссылками на моменты записи, уверенностью и стоимостью наблюдения; прямо сказано, что только Vision смотрит видео, остальные три автоматизации читают события и «знают, что люди сделали, но не что им показал экран» - [PostHog pocket guide: Replay Vision](https://posthog.com/pocket-guides/session-replay/replay-vision)
- [ВЕНДОР] Microsoft Clarity Copilot: Session Insights - текстовый пересказ одной записи; Grouped Session Insights - сводка по группе (например, «Топ-10 записей» по любым фильтрам) - [Microsoft Learn: Grouped](https://learn.microsoft.com/en-us/clarity/copilot/grouped-session-insights). Ограничения (док. от 23.10.2025): нет для мобильных приложений, нет для сессий короче 5 секунд, нельзя делиться/скачивать; прямая оговорка: генеративные модели «могут неверно интерпретировать или генерировать неверную информацию», есть кнопки оценки «полезно/нет» (палец вверх/вниз) - [Microsoft Learn: Session Insights](https://learn.microsoft.com/en-us/clarity/copilot/session-insights). Позже анонсирован Copilot для мобильных проектов - [Clarity Blog](https://clarity.microsoft.com/blog/announcing-copilot-in-microsoft-clarity-for-mobile-apps/) (с ограничением из документации частично расходится - уточнять по дате)
- [ВЕНДОР] Amplitude: агенты в открытой бете с июня 2025 (Dashboard Agent и Session Replay Agent), плюс MCP-сервер для подключения поведенческих данных к внешним ИИ-инструментам (октябрь 2025) - [SiliconANGLE](https://siliconangle.com/2025/10/21/amplitude-introduces-mcp-ai-agents-automate-behavioral-data-analysis/); [Amplitude press: MCP](https://amplitude.com/press/amplitude-brings-behavioral-data-into-ai-tools-with-mcp-launch). Февраль 2026: «первый полностью автономный агент аналитики», Global Agent + 4 специализированных (дашборды, сессии, эксперименты, обратная связь); Session Replay Agent «непрерывно просматривает сотни сессий, находит скрытое трение, оценивает влияние на выручку, рекомендует исправления» - это маркетинговая формулировка - [Amplitude press, 16.02.2026](https://amplitude.com/press/amplitude-introduces-agentic-ai-analytics-for-the-next-era-of-product-experiences); Session Replay Agent v2 - GA - [Amplitude changelog](https://amplitude.com/releases/session-replay-agent-v2)
- [ВЕНДОР] Amplitude Session Replay Agent, документация: вход - воронка или событие + необязательные указания («смотри на новую фичу»); агент «сэмплирует» записи (объём выборки не указан); выход - находки с оценкой импакта и ссылками на элементы UI, подборки клипов-доказательств, рекомендации, процент затронутых пользователей; ограничения: зависит от срока хранения записей, часть элементов замаскирована, «HTML и селекторы берутся из выборки сессий и могут не отражать все варианты» страницы, большие запросы медленные или падают, нативные мобильные приложения не поддерживаются; заявлений о точности и предупреждений о галлюцинациях НЕТ - [Amplitude Docs](https://amplitude.com/docs/amplitude-ai/session-replay-agent)
- [ВЕНДОР] Contentsquare Sense (13.05.2025): агент, который «планирует, анализирует и действует»; мульти-сессионные ИИ-сводки «ключевых паттернов, проблем и точек трения», генерация опросов, анализ Voice of Customer; опрос самого вендора: у >37% команд 26-50% рабочего времени уходит на поиск и проверку данных - [Contentsquare press](https://contentsquare.com/press/contentsquare-announces-sense-ai-agent/)
- [ВЕНДОР][ВТОРИЧНО] FullStory StoryAI: «Opportunities» сами подсвечивают сигналы фрустрации, провалы и аномалии в воронках с оценкой бизнес-импакта; «Ask StoryAI» - встроенный аналитик вопросов-ответов - [FullStory blog (сравнение с Quantum Metric)](https://www.fullstory.com/blog/fullstory-vs-quantum-metric/). Quantum Metric Felix AI - агентная система на Google Gemini (по страницам сравнения вендора) - [Quantum Metric compare](https://www.quantummetric.com/compare/fullstory-vs-quantum-metric)
- [ВЕНДОР] LogRocket: Galileo с лета 2024 делает пересказы сессий - [LogRocket blog, Summer '24](https://blog.logrocket.com/product-management/galileo-ai-summer-24/); «Ask Galileo» отвечает на вопросы об опыте пользователей - [LogRocket blog](https://blog.logrocket.com/introducing-ask-galileo/); Galileo «прогоняет события сессии», задаёт сам себе вопросы о происходящем и сводит ответы в описание проблемы - [LogRocket Galileo](https://logrocket.com/products/galileo-ai)
- [ВЕНДОР] Mixpanel Spark (теперь «Mixpanel Agent») - вопросы словами → отчёт - [Mixpanel blog](https://mixpanel.com/blog/spark-bringing-generative-ai-to-mixpanel/); [Mixpanel Docs](https://docs.mixpanel.com/docs/mixpanel-agent); вендор заявляет тестирование точности до выпуска и мониторинг через оценки «полезно/нет» (палец вверх/вниз), ответы «могут содержать ошибки» - [Mixpanel AI compliance](https://mixpanel.com/legal/ai-compliance/); Session Replay развивается в «слой понимания» с автосводками паттернов - [Mixpanel blog](https://mixpanel.com/blog/session-replay-updates/)

### Inferences
- Паттерн, общий для всех: правила/счётчики находят кандидатов → LLM пишет текст → человек подтверждает (оценки «полезно/нет» (палец вверх/вниз), триаж). LLM здесь «читатель и рассказчик», а не детектор.
- Отсутствие опубликованной точности - системный признак: вендоры продают экономию времени на просмотре записей, а не измеримую корректность выводов. Самая честная реализация - PostHog Vision (цитаты на моменты записи + уверенность + цена наблюдения), её стоит брать как образец дизайна.
- Большинство функций сделано для сайтов/продуктов с тысячами анонимных посетителей, где главный вопрос - конверсия. Внутренняя CRM с 15 известными сотрудниками - другая задача: там пересказ «что сделал Иван в 14:03» близок к слежке (см. раздел 5).

### Gaps
- Нет ни одной независимой оценки точности пересказов сессий (PostHog, Clarity, Amplitude, Contentsquare) - ни у вендоров, ни в найденной научной литературе.
- Hotjar AI: надёжных первичных данных о функциях и ограничениях в этом сборе не найдено.
- Первичный пресс-релиз Amplitude от 16.02.2026 не открылся (403 на BusinessWire), формулировки взяты из поисковой выдачи с сайта Amplitude.

## 3. Обучение ИИ-агентов на демонстрациях людей в интерфейсах: датасеты, лаборатории, RPA

### Takeaway
Лаборатории учат агентов «работать в интерфейсах» на четырёх видах данных: (1) оплачиваемые демонстрации нанятых людей (Rico, Mind2Web, AndroidControl, CUA-Suite), (2) синтетические среды + обучение с подкреплением (OpenAI CUA, Anthropic computer use), (3) реальные рабочие процессы пользователей продукта (ScribeAgent - 6 млрд токенов из Scribe), (4) демонстрация «на лету» без переобучения модели - агент извлекает показанный пример из памяти (Microsoft UFO, Google Mariner «Teach & Repeat»). Для маленькой компании применим только четвёртый вариант.

### Cited Findings
- [НАУКА][СТАРОЕ] Rico (UIST 2017): ~72 тыс. уникальных экранов из 9,7 тыс. Android-приложений (27 категорий), 10,8 тыс. трасс взаимодействия, ~3 млн размеченных элементов; собрано 13 нанятыми через Upwork людьми + автоматическим агентом; задуманные применения - поиск дизайна, генерация макетов и кода, моделирование взаимодействия, предсказание восприятия - [ACM DL](https://dl.acm.org/doi/10.1145/3126594.3126651); ретроспектива использования - [Google Research](https://research.google/pubs/an-early-rico-retrospective-three-years-of-uses-for-a-mobile-app-dataset/)
- [НАУКА][СТАРОЕ] Mind2Web (NeurIPS 2023, spotlight): 2 350 задач на 137 реальных сайтах из 31 области; фильтрация сырого HTML маленькой моделью заметно повышает эффективность LLM - [arXiv 2306.06070](https://arxiv.org/abs/2306.06070); [сайт проекта](https://osu-nlp-group.github.io/Mind2Web/)
- [НАУКА][СТАРОЕ] WebArena: 812 длинных задач в воспроизводимой веб-среде; лучший агент на GPT-4 - 14,41% успеха против 78,24% у людей (2023) - [arXiv 2307.13854](https://arxiv.org/pdf/2307.13854)
- [НАУКА][СТАРОЕ] OmniACT (2024): 9 802 задачи в 38 настольных приложениях и 27 сайтах (macOS/Windows/Linux); GPT-4 - лишь 15% от уровня человека - [arXiv 2402.17553](https://arxiv.org/abs/2402.17553)
- [НАУКА] AndroidControl (Google DeepMind, NeurIPS 2024): 15 283 демонстрации, 14 548 уникальных задач, 833 приложения, инструкции двух уровней (высокоуровневая цель и пошаговые); дообучение масштабируется ВНУТРИ домена («устойчивость, возможно, достижима просто сбором данных»), но ВНЕ домена растёт намного медленнее - для высокоуровневых задач «одного дообучения на большем объёме данных может быть недостаточно» - [arXiv 2406.03679](https://arxiv.org/abs/2406.03679)
- [НАУКА] CUA-Suite (25.03.2026): ~55 часов видео (6 млн кадров, 30 fps) с кинематикой курсора, 10 000 задач, показанных людьми, в 87 приложениях, многоуровневые аннотации рассуждений; GroundCUA - 56 тыс. скриншотов с 3,6 млн размеченных элементов; современные модели проваливают ~60% задач в профессиональных настольных приложениях; предыдущий крупнейший открытый набор (ScaleCUA) - меньше 20 часов - [arXiv 2603.24440](https://arxiv.org/abs/2603.24440)
- [НАУКА] ScribeAgent (ноябрь 2024, CMU + Scribe): дообучение открытых LLM на «производственных данных рабочих процессов» из продукта Scribe - более 250 доменов, 6 млрд токенов; SOTA по прямой генерации на Mind2Web, +7,3% успеха на WebArena относительно лучших текстовых агентов; в аннотации вопросы приватности не обсуждаются - [arXiv 2411.15004](https://arxiv.org/abs/2411.15004). Это самый близкий документированный пример «компания обучила агента на реальных трассах работы своих пользователей».
- [ВЕНДОР][СТАРОЕ] OpenAI CUA / Operator (январь 2025): зрение GPT-4o + рассуждение, обученное обучением с подкреплением; OSWorld 38,1% (человек 72,4%), WebArena 58,1%, WebVoyager 87% - [OpenAI: Computer-Using Agent](https://openai.com/index/computer-using-agent/); [Introducing Operator](https://openai.com/index/introducing-operator/). Состав обучающих данных OpenAI не раскрывает; утверждения вторичных сайтов о «supervised для восприятия + RL на демонстрациях» не подтверждены первоисточником - [ZBrain, вторично](https://zbrain.ai/cua-models/)
- [ВЕНДОР][СТАРОЕ] Anthropic (22.10.2024): Claude учили на «нескольких простых программах, вроде калькулятора и текстового редактора», без доступа к интернету во время обучения; критичным было научить модель точно считать пиксели; OSWorld 14,9% (следующая модель - 7,7%, люди - 70-75%); «медленно и часто с ошибками» - [Anthropic: Developing computer use](https://www.anthropic.com/news/developing-computer-use)
- [ВТОРИЧНО] Google Project Mariner: 83,5% на WebVoyager при запуске (декабрь 2024); с Google I/O 2025 - «Teach & Repeat»: агент один раз смотрит, как человек выполняет процесс, и повторяет его на похожих задачах - [Slashdot](https://tech.slashdot.org/story/24/12/11/1648248/google-unveils-project-mariner-ai-agents-to-use-the-web-for-you); [AI Tinkerers](https://aitinkerers.org/technologies/google-project-mariner) (первичную страницу DeepMind открыть не удалось)
- [НАУКА] Microsoft UFO (NAACL 2025): двухагентная схема для Windows (скриншот + дерево элементов управления); «экспертность» в приложении через RAG из справки, поиска и ЧЕЛОВЕЧЕСКИХ ДЕМОНСТРАЦИЙ, записанных штатным Windows Step Recorder - т.е. демонстрация подмешивается в контекст, а не переобучает модель - [arXiv 2402.07939](https://arxiv.org/html/2402.07939v5); развитие - UFO2 «Desktop AgentOS» - [arXiv 2504.14603](https://arxiv.org/pdf/2504.14603)
- [ВТОРИЧНО] Состояние на сентябрь 2026: по агрегатору BenchLM лидеры OSWorld-Verified (исправленная версия бенчмарка от июля 2025) набирают 85-86%, т.е. выше исходной человеческой планки 72,36% - [BenchLM.ai](https://benchlm.ai/benchmarks/osworld-verified). Одновременно выходят работы о том, что бенчмарки неверно оценивают агентов - [arXiv 2607.28367](https://arxiv.org/pdf/2607.28367) (прочитан только заголовок); появилось предобучение на неразмеченных видео работы людей за компьютером - [VideoAgentTrek, arXiv 2510.19488](https://arxiv.org/pdf/2510.19488) (прочитан только заголовок)
- [ВЕНДОР] RPA-линия (process discovery для автоматизации): UiPath Task Mining записывает варианты известной задачи, кластеризует и сливает трассы, строит граф задачи с вариантами и статистикой - [UiPath Docs: Introduction](https://docs.uipath.com/task-mining/automation-cloud/latest/user-guide/introduction-as); детали алгоритма - в разделе 1.

### Inferences
- «Как лучшие компании обучают системы изучать работу живых людей» - на практике это ДВЕ разные индустрии: (а) аналитика поведения (понять людей, где им плохо) - правила + LLM-пересказ; (б) агенты компьютерного использования (заменить людей в рутине) - демонстрации тысяч нанятых исполнителей + RL в песочницах. Путать их вредно: у маленькой компании нет данных для (б), а (а) не требует обучения собственных моделей вообще.
- Тренд 2025-2026 - от «обучить модель на демонстрациях» к «показать один раз и положить в контекст» (UFO RAG, Mariner Teach & Repeat). Для внутренней CRM это значит: описанный текстом эталон процесса («как правильно оформить заявку») уже можно давать готовой LLM как инструкцию-сравнение без какого-либо обучения.
- Даже при 15 тыс. демонстраций (AndroidControl) обобщение на новые задачи слабое, а на профессиональных настольных программах провал ~60% (CUA-Suite) - нишевые бизнес-интерфейсы остаются трудными для агентов.

### Gaps
- Не найдено первичных данных о том, использует ли OpenAI/Anthropic/Google реальные трассы пользователей своих продуктов для обучения агентов (раскрываются только синтетические среды/RL и нанятые демонстраторы).
- Первичная страница Google DeepMind по Project Mariner не открылась - цифры взяты из вторичных источников.
- Цифры лидерборда OSWorld-Verified 2026 - только агрегатор, не проверены по первичным отчётам.

## 4. Реальность объёма данных: что работает на малых данных (десятки пользователей) и что - на больших

### Takeaway
Всё, что в индустрии называется «ML на поведении», построено на сотнях тысяч-миллиардах событий от тысяч-миллионов людей (142 млн событий у Wang et al., 305 тыс. сессий в модели фрустрации, «миллиарды точек» у LogRocket, 15 тыс. демонстраций в AndroidControl - и даже этого мало для обобщения). На малых данных работают: правила-эвристики с порогами повторов, описательная статистика последовательностей (счётчики переходов) и LLM как «аналитик-читатель» с заранее заданной схемой категорий (дедуктивное кодирование), где LLM сравним с людьми - плюс обязательная ручная проверка.

### Cited Findings
- [НАУКА] Масштабы «обучаемых» систем: 142 млн событий (две соцсети) - [Wang et al., CHI 2016](https://gangw.cs.illinois.edu/click_ch16.pdf); 5,4 млн событий / 304 881 сессия для модели фрустрации - [arXiv 2512.20438](https://arxiv.org/abs/2512.20438); «миллиарды точек данных» для модели важности - [LogRocket Docs](https://docs.logrocket.com/docs/galileo) [ВЕНДОР]
- [НАУКА] Даже 15 283 демонстрации не дают надёжного обобщения на новые высокоуровневые задачи - [AndroidControl, arXiv 2406.03679](https://arxiv.org/abs/2406.03679)
- [ВЕНДОР] Пороги вместо обучения: LogRocket считает проблему серьёзной только при ≥3 повторах - [LogRocket Docs](https://docs.logrocket.com/docs/galileo); UiPath отсекает шум порогом «≥5 действий, ≥3 шагов, ≥30 секунд» и ищет повторяющиеся последовательности, не требуя нескольких пользователей - [UiPath Docs](https://docs.uipath.com/task-mining/automation-suite/2023.10/user-guide/unassisted-task-mining-analysis-guide); [UiPath FAQ](https://docs.uipath.com/task-mining/automation-suite/2024.10/user-guide/faq)
- [ВЕНДОР] Human-in-the-loop как замена разметки: триаж «высокий/низкий импакт/игнор» улучшает рекомендации Galileo - [LogRocket Docs](https://docs.logrocket.com/docs/galileo); оценки «полезно/нет» (палец вверх/вниз) в Clarity - [Microsoft Learn](https://learn.microsoft.com/en-us/clarity/copilot/session-insights) и Mixpanel - [Mixpanel AI compliance](https://mixpanel.com/legal/ai-compliance/)
- [ВЕНДОР] Качество данных важнее модели: для точных ответов Mixpanel советует убрать дубли событий/свойств и давать событиям простые различимые имена; инструмент лучше отвечает на «что», чем на «почему» - [Mixpanel Docs](https://docs.mixpanel.com/docs/mixpanel-agent) (по поисковой выдаче; точная страница с формулировкой не открыта)
- [НАУКА] LLM как кодировщик текстов: в слепом сравнении при ДЕДУКТИВНОМ кодировании (по заданной схеме категорий) LLM дали 93,5% совпадения с экспертным консенсусом (κ = 0,34) против 92,7% (κ = 0,34) у слепых людей-кодировщиков; при ИНДУКТИВНОЙ генерации тем результаты менее стабильны, особенно где нужен тон и нюанс - [PLOS Digital Health / PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC13048440/). Появляются работы о том, что «согласие не равно качеству» - [arXiv 2607.28890](https://arxiv.org/pdf/2607.28890) (прочитан только заголовок)
- [ВЕНДОР/НАУКА] Anthropic Clio: LLM-конвейер «извлечь признаки → сгруппировать по смыслу → LLM пишет название и описание кластера → иерархия» на 1 млн диалогов; согласие с классификацией команды Trust & Safety r = 0,71 - [Anthropic: Clio](https://www.anthropic.com/research/clio)

### Inferences
- Для ~15 сотрудников и сотен-тысяч событий в неделю: обучать собственную ML-модель (кластеризация людей, прогноз оттока, модель фрустрации) статистически бессмысленно - нет ни объёма, ни меток, а каждый «кластер» - это 1-3 знакомых человека. Правильный уровень: SQL-счётчики и правила (как у FullStory/LogRocket) + LLM для группировки свободного текста (тексты ошибок сохранения, пустые поисковые запросы) по заданной схеме категорий.
- Каппа 0,34 при 93% совпадения означает, что категории несбалансированы и «согласие» во многом случайно - даже хороший LLM-классификатор нужно выборочно проверять человеком, а не принимать на веру.
- Данные о бизнес-записях с временными метками (заявки, сделки) для маленькой компании ценнее UI-кликов: их меньше, но каждое событие осмысленно; «process mining» по ним (время между этапами, возвраты назад) делается обычным SQL без ML.

### Gaps
- Не найдено исследований, специально измеряющих, с какого объёма данных (число пользователей/событий) кластеризация или модели последовательностей начинают давать устойчивый результат во внутренних корпоративных системах.
- Точная формулировка Mixpanel про «чистые имена событий» взята из поисковой выдачи, страница не открывалась.

## 5. Подводные камни: приватность, смещения, переинтерпретация, эффект Гудхарта, дрейф после смены UI

### Takeaway
Главные риски документированы хорошо: запись сессий утекает персональные данные (маскирование несовершенно даже у лидеров); электронный мониторинг сотрудников по метаанализу 94 выборок НЕ повышает производительность, но повышает стресс; ИИ-выводы строятся на выборках и могут не отражать все варианты интерфейса; точность пересказов нигде не измерена. Про дрейф моделей после изменения интерфейса прямых исследований не найдено - есть лишь косвенные признаки в документации вендоров.

### Cited Findings
- [НАУКА][СТАРОЕ] Принстон, «No boundaries» (2017, Englehardt, Acar, Narayanan): скрипты записи сессий собирают нажатия клавиш, движения мыши и всё содержимое страницы, текст форм - ДО отправки формы; найдены на 482 сайтах из топ-50 000 Alexa; автоматическое скрытие персональных данных «несовершенно и частично» (утекали пароли, данные карт, медицинские сведения) - [Princeton CITP](https://blog.citp.princeton.edu/2017/11/15/no-boundaries-exfiltration-of-personal-data-by-session-replay-scripts); гайд для специалистов по приватности - [Future of Privacy Forum](https://fpf.org/blog/understanding-session-replay-scripts-a-guide-for-privacy-professionals/)
- [ВЕНДОР] Даже маскирование ПДн средствами ИИ ошибается: у UiPath алгоритм «может неверно пометить или не пометить что-то как ПДн» (текст не распознан OCR, обрезан, нет контекста) - [UiPath Docs](https://docs.uipath.com/task-mining/automation-suite/2023.10/user-guide/unassisted-task-mining-analysis-guide); Anthropic про Clio: «возможно, наши системы не поймают некоторые виды частной информации» - [Anthropic: Clio](https://www.anthropic.com/research/clio)
- [ВЕНДОР] Практика разделения: LogRocket - данные сессий, отправленные в LLM, не используются для обучения; модель серьёзности работает только на обезличенных счётчиках - [LogRocket Docs](https://docs.logrocket.com/docs/galileo)
- [НАУКА] Эффект мониторинга/Гудхарта: метаанализ Ravid et al. (Personnel Psychology, 2023; 94 независимые выборки, 23 461 человек) - «нет доказательств, что электронный мониторинг улучшает производительность»; мониторинг связан с ростом стресса независимо от его характеристик; при более прозрачном и менее инвазивном мониторинге отношение работников лучше - [Wiley](https://onlinelibrary.wiley.com/doi/abs/10.1111/peps.12514); [препринт на сайте Microsoft Research](https://www.microsoft.com/en-us/research/wp-content/uploads/2020/07/NFW-Ravid-et-al.pdf). Второй метаанализ по той же теме (удовлетворённость, стресс, производительность, контрпродуктивное поведение) - [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S2451958822000616) (выводы не проверялись в этом сборе)
- [ВЕНДОР] Переинтерпретация/выборка: у Amplitude агент сэмплирует записи, «HTML и селекторы берутся из выборки и могут не отражать все варианты», часть элементов замаскирована - [Amplitude Docs](https://amplitude.com/docs/amplitude-ai/session-replay-agent); Clarity: генеративный ИИ «может неверно интерпретировать» - [Microsoft Learn](https://learn.microsoft.com/en-us/clarity/copilot/session-insights); PostHog: агенты, читающие события, не знают, что человек видел на экране - [PostHog](https://posthog.com/pocket-guides/session-replay/replay-vision)
- [ВЕНДОР] Ложные срабатывания правил требуют ручной настройки (исключение элементов из rage/dead click) - [FullStory Help](https://help.fullstory.com/hc/en-us/articles/360020622734-Prevent-elements-from-being-classified-as-Rage-or-Dead-Clicks-via-Fullstory-Settings-or-via-code); task mining дробит одну задачу на несколько, если люди выполняют её по-разному - [UiPath Docs](https://docs.uipath.com/task-mining/automation-suite/2023.10/user-guide/unassisted-task-mining-analysis-guide)
- [НАУКА] Смещение по домену: агенты, обученные на массовых сайтах/приложениях, плохо переносятся на новые и профессиональные интерфейсы (медленный рост вне домена в AndroidControl; ~60% провалов в профессиональных настольных программах в CUA-Suite) - [arXiv 2406.03679](https://arxiv.org/abs/2406.03679); [arXiv 2603.24440](https://arxiv.org/abs/2603.24440)

### Inferences
- Во внутренней системе с поимённо известными сотрудниками поведенческая аналитика становится мониторингом персонала. По метаанализу это не даёт роста результатов, но даёт стресс; как только сотрудники узнают, что считается, например, «пустой поиск» или «заблокированный клик», метрика начнёт оптимизироваться сама по себе (эффект Гудхарта). Безопаснее агрегировать по страницам/функциям («где интерфейс мешает»), а не по людям, и открыто сказать команде, что и зачем собирается.
- Дрейф после смены UI: любое правило или ИИ-вывод, привязанный к селекторам/названиям кнопок, ломается при редизайне; при частых выкатках сравнение «неделя к неделе» будет ловить изменения интерфейса, а не поведения. Нужна отметка версии/даты выкатки рядом с событиями.
- Пересказ одной сессии конкретного человека LLM-ом - наиболее рискованный вид вывода: неизмеренная точность + персональный характер.

### Gaps
- Не найдено исследований, прямо измеряющих дрейф поведенческих моделей/правил после редизайна интерфейса.
- Не найдено исследований Гудхарт-эффекта именно для UI-метрик (есть только общий метаанализ электронного мониторинга).
- Российская правовая специфика (152-ФЗ, передача данных в зарубежные LLM API) в этом сборе сознательно не исследовалась - это отдельная тема.

## 6. Рекомендации для маленькой команды: как использовать LLM для анализа собственных журналов событий

### Takeaway
Документированные образцы (Clio у Anthropic, «сканеры» PostHog Replay Vision, порог ≥3 повторов + триаж у LogRocket, агент Amplitude «область + указания + доказательства») складываются в простой рецепт без обучения собственных моделей: детерминированная выборка и счётчики в SQL → LLM группирует и описывает по заданной схеме категорий → каждая находка со ссылками на конкретные события и уровнем уверенности → человек отмечает полезно/нет → сравнение с прошлым периодом ищет НОВЫЕ паттерны.

### Cited Findings
- [ВЕНДОР/НАУКА] Clio: извлечение признаков из каждой записи → группировка похожих → LLM пишет название и сводку кластера, исключая частную информацию → многоуровневая иерархия; защита: обезличивание, агрегация, минимальный порог частоты темы, проверка сводок моделью на отсутствие идентифицирующих деталей - [Anthropic: Clio](https://www.anthropic.com/research/clio)
- [ВЕНДОР] PostHog Replay Vision: «сканер» = промпт (что искать) + тип ответа (формат) + фильтры (какие записи); результат хранится как обычное событие с рассуждением, ссылками на моменты-доказательства, уверенностью и стоимостью - [PostHog](https://posthog.com/pocket-guides/session-replay/replay-vision); PostHog AI пересказывает по потоку событий, не по видео - дешевле и быстрее - [PostHog Docs](https://posthog.com/docs/session-replay/session-summaries-ai)
- [ВЕНДОР] Amplitude Session Replay Agent: пользователь задаёт область (воронка/событие) и необязательные указания; каждая находка сопровождается подборкой записей-доказательств и долей затронутых пользователей; находки доставляются проактивно в Slack/почту - [Amplitude Docs](https://amplitude.com/docs/amplitude-ai/session-replay-agent); [SiliconANGLE](https://siliconangle.com/2025/10/21/amplitude-introduces-mcp-ai-agents-automate-behavioral-data-analysis/)
- [ВЕНДОР] LogRocket: порог ≥3 повторов для «серьёзной» проблемы, LLM пишет описание, триаж людьми улучшает приоритизацию, в LLM - только то, что нужно для описания - [LogRocket Docs](https://docs.logrocket.com/docs/galileo)
- [НАУКА] LLM надёжнее при применении ГОТОВОЙ схемы категорий (дедуктивно), чем при самостоятельном придумывании тем (индуктивно) - [PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC13048440/)
- [ВЕНДОР] Качество ответа ИИ зависит от чистоты и понятности имён событий - [Mixpanel Docs](https://docs.mixpanel.com/docs/mixpanel-agent)
- [НАУКА] Если данных много и нужен «поиск повторяющихся рутин» - литература task mining советует сначала сегментацию на задачи, затем кластеризацию - [Robotic Process Mining, BISE](https://link.springer.com/article/10.1007/s12599-020-00641-4)

### Inferences
- Конкретный рецепт для таблицы `ui_events` (blocked_click, save_error, empty_search, viewport) и бизнес-записей, составленный по образцам выше (это синтез, а не документированный кейс):
  1. Раз в неделю SQL считает: частоту каждого типа по странице/элементу, новые пары «страница+тип», которых не было прошлые 4 недели, топ текстов save_error и empty_search. Порог «≥3 повторов», как у LogRocket.
  2. Тексты ошибок и пустые запросы - в LLM с ЗАДАННОЙ схемой категорий (например: «нет такого клиента в справочнике», «опечатка», «ошибка сервера», «нет прав») - дедуктивно, как в исследовании; то, что не легло ни в одну категорию, выносить отдельным списком «новое».
  3. LLM пишет короткий дайджест «где интерфейс мешает» с обязательными ссылками на id событий и пометкой уверенности (приём PostHog Vision); без ссылки находка не показывается.
  4. Руководитель ставит оценки «полезно/нет» (палец вверх/вниз) каждой находке - это и есть «обучение» системы на малых данных (приём Clarity/LogRocket/Mixpanel): отклонённые шаблоны больше не присылать, подтверждённые превращать в правила.
  5. Агрегировать по функциям/страницам, а не по людям; имена сотрудников перед отправкой во внешний API заменять псевдонимами; отмечать даты выкаток, чтобы изменения интерфейса не путались с изменением поведения.
- Чего НЕ делать при таком объёме: обучать свои модели оттока/фрустрации, кластеризовать 15 человек, строить ИИ-оценку «эффективности» отдельного сотрудника по кликам (метаанализ мониторинга + эффект Гудхарта).
- Стоимость такого конвейера мала: сотни-тысячи событий в неделю после SQL-агрегации - это единицы тысяч токенов на запрос к LLM.

### Gaps
- Не найдено опубликованного кейса именно маленькой компании (10-20 пользователей), которая анализирует свои журналы UI-событий с помощью LLM и измерила результат; рецепт выше собран из практик крупных вендоров и научных работ, его эффективность на таком масштабе не проверена.
- Не найдено независимых сравнений «LLM-дайджест против ручного просмотра» по полноте находок трения.
