# План: ДЗ и Воронка документов на странице менеджера - переиспользовать общее ядро

**Дата:** 2026-08-12
**Автор:** Клод
**Статус:** реализовано, ждёт деплоя

## Цель

Влад (по скринам global ДЗ и "Проблемные заказы"): не изобретать заново - вкладки
"Дебиторская задолженность" и "Воронка документов" на личной странице менеджера должны быть
в ТОМ ЖЕ формате, что уже есть на дашборде, и брать данные из одного источника с ним.

## Реализация

### ДЗ-вкладка
- Убран текстовый инпут "Мин. сумма долга" - заменён двойным слайдером диапазона
  (`.range-slider`, новый CSS-компонент, два `input[type=range]` внахлёст + заполненная
  полоса между ними, без единого текстового поля).
- Разворачивание строки контрагента по клику - показывает список документов через
  `buildDebtDocsHtml_` (та же самая функция, что уже открывает строку в global ДЗ) - даты,
  юрлицо, номер реализации, сумма, сверка "Итого/Аванс/Открыто по факту".
- Цвет просрочки (`ageCls`, тот же светофор, что в global ДЗ: >90 красный, >30 жёлтый,
  иначе зелёный) и строка "от какого юрлица работаем" (`byOrg`, тот же формат
  "— Бульдог: 452 500 ₽").
- Статус - только просмотр текстом, без `<select>` для смены (Влад: "без возможности менять,
  только статус видеть").

### Воронка документов
- Компактная сводка (сегментированная полоса + счётчики по стадиям) оставлена сверху.
- Ниже добавлена детальная таблица - тот же формат, что "Обзор заказов → Проблемные заказы":
  вкладки-фильтры Все/Нет путёвки/Не проведён/Нет реализации + таблица с теми же 9 колонками
  (Номер/Дата/Декада/Клиент/Менеджер/Водитель-наёмник/Сумма/Оплата/Статус).
- Один источник строки - `problemOrderRowHtml_(p)` вынесена из `filterProblems()` (global
  страница) в отдельную функцию, переиспользуется ОБОИМИ местами - не два похожих шаблона,
  а один.

### Бэкенд
- `buildManagerView_` прикладывает `orders.problem_orders`, отфильтрованный на этого
  менеджера (приватность - другие менеджеры не видны роли `manager`); admin-предпросмотр
  дополнительно фильтрует на фронте (там company-wide список).

## Проверка

- Слайдер диапазона - без текстового ввода, границы двигаются, фильтрует таблицу.
- Разворачивание строки - документы в точности как на скрине Влада (даты/юрлицо/реализация/
  суммы + сверка).
- Воронка документов - таблица с фильтрами по статусу, тот же формат, что "Проблемные
  заказы", отфильтровано на менеджера.
- Регрессия: global "Проблемные заказы" (после рефакторинга на `problemOrderRowHtml_`),
  Прус/Васин - не задеты.

## Уточнения от 2026-08-12 (тот же день, вторая итерация - баг с пропавшим должником)

Влад заметил, что на личной странице Савитка не видно должника "[Гео]Спецстрой", и сам
нашёл причину, диктуя фикс: двойной слайдер суммы долга (см. "Реализация" выше) прятал его.

**Корень бага:** `mgrDebtRangeMax` был module-level переменной (переживает между рендерами).
Она обновлялась только правилом `if (mgrDebtRangeMax === null || mgrDebtRangeMax > rangeMax)
mgrDebtRangeMax = rangeMax` - то есть могла УМЕНЬШАТЬСЯ, но не увеличивалась обратно. Если в
admin-предпросмотре сначала открывали менеджера с маленьким максимальным долгом, потом
переключались на Савитка (у которого макс. долг больше) - верхняя граница слайдера оставалась
от предыдущего, меньшего значения, и крупный долг "[Гео]Спецстрой" молча обрезался фильтром.
Это ровно то, что описывал Влад: "разобрался, почему геоспецстрой не показывают, потому что
этот дебильный бегунок... взял диапазон меньше 2 миллионов".

**Фикс (по прямому указанию - "убери его вообще, чтобы его не было"):**
- Слайдер суммы долга удалён целиком - CSS (`.range-slider*`), состояние
  (`mgrDebtRangeMin`/`mgrDebtRangeMax`), разметка и предикат фильтра по сумме.
- Фильтр по дням просрочки переведён на ТОЧНО тот же механизм, что global ДЗ
  (`debtBucketFilters` - `Set`, множественный выбор, `setDebtBucketFilter`), только с другим
  дефолтом: `mgrDebtBuckets = new Set(['0-30','30-60','60-90'])` вместо пустого множества у
  global ДЗ (Влад: "изначально... сразу три зажатые диапазона... при отжимании одного из
  диапазонов остаётся столько, сколько зажато").
- Цвет ячейки баланса - убран выдуманный `red`, теперь как в global ДЗ (без цвета, только
  `<b>`). "Весь стиль возьми из нашей дебиторки. Не надо ничего придумывать отдельного здесь."

**Проверка:** синтетика с двумя менеджерами (маленький долг → Савиток с должником 3.5 млн) -
переключение через `<select>` дропдауна воспроизвело баг на старом коде и подтвердило фикс на
новом (должник виден сразу, без ручных действий). Мульти-выбор корзин проверен - отжатие
одной корзины оставляет остальные зажатыми, должник корректно уходит/возвращается из списка
при попадании/невыпадении в активные корзины. Цвет баланса - без цвета, просрочка - `ageCls`
как раньше.

**Урок:** module-level UI-состояние (фильтр), которое не сбрасывается при смене "объекта
просмотра" (менеджера в admin-дропдауне) - источник трудноуловимых багов "у одного не видно
то, что видно у другого" - особенно если состояние ещё и односторонне монотонно (граница
может только уменьшаться). Простое решение часто лучше "умного" - слайдер с автогранцей был
сложнее и хуже, чем обычные кнопки-корзины, которые уже существовали в global ДЗ.
