# Ретроспектива: вкладка "План задания" на дашборде (вариант А)

2026-08-16, вечер-ночь.

## Что сделали

Первая интеграция дашборда с отдельной таблицей планировки ("Скрипты для
планировки"/`Планировка_заказов*`) - новая вкладка "План задания", только
чтение. Менеджер/логист видит свои собственные заказы за текущий месяц
(номер, техника, статус, назначенный транспорт, стоимость) прямо на
дашборде, без захода в Google Таблицу. Сама таблица планировки полностью
не тронута в своей рабочей логике (masterEditRouter, покраска, Telegram) -
только добавлена одна строка записи в новую служебную таблицу-указатель.

**Архитектура:**
- Новая постоянная таблица-указатель "План задания - Индекс" (1 строка:
  месяц/год/id/ссылка), которую `duplicateForNextMonth()` перезаписывает
  при создании копии на новый месяц.
- `getOrderPlanView_()` в дашборде читает по индексу текущую таблицу
  планировки, сопоставляет имена (лист "Доступ" хранит ФИО, таблица
  планировки - "Фамилия Имя", разные форматы) и отдаёт только заказы этого
  человека - и как менеджера-продавца, и как логиста-диспетчера.
- `?action=order_plan` в `doGet`.

## Что пошло не по плану (и как чинили)

1. **Ветка была создана от точки на 320 коммитов позади `origin/main`.**
   Работал вслепую поверх устаревшей копии `files/index.html`/
   `scripts/full_script_final.js` (без "Поступления", клиентской аналитики
   и т.д.), хотя `origin/main` и живой Apps Script были синхронны между
   собой. Обнаружил только на этапе деплоя, когда сравнил размер файлов.
   Исправлено: ветка сброшена на `origin/main`, фича перенесена заново.
   **Урок:** перед началом любой сессии в worktree - проверять
   `git rev-list --left-right --count HEAD...origin/main`.

2. **Разные форматы имён.** Лист "Доступ" хранит "Фамилия Имя Отчество",
   таблица планировки - "Фамилия Имя" (плюс у Прус-Роскошного фамилия в
   планировке короче через дефис). Без нормализации - 0 совпадений из 17
   имён. Сверено диагностической функцией на реальных данных перед тем как
   полагаться на точное сравнение.

3. **Право доступа между Apps Script проектами.** Таблицу-указатель создал
   Влад вручную (ручной запуск = его личный аккаунт), а живой `/exec`
   дашборда работает под другим аккаунтом (`USER_DEPLOYING`) - молчаливый
   "permission denied". Исправлено передачей владения + автоматической
   выдачей доступа новым копиям таблицы планировки в коде
   (`duplicateForNextMonth`), чтобы больше не требовалось ручное действие
   каждый месяц. Записано в память
   (`project_apps_script_cross_project_file_ownership_gotcha`).

4. **Производительность.** Живой тест показал ~2.5 минуты на человека -
   Sheets API медленный на ~31 последовательный вызов `getDataRange()`.
   Решение в два слоя: кэш по дням (`CacheService`, TTL 4 часа) + фоновый
   прогрев кэша внутри уже существующего `runAll()` (6 раз в день) - живой
   пользователь почти никогда не платит холодным чтением.

## Обратная связь Влада

- "Система должна закладывать мгновенный отклик как фундамент" - принято
  как принцип для будущих фич, реализовано для этой через фоновый прогрев.
  Настоящий realtime (Sheets → дашборд без опроса) и защита от
  конкурентной записи - осознанно отложены как отдельная, более крупная
  задача на момент появления записи с дашборда (вариант Б).
- Явно попросил сделать `dlinnomertral@gmail.com` владельцем инфраструктуры
  вместо ручного шаринга - более устойчивое решение, учтено в коде.

## Итог

Задеплоено (backend v205, frontend в `main`, GitHub Pages), проверено

основным рабочим инструментом, дашборд её не изменяет.
