# План: Рыщанов уволился (с 01.09) - роль/зарплата переходят к Сильчеву, редизайн страницы по ГОСТу

**Дата:** 2026-09-10
**Автор:** Клод
**Статус:** реализовано целиком (Фаза 1 - main `a8bc507`/`15823a4` + серверный фикс VPS
`c5a5db0`; Фаза 2 - main `b0bd352`). Обе фазы проверены изолированными тестами на реальных
живых данных (Сильчев, сентябрь 2026). Живой прогон самим Владом - ждёт.

## Контекст и цель

Влад: «Рустем уволился с 1 сентября. Поэтому сейчас Максим [Сильчев] за него. Личную
страницу Максима в дашборде нужно сделать как у Рустема, а там, где блок с зарплатой -
сделать Сильчева с 1 сентября вместо Рустема, только убрать мотивацию 1% от ВП тралов
(спецтралов). В остальном у Сильчева будет пока мотивация Рустема. Также Сильчев пока
ведёт заказы - это в зарплату не идёт, но как счётчик пусть остаётся.»
+ «Да и нужно вид личной странице переработать по ГОСТу, как у старших менеджеров и
менеджеров - расположение блоков и дизайн.»

**Важно:** «Максим» и «Сильчев» - ОДИН человек (`'сильчев':'Сильчев Максим'` в
`LOGIST_FULL_NAME_` файла). Не два разных сотрудника.

**Контекст найма:** Влад параллельно нанимает постоянного старшего логиста на замену
Рыщанову (память `project_hiring_senior_logist`, оффер ~350к, запущено 28.08). Сильчев -
ВРЕМЕННОЕ исполнение обязанностей на переходный период, не окончательное назначение -
формулировки в коде должны отражать это («пока»/«и.о.»), не переименовывать роль насовсем.

Решения по AskUserQuestion (10.09):
- 2%-бонус (маржа найма всех логистов) считается от пула ВСЕХ 4 «чистых» логистов, включая
  самого Сильчева - формулу-пул НЕ трогаем, меняем только кому идёт итоговый платёж.
- Редизайн делаем СЕЙЧАС ЖЕ, вместе с передачей роли, одним заходом.

  локальными переменными `renderSalesSalary`, которые считают `qualMarginAllLogists`).
- Канон «Ролевая личная страница» - `DESIGN_SYSTEM.md`, раздел 4, «утверждено Владом 08.09» -

  `renderMyPageManager` буквально (calcMgr/okladNextTierNote_ и т.п. - это про личный план
  выручки менеджера, у руководителя логистики другая метрика - ВП отдела) - переиспользуем
  СТРУКТУРУ/классы, содержимое - своё (ВП/техника/водители/наёмная техника/документы/путевые,

- `isRyschanowEntry_`/`isRyschanowLogistName_`/`renderMyPageRyschanow`/`ryschanow-salary` -
  имена функций НЕ переименовываем (косметика без функциональной пользы, лишний риск диффа) -

## Реализация

### Фаза 1 - зарплата + идентичность (риск: реальные деньги, делаем первым, со сверкой)

1. **Новый резолвер головы отдела по периоду** (module scope, рядом с `calcRyschanow`):
   ```js
   var SILCHEV_HEAD_FROM_ = '2026-09'; // Рустем уволился 01.09 - Сильчев и.о. с сентября
   function isSilchevHeadPeriod_(period) { return (period||'') >= SILCHEV_HEAD_FROM_; }
   function ryschanowHeadFor_(period) {
     return isSilchevHeadPeriod_(period)
       ? { sur:'сильчев', name:'Сильчев Максим' }
       : { sur:'рыщанов', name:'Рыщанов Рустем' };
   }
   ```
   Гвард историчности: август и раньше остаются на Рыщанове (уже выплачено, не переписываем
   задним числом), сентябрь+ - Сильчев. Тот же приём, что `NEW_RULES_FROM`/`isNewRulesPeriod`.
2. **`renderRyschanowDeptCardHtml_`** - новый 7-й параметр `period`; внутри:
   - `var head = ryschanowHeadFor_(period); var headName = head.name;` (вместо хардкода
     `'Рыщанов Рустем'`).
   - `var effSpecialTrals = head.sur === 'сильчев' ? 0 : specialTralsProfit;` - передаём в
     `calcRyschanow` вместо сырого `specialTralsProfit`. Строка-сноска «1% ВП спецтралов»
     сама не отрендерится (`headRC.specialTralsBonus` будет 0 - falsy, существующий `if`).
   - В цикле по `RYSCHANOW_ALL_LOGISTS_SUR_FRONT_` - помечать `isHeadSelf: sur === head.sur`
     на пуш в `logistCalcs`.
   - `logistTotal` - исключить `isHeadSelf` из суммы (его личные сделки не идут в фонд
     отдела второй раз - он уже оплачен головной строкой).
   - Рендер строки `isHeadSelf` - Выручка/Заявок/Маржа найма/Затраты остаются видны (Влад:
     «как счётчик пусть остаётся»), Оклад/Премии/ИТОГО - `—` + сноска под строкой
     «Личные сделки - счётчик, не оплачиваются отдельно: зарплата по формуле руководителя
     выше».
3. **Оба call-site** (`renderSalesSalary` ~18138, `ryschanowSalaryCardHtml_` ~17147) -
   добавить 7-й аргумент `(D.orders||{}).period`.
4. **Идентичность страницы/роутинга** - `isRyschanowEntry_` (~6797) и `curPersonSur ===
   'рыщанов'` (~10425, видимость пункта меню `ryschanow-salary`) - сменить матч на
   `'сильчев'`. НЕ период-зависимо (кто сейчас видит спецстраницу - вопрос текущей
   операционной роли, не того, какой месяц просматривается внутри неё).
5. **Регресс:** изолированный Node-тест `renderRyschanowDeptCardHtml_`/`calcRyschanow` на
   двух периодах (август - Рыщанов с 1%, сентябрь - Сильчев без 1%, его личная строка не
   добавляет в `deptFund`), сверка чисел вручную по формуле.

### Фаза 2 - редизайн страницы по канону «Ролевая личная страница»

`renderMyPageRyschanow` (~9279) переводится на структуру DESIGN_SYSTEM.md раздел 4:
1. Шапка - без изменений (уже общий стандарт, `page-title`/`page-subtitle`).
2. **Вердикт-полоса `.mp-status`** - слово по прогрессу плана ВП (переиспользуем
   существующие `gpPct`/`gpForecastPct`/пороги, что уже считает `planProgressBar` выше по
   файлу для этой же страницы) - словарь СВОЙ (аналогично механику/менеджеру, записать в
   ГОСТ при сдаче): «ПЛАН НЕ ЗАДАН» / «МЕСЯЦ ТОЛЬКО НАЧАЛСЯ» / «ОТСТАВАНИЕ X,X ДНЯ» /
   «ИДЁШЬ С ОПЕРЕЖЕНИЕМ» / «ИДЁШЬ В ГРАФИКЕ» / «ПЛАН ЗАКРЫТ» (та же лестница состояний, что
   у менеджера - метрика та же по форме, план/факт/прогноз, просто ВП вместо выручки) - рычаг
   «Сегодня нужно N ₽ ВП».
3. **Ярус 5fr/7fr** - слева таблица «Техника» (главная рабочая, самая крупная), справа
   плашки-метрики `.mp-stat` (Заказов по найму / Маржа найма / Документы готово-всего /
   Общая маржинальность) - те самые 4 карточки, что Влад просил убрать со старой версии
   страницы (26.08, «дублировали Наёмную технику») - теперь у них есть законное место (ярус
   метрик канона), не дублирование, а РОВНО тот слот, для которого канон их предусматривает.
4. **Ярус 1fr/1fr** - «Воронка документов» (готовый блок, переносится как есть) +
   «Наёмная техника» (сводка/шкала маржи, hero-число).
5. **Полная таблица** с `<select>`-фильтрами - выбор между Водители/Не сданные путевые
   (водители)/Топ поставщиков без путевых (то, что раньше было отдельными вкладками
   `tab-bar`, сворачивается в один `<select>` над таблицей, канон «Сортируемая таблица»).
6. **Шторка `.mp-drawer`** - клик по строке техники/водителя открывает карточку (минимум -
   просмотр деталей; действий пока нет, не добавляем самовольно - Влад не просил).
7. 🤖 ИИ-задачи (`renderAiTasksBlockHtml_`) - остаются ПЕРВЫМ блоком после вердикт-полосы
   (как у остальных ролей).
8. Регресс: изолированный тест рендера на реальных/синтетических данных - вкладки/фильтры
   работают, нет NaN на пустых данных (архивный период без части полей).

## Риски

- **Payroll-риск (главный):** ошибка в формуле/дате перехода = неверная зарплата реальному
  человеку. Смягчение - Фаза 1 отдельно от Фазы 2, построчная сверка чисел вручную ПЕРЕД
  деплоем, живая проверка на реальных сентябрьских данных сразу после.
- **Редизайн - объём.** Канон уже одобрен (не новый паттерн, доп. согласования не нужно по
  ГОСТу п.0.2), но сам перенос контента в новую структуру - реальный объём кода. Идём после
  Фазы 1, чтобы срочное (зарплата с 1 сентября) не зависело от объёмного (редизайн).
- **Функции остаются "Ryschanow*" по имени** - решение осознанное (см. выше), не путаница -
  комментарии на месте объясняют.
