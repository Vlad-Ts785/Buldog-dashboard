# План: выбор периода на личной странице (текущий/прошлый месяц)

**Дата:** 2026-08-11
**Автор:** Клод
**Статус:** реализовано, ждёт деплоя

## Цель

На "Личной странице" (менеджер и логист) добавить переключатель "Текущий месяц" /
"Прошлый месяц" - работает и в admin-предпросмотре, и при реальном входе сотрудника.

## Контекст

Продолжение серии: [plans/2026-08-10-logist-personal-page.md](2026-08-10-logist-personal-page.md),
[plans/2026-08-10-logist-page-toggle-and-header.md](2026-08-10-logist-page-toggle-and-header.md).
Влад: "нужно сделать ещё выбор периода: текущий месяц и прошлый месяц".

Выбор периода уже есть на вкладках Продажи/Менеджеры/Логисты/Зарплата (`changePeriod()`,
`action=orders_period`, только `admin`). Личная страница им не пользовалась - работала только
с живым `D.orders`. `action=orders_period` нельзя переиспользовать напрямую для ролей
manager/logist (отдаёт ВСЮ компанию), нужен урезанный аналог.

## Реализация

### Бэкенд
- `getManagerView_`/`getLogistView_` разобраны на `buildManagerView_(orders, name)` /
  `buildLogistView_(orders, name)` (принимают уже загруженный `orders`) + обёртки для текущего
  месяца (`getOrdersData`) и `getManagerViewForPeriod_`/`getLogistViewForPeriod_` для архива
  (`getOrdersDataForPeriod`).
- Новый `action=my_page_period&period=YYYY-MM` в `doGet` - доступен только ролям
  `manager`/`logist` (не admin - у него уже есть `orders_period`), использует ту же фильтрацию
  "только свои данные", что и обычный вход.

### Фронтенд
- `myPagePeriod`/`myPagePeriodCache`/`setMyPagePeriod()` - на диспетчере `renderMyPage()`,
  подменяет `D.orders`/`D.summary.profit_long` на время рендера (тот же приём, что
  `renderSalesTabsForPeriod()`), с кэшем по периоду (не дёргает API повторно).
- Admin - через существующий `action=orders_period`; manager/logist - через новый
  `action=my_page_period`. Кнопки `.tab-bar`/`.tab-btn` "Текущий месяц"/"Прошлый месяц" в
  шапке (`prevMonthKey_()` - предыдущий календарный месяц от клиентской даты).
- "Прошлый месяц" всегда один конкретный месяц (не список архивов) - соответствует буквальной
  просьбе Влада, не переиспользует `available_periods`.

## Проверка

- Синтетические данные в браузере: admin-предпросмотр (мок `orders_period`) и роль `logist`
  (мок `my_page_period`) - оба пути корректно подменяют данные, зарплата пересчитывается по
  периоду (проверено вручную: июль 30 заказов/700к маржи -> 81 000₽, сходится с формулой).
  Переключение обратно на "Текущий месяц" возвращает исходные данные без потерь.
- Синтаксис фронтенда и бэкенда проверен (`node --check`).
