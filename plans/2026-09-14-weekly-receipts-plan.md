# План: «План поступлений» — еженедельный план сбора ДЗ от руководителей отдела продаж

**Дата:** 2026-09-14
**Автор:** Клод
**Статус:** в работе

## Цель

Влад по понедельникам (и до вторника 15:00) получает от Ахтамовой и Гусейновой
(руководители коммерческих групп) план — с каких контрагентов их зоны они реально ждут
оплату на этой неделе и сколько. План живёт в новой вкладке дашборда, сравнивается позже
с фактом (снижением баланса ДЗ), директор видит сводку по обеим руководителям с
развёрткой по контрагентам по клику.

## Контекст

Превью формы (`examples/prototype-weekly-receipts-plan.html`, [артефакт](https://claude.ai/code/artifact/0a09dcfe-cd4c-4867-839e-54b911a79b63))
собрано параллельными агентами-специалистами (эргономист + аналитик, методика
DESIGN_SYSTEM.md раздел 0.3) на мок-данных, одобрено Владом 2026-09-14 живым просмотром +
одной доработкой (развёртка по клику на директорской сводке).

**Решено Владом (2026-09-14):**
- Дедлайн — понедельник и вторник **до 15:00** каждую неделю (окно редактирования: понедельник
  00:00 → вторник 15:00, потом форма закрывается на правки до конца недели).
- Долги Ратникова (менеджер без группы/руководителя, `DEPT_CFG` в files/index.html:17881,
  `solo:true`) — **вне этой фичи**, Ахтамова/Гусейнова к нему не привязаны, Влад разбирается
  сам.
- Уволенные менеджеры (Дербенцева, Шейко, Коньшина, Володин) — их зависшие должники **остаются
  в зоне того отдела, где менеджер был** (ровно так, как уже сделано в живом коде:
  `DEPT_CFG`/`COMMERCIAL_DEPTS` держат их в `members` до сих пор, files/index.html:17872-17873,
  19362-19364 — ничего менять не нужно, просто переиспользовать существующий состав).
- Один инпут суммы на контрагента (не разбивка по юрлицам) — подтверждено, как в превью.

**Важная находка при разведке кода (радикально сокращает объём новой работы):**
зона «свои должники» для Ахтамовой/Гусейновой **уже существует и живёт в проде** —
страница `#page-commercial-head-debt` (`renderCommercialHeadDebtPage_()`,
files/index.html:19251) уже фильтрует `D.debt.by_customer` по `currentCommercialHeadCfg_()`
→ `DEPT_CFG.members`, с корзинами просрочки, статусами, byOrg-разбивкой, drill-down по
документам. Новая фича НЕ строит список должников с нуля — она **добавляет слой
планирования** (чекбокс + сумма + дедлайн + отправка) поверх уже готовых данных, отдельной
вкладкой (Влад прямо просил «новая вкладка... новая форма», не расширение вкладки ДЗ).

**Архитектурная находка (ИСПРАВЛЕНО после разведки кода api/server.js, отменяет
первоначальное предположение ниже вычеркнутым текстом):** ~~Ахтамова/Гусейнова заходят под
`D.role === 'manager'`... нужен прокси-экшен в Apps Script~~ — ОКАЗАЛОСЬ НЕ ТАК. Браузер
ЛЮБОЙ роли уже держит рабочий `session_token` (`SESSION_TOKEN` в files/index.html,
localStorage, `fetchFromYardApi_`/`postToYardApi_`/`postToYardApiWithBody_` — уже
используются менеджерами напрямую для geocoder/calculator/sprav-документов). VPS уже умеет
self-service эндпоинты для role=manager с проверкой "это точно свой человек, не чужой"
(живой пример — `/api/ai_tasks`: admin передаёт `person=`, manager получает своё имя из
`access_users` по email сессии). Прокси через Apps Script НЕ нужен — прямой browser→VPS.
Дополнительно на сервере уже ГОТОВА зона: `COMMERCIAL_HEAD_TEAMS_`/`surOf_`/
`commercialHeadTeam_` (api/server.js:8233-8243) — server-side зеркало `DEPT_CFG`, уже
используется в `buildManagerPayload_`. Фаза 2 (Apps Script) — УДАЛЕНА из плана, см. ниже.

## Риски

- **Написание контрагента может разойтись между ДЗ-снимком на момент планирования и
  фактическим на конец недели** (переименование в 1С, смена регистра) — план и факт могут
  не совпасть по ключу. Сверять по паре (contragent, manager), не только по имени.
- ~~Auth server-to-server~~ — СНЯТО, см. находку в контексте (прямой browser→VPS уже
  работает для других self-service эндпоинтов, ничего дополнительного не понадобилось).
- **Метрика «факта»** (план vs факт) — сознательно ВНЕ этого плана (см. открытые вопросы
  в превью), отдельная задача после того, как форма пожила хотя бы одну неделю вживую.

## Открытые вопросы

- Метрика факта (снижение баланса ДЗ за неделю) — отдельно, после недели живых данных.
- Нужен ли admin возможность редактировать план ЗА руководителя, или только смотреть.

### Фаза 7 (14.09, вечер) — дизайн-штурм «Пульс», редизайн на сайте

После нескольких живых заходов (лок после отправки, факт+перенос, таблица по просьбе
Влада) он сам сказал про сводку директора «мне это не нравится, как сейчас» и попросил

вариантов, сравнение). Штурм прошёл в два захода:

1. **Сводка директора** — 3 агента, 3 варианта («Пульс» KPI+bullet-чарт, «Рабочий стол»
   плотная таблица, «Карточки» тайлы с прогресс-кольцами), собраны в сравнительный Artifact.
   Влад выбрал «Пульс».
2. **Личная страница руководителя** — тем же методом, 3 варианта в стиле «Пульс»
   («Пульс-лента», «Пульс-борт», «Пульс-сетка»), тоже сравнительный Artifact. Влад выбрал
   «Пульс-ленту» («это самый лучший вариант») и дал два уточнения: значок копирования
   рядом с контрагентом (чтобы быстро вставить в поиск 1С), но копироваться должен ИНН,
   не название компании; плюс фамилия ответственного менеджера в строке. Уточнения внесены
   в превью, затем — «запускай на сайты, один в один как в этом превью».

**Реализовано в `files/index.html` (без изменений на VPS/`api/server.js` — это чистый
редизайн фронтенда, данные и эндпоинты те же):**
