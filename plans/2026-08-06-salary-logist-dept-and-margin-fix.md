# План: Зарплата - починка порога 23%, «Отдел Рыщанова» с логистами, скрытие уволенных

**Дата:** 2026-08-06
**Автор:** Влад (постановка) / Клод (реализация)
**Статус:** в работе

## Цель

Починить регрессию в расчёте маржи найма (порог 23% снова проверяется по заказу, а не по
компании), собрать весь отдел логистики (Рыщанов + логисты) в один блок «Отдел Рыщанова» с
персональными формулами, и перестать показывать в «Зарплате» сотрудников без выручки
(похоже на увольнение).

## Контекст

Вкладка «Зарплата» (`files/index.html`, `renderSalesSalary`) и backend-агрегация
(`scripts/full_script_final.js`, `aggregateOrdersRows`) уже реализуют большую часть нужной
логики (см. `../ai-clone/... project_salary_rules.md`), но:

1. **Регрессия порога 23%.** 2026-07-07 порог "маржа найма ≥23%" был исправлен с проверки
   *по каждому заказу* на проверку *по компании за месяц целиком* (см. память
   `project_salary_rules.md`, инцидент 2026-07-07). В текущем коде (`full_script_final.js:5040`)
   снова стоит `marginQualifies = isHired && marginPct >= 0.23` **по строке заказа** -
   агрегирующего прохода `companyMarginPct`/`companyMarginQualifies` в файле нет. Видимо,
   откатилось при одном из параллельных `clasp push` мимо git (см. память, там уже был такой
   инцидент 2026-07-07 с гонкой сессий).
2. **«Отдел Рыщанова»** в `DEPTS` (`files/index.html:4161`) сейчас содержит только
   `['рыщанов','суркова']` - остальные логисты (Кан, Махура, Прус-Роскошный, Сильчев, Васин)
   рендерятся отдельным блоком «Логисты» ниже всех отделов (`files/index.html:4322+`). Влад
   хочет их внутри одного блока «Отдел Рыщанова» (Рустем/Рыщанов - руководитель, все логисты -
   подчинённые).
3. **Васин** сейчас считается по общей формуле логиста (`calcLogist`: 500₽/заявка + 8% квалиф.
   маржи найма). Нужна отдельная формула: 2.5% от валовой прибыли (ВП) по группе длинномеры
   **по компании целиком** (`D.summary.profitLong` - тот же источник, что уже использует
   Рыщанов для своей ВП, см. `project_profit_rule`).
4. **Менеджеры/логисты без выручки текущего периода** (пример: Дербенцева, Коньшина, Володин)
   сейчас всё равно рендерятся строкой «нет данных» (`files/index.html:4296-4297`). Влад:
   такие люди скорее всего уволены, строку не показывать вовсе.
5. **Отдельный, ещё не решённый вопрос** - расхождение между картой "Маржа (наём)"
   (сумма поля `Прибыль` 1С построчно) и таблицей "Наёмная техника"/партнёры (`revenue-cost`
   в `supplierMap`). Влад попросил сначала понять причину (см. `diagnoseHiredMarginMismatch()`,
   закоммичена отдельно, ждём лога) - **в этот план не входит**, чинить отдельно после диагноза.

Подтверждено с Владом (через уточняющие вопросы 2026-08-06):
- Логисты остаются на **8%** от квалифицирующей маржи найма (речь про 2% была про
  формулу Рыщанова, не логистов - ставка логиста не меняется).
- 500₽/заявка своим парком у логиста платится **всегда**, независимо от порога 23%.
- Васину ВП длинномеры = **общая ВП длинномеров по компании** (`D.summary.profitLong`), не
  только его личные заказы.

**Диагностика рассинхрона маржи завершена (2026-08-06, `diagnoseHiredMarginMismatch()`).**
Причина: колонка "Стоимость привлечённой техники" (hired_cost) не всегда заполняется в отчёте
1С (пример - заказ #471953 МАШРЕЗЕРВ: Затраты=0, хотя Прибыль(1С)=95000 при Сумме=110000 -
1С корректно видит реальную стоимость найма ~15000, наша колонка "Затраты" её просто не
получила). Поле "Прибыль" 1С надёжнее - оно уже кормит зарплату через `hiredProfit`/
`managerMap`/`logistMap`. Решение: **`supplierList` (таблица "Наёмная техника"/партнёры)
переключить с `revenue-cost` на накопленную построчно `profit`** - малый низкорисковый фикс,
делается в рамках этого же плана (Фаза 5).

**Приказ № 01/07/26 от 01.07.2026 "Об утверждении мотивации руководителя отдела логистики
Тралы и длинномеры"** (подписан Гонтюрев А.А., рукописная пометка "До 1.11.26" - дата
истечения/пересмотра): дополнительно к окладу и прочим бонусам Рыщанова - **премия 1% от
валовой прибыли (ВП), наработанной тремя конкретными тралами**:
- Скания В 776 ЕТ 797 + файмон корыто 4 оси УУ 4720 77
- Скания М 800 АЕ 797 + файмон корыто 4 оси УХ 5545 77
- Скания О 894 ХМ 797 + файмон 8-осный ХУ 5875 77

Действует с 01.07.2026. Три эти тягача уже видны в живой Штатке (сверено с реальным списком
тралов) - госномера: В776ЕТ797, М800АЕ797, О894ХМ797.

## Критерии готовности

- [ ] На вкладке «Зарплата» «Отдел Рыщанова» показывает одним блоком: Рыщанов + все активные
      логисты (Кан, Махура, Прус-Роскошный, Сильчев, Васин - у кого есть данные за период).
- [ ] Васин считается по 2.5% ВП длинномеров компании, остальные логисты - по старой формуле
      (500₽/заявка + 8% квалиф. маржи).
- [ ] Порог 23% проверяется ОДИН раз по компании за месяц (не по каждому заказу) - баннер над
      ФОТ показывает этот %, все сотрудники получают либо весь квалиф.бонус, либо ничего.
- [ ] Дербенцева, Коньшина, Володин (и любой другой без выручки за период) не отображаются ни
      в шапке отдела, ни в таблице.
- [ ] Числа сверены на реальном текущем периоде (сравнить ФОТ до/после фикса на разумность,
      особенно сумму 2% Рыщанова - если 23% раньше не выполнялся из-за бага, сумма могла быть
      занижена).
- [ ] Задеплоено через clasp (backend) + закоммичено в git (frontend правки в `files/index.html`
      идут через обычный git push → автодеплой GitHub Pages, backend - через clasp с
      pull+diff протоколом).

## Риски

- Смена базы квалификации (построчно → по компании) задним числом меняет цифры зарплаты за
  ТЕКУЩИЙ месяц у всех сотрудников сразу - если месяц уже частично выплачен, показать Владу
  разницу ДО деплоя, не просто задеплоить молча.
- Объединение таблиц логистов и менеджеров в один блок может визуально сломать вёрстку (разные
  наборы колонок) - проверить в браузере после правки, не только в коде.
- Расхождение маржи (Фаза "не входит") может означать, что и `hiredProfit`/`companyMarginPct`
  сами по себе занижены (если поле "Прибыль" 1С систематически меньше реальной маржи) - тогда
  порог 23% может ложно не выполняться там, где по факту маржа выше. Дождаться диагностики
  прежде чем считать Фазу 1 окончательно закрытой по цифрам (код будет правильный, но входные
  данные - под вопросом).

- **Что сделано:**
  - Фаза 1: порог 23% снова считается по компании за месяц целиком (регрессия починена),
    баннер над сводкой ФОТ восстановлен.
  - Фаза 2: логисты (Кан/Махура/Сильчев/Прус-Роскошный/Суркова/Васин) перенесены внутрь
    карточки "Отдел Рыщанова", отдельный блок "Логисты" остался только для периодов до июля.

  - Фаза 4: сотрудники без данных за период не рендерятся ("нет данных" убрано, строка и

  - Фаза 5: приказ №01/07/26 - +1% ВП трёх конкретных тралов Рыщанову, гейт по дате до

  - Фаза 6: таблица "Наёмная техника" (партнёры) считает маржу из поля "Прибыль" 1С, не

  Apps Script, но НЕ `create-version`+`redeploy`; frontend закоммичен в feature-ветку, не в
  main) - осознанно, ждём ревью Влада перед тем, как менять реальные суммы зарплат.
- **Что добавить в бэклог:** выяснить у 1С/бухгалтерии природу третьей статьи затрат по
