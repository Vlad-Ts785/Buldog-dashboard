# Личные страницы Ахтамовой и Гусейновой (руководители коммерческих групп)

## Цель

Влад (2026-08-26, после завершения страницы Рыщанова): "давайте сделаем странички для
старших менеджеров Ахтамовой и Гусейновой. Они должны отражать и задачи. План выполнения
отдела... точно такая же табличка [как в Зарплате]... блок с вкладками Поступления
(по менеджерам/вчера/сегодня/эта неделя)... Дебиторская задолженность".

Уточнение после первого прохода (тот же день): ДЗ и Зарплата - НЕ вкладки на личной
странице, а ОТДЕЛЬНЫЕ пункты в левом меню (тот же принцип, что только что сделан для
Рыщанова - "Отдельная и единственная"), скрытые по умолчанию, видны только этим двум
руководителям (свой вход) или admin-предпросмотру "как они".

Похожий принцип на странице Рыщанова, но ЭТИ роли - `manager` (не `logist`), и у них УЖЕ
есть готовая структура в `renderSalesSalary()` (карточки "Отдел Ахтамовой"/"Отдел
Гусейновой" в `COMMERCIAL_DEPTS`) - максимально переиспользуем, не изобретаем заново.

## Что новое

### 1. Дельта "с вчера" на табличке отдела (скриншот 1, `▲+3` / `▲+600 000`) - УЖЕ ЕСТЬ

Ложная тревога - при первом чтении плана казалось, что нужны новые бэкенд-поля
(`orders_thru_yesterday`). На самом деле это НЕ нужно: `managerMap[mgr].today_new_orders`/
`today_new_amount`/`today_new_list` УЖЕ считаются бэкендом (scripts/full_script_final.js,
комментарий "для стрелки динамики и drill-down", Влад 2026-07-17) и УЖЕ используются на
странице "По менеджерам" (`mgrRow()`, files/index.html:8004-8010) - ровно то же самое
"▲+N" с click-to-expand списком заказов (`todayList`), что на скриншоте 1. Просто нужно
скопировать этот РЕНДЕР (не аггрегацию) в новую `renderDeptGroupTableHtml_()` - см. раздел
"Что уже есть" выше. Бэкенд трогать НЕ требуется вообще, ни на Apps Script, ни на VPS -
поле уже есть и уже отдаётся сервером (проверить на живых данных, что server-computed путь
(`USE_SERVER_ORDERS_CALC=on`) тоже отдаёт `today_new_orders`/`today_new_amount`/
`today_new_list` - если ПОЛЕ УЖЕ используется живой страницей "По менеджерам" без жалоб на
пустоту, значит уже синхронизировано на VPS, отдельно перепроверять не обязательно, но
одним быстрым curl'ом стоит подтвердить перед тем как полагаться на него в новом месте).

### 2. Личная страница (новая функция `renderMyPageAhtamova_`/переиспользуемая для обеих,
   параметризованная составом отдела)

- ИИ-задачи - новый промпт/контекст (`buildCommercialHeadAiContext_`/
  `buildCommercialHeadAiTasksPrompt_`, роль-независимый параметр "чей отдел"), по образцу
  `buildRyschanowAiContext_`/`buildRyschanowAiTasksPrompt_`, но темы другие: план продаж
  отдела, кто отстаёт от плана, кто просрочил ДЗ, кто не сдал крупную сумму поступлений.
  Формулировки - С ПОЗИЦИИ РУКОВОДИТЕЛЯ (тот же принцип, что только что закреплён для
  Рыщанова - НЕ "позвони [клиенту]", а "спроси с [менеджера]"/"поставь задачу").
- План выполнения отдела - тот же % бар, что уже есть в футере карточки "Отдел X"
  ("Итого отдела: X ₽ · Y% из Z") - НЕ дублировать таблицу целиком на странице, просто
  верхний план-бар (как у Рыщанова "Валовая прибыль своего парка"), а полную табличку -
  только через отдельный пункт "Зарплата" в меню (см. ниже).
- Вкладки "Поступления" (по менеджерам/вчера/сегодня/эта неделя) - фильтр состава отдела
  по фамилиям (`ordInList`/аналог), переиспользовать `renderReceipts` рендер-функции,
  просто с урезанным списком менеджеров на входе.

### 3. Отдельные пункты левого меню (НЕ вкладки на личной странице)

- `data-page="ahtamova-salary"` / `data-page="guseinova-salary"` (или ОДИН универсальный
  `data-page="commercial-head-salary"`, показывающий карточку своего отдела в зависимости
  от того, кто смотрит - проще в поддержке, один пункт вместо двух хардкод-copies) -
  показывает `renderCommercialDeptCardHtml_()` для СВОЕГО отдела. Видимость в
  `applyRoleUI()` - по фамилии текущего просматриваемого (Ахтамова/Гусейнова, свой вход
  или admin-предпросмотр).
- `data-page="commercial-head-debt"` - страница ДЗ, отфильтрованная под состав отдела
  (переиспользовать `renderDebt`/Должники, дефолтный/зафиксированный фильтр по составу
  команды - решить на этапе реализации, показывать ли переключатель между менеджерами
  внутри отдела или сразу всех вместе).

### 4. Роутинг/доступ

- `isAhtamovaName_(name)`/`isGuseinovaName_(name)` (или один `isCommercialHeadName_` с
  возвратом, КАКОЙ отдел) - фамильная проверка, как `isRyschanowLogistName_`.
- `buildManagerView_` (аналог `buildLogistView_` для роли `manager`) - приложить
  company-wide срез (свой отдел целиком: `by_manager` только своей команды, ДЗ своей
  команды, receipts своей команды) при самостоятельном входе - тот же приём, что
  `ryschanow_summary`.
- `doGet action=generate_ai_tasks` - резолвить роль `'commercial_head'` по фамилии, как
  уже сделано для `'ryschanow'`.
- `ALWAYS_PREVIEW_ROSTER_`/`buildMyPageRoster_` - Ахтамова и Гусейнова УЖЕ есть в
  by_manager (у них есть личные продажи, `ownSales:true`) - вероятно НЕ нужна заглушка,
  но проверить на реальных данных перед сдачей.

## Риски / открытые вопросы (решить по ходу, не блокируют старт)

  карточки (сумма планов всех менеджеров команды), или отдельный план ВВОДИМЫЙ вручную

## Порядок реализации (единый заход, без промежуточных пауз, копируя протокол Рыщанова)

1. Бэкенд: `orders_thru_yesterday` в managerMap (Apps Script + VPS СРАЗУ вместе).
2. Бэкенд: `renderCommercialDeptCardHtml_()` вынесена в module scope на фронтенде,
   `renderSalesSalary()` переключён на неё (как уже сделано с Рыщановым) - без визуальной
   регрессии на company-wide вкладке "Зарплата".
3. Бэкенд: `isAhtamovaName_`/`isGuseinovaName_`, `buildManagerView_` company-wide срез,
   AI-промпт/контекст, doGet роутинг.
4. Фронтенд: личная страница (ИИ-задачи + план-бар + вкладки поступлений).
5. Фронтенд: два новых пункта меню (Зарплата/ДЗ), `applyRoleUI()` видимость.
6. Тесты (изолированные Node, оба сценария входа - admin/self), деплой (Apps Script +
   VPS + git), проверка на живом сайте.
7. Запись в DEPLOY_LOG.md/README VPS, ретроспектива.
