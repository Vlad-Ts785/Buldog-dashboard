# План: страница "Глобальная статистика" - ключевые метрики по месяцам + динамика за год

**Дата:** 2026-08-04
**Автор:** Клод (с Владом)
**Статус:** черновик

## Цель

Новая страница дашборда: выбрать любой месяц (не только текущий) и увидеть ключевые цифры
бизнеса за него (выручка, валовая прибыль по сегментам, выполнение планов), плюс график
этих же метрик по всем месяцам года одним взглядом - без переключения между вкладками.

## Контекст

Повод (Влад, 2026-08-04): на "Панели" карточка "Валовая прибыль" в начале августа временно
показала июльские цифры (пока не настроена рассылка августовского "Отчёта парк" - это
отдельный, уже решённый вопрос на стороне 1С, не баг дашборда). Разбирая это, Влад
сформулировал более широкую потребность: "эти ключевые данные важны, хочу видеть их по
каждому выбранному месяцу и в динамике по году".

Что уже есть и можно переиспользовать:
- Переключатель периода на "По менеджерам"/"Заказах" (план от 2026-06-30) - `changePeriod()`,
  `getOrdersDataForPeriod()`, `getGrossProfitForPeriod()`, `getAvailablePeriods()`. Уже умеет
  доставать факт/план продаж и ВП за произвольный архивный месяц.
- `computeSalesFaktPlan_(ordersData)` (2026-08-04, сегодняшний фикс) - общий расчёт
  факта/плана без задвоения внутренних, один источник для текущего и архивного периода.
- `aggregateFinHistoryForRange()` - уже умеет брать ВП по сегментам (тралы/длинномеры) за
  любой диапазон дат, источник - `Данные_1С_история` (архив по месяцам) с фолбэком на
  посуточные снимки `История_финансов`.
- Chart.js уже подключен и используется (графики на "Динамике", мини-график ДЗ на Панели).

Чего не хватает: сейчас "по каждому месяцу" данные достаются КАЖДЫЙ РАЗ заново (разбор
архивного листа заказов на лету + пересчёт ВП по диапазону дат). Для одного выбранного
месяца это нормально (так и работает "По менеджерам"), но для графика по ГОДУ (до 12 точек
разом) пересчитывать всё на лету при каждом открытии страницы - медленно и не нужно, эти
цифры не меняются задним числом (кроме текущего месяца). Нужен лёгкий кэш - сводная таблица
"месяц -> ключевые цифры", которая копится по ходу дела и не пересчитывается с нуля каждый раз.

## Фазы

### Фаза 1. Бэкенд: сводный лист по месяцам (~1 час)
- [ ] Новый лист `История_месяцев`: Месяц (YYYY-MM) | Выручка | Выручка план | ВП (свой парк) |
      ВП тралы | ВП длинномеры | ВП план | Маржа найма (выручка/прибыль найма) | Обновлено (дата)
- [ ] `saveMonthSummary_(ss, monthKey)` - считает строку для месяца через уже существующие
      `getOrdersDataForPeriod`/`getGrossProfitForPeriod` (или `getSummaryData`/`getOrdersData`
      напрямую, если monthKey - текущий месяц) + `computeSalesFaktPlan_`, идемпотентно
      перезаписывает строку этого месяца (не дублирует, как `saveDebtHistory`/`saveFinancialHistory`)
- [ ] В `runAll()` - вызывать `saveMonthSummary_(ss, currentMonthKey)` на каждом прогоне,
      чтобы текущий месяц в сводке был свежим внутри дня (не только на конец месяца)
- [ ] Разовая функция `backfillMonthSummaries()` - проходит по всем месяцам, для которых
      есть архив `Заказы_YYYY-MM`, и считает `saveMonthSummary_` по каждому. Влад запускает
      вручную один раз в редакторе, дальше не нужно (см. `project_apps_script_trailing_underscore` -
      имя без `_` на конце, чтобы было видно в списке "Выполнить")

### Фаза 2. Бэкенд: эндпоинт для фронтенда (~20 мин)
- [ ] `action=global_stats` -> `{ months: [...] }`, читает `История_месяцев` целиком,
      сортирует по месяцу
- [ ] Текущий месяц в ответе - подменять на live-расчёт (не на то, что лежит в кэше), чтобы
      "сегодняшняя" точка на графике не отставала от последнего `runAll()` - тот же приём,
      что уже applies для "Панели" (всегда живые данные для текущего периода)

### Фаза 3. Фронтенд: страница "Глобальная статистика" (~1.5 часа)
- [ ] Пункт в сайдбаре (иконка + `showPage('global-stats', this)`)
- [ ] Верхний блок - выбор месяца (тот же паттерн, что уже на "По менеджерам": выпадающий
      список из `available_periods` + "Текущий месяц"), под ним - карточки ключевых метрик
      этого месяца (переиспользовать вёрстку карточек с "Панели": Общая выручка, Валовая
      прибыль с разбивкой тралы/длинномеры, Выполнение планов)
- [ ] Нижний блок - график по году (Chart.js line/bar): выручка и ВП по месяцам, план -
      пунктирной линией там, где он есть
- [ ] Загрузка `action=global_stats` один раз при первом заходе на страницу (как
      `loadHistoryData()` для "Динамики"), не при каждом рендере

### Фаза 4. Проверка и деплой (~20 мин)
- [ ] `backfillMonthSummaries()` запущен вручную Владом, все текущие архивные месяцы
      (минимум 2026-06, 2026-07) корректно легли в `История_месяцев`
- [ ] Цифры за конкретный месяц на новой странице совпадают с тем, что показывает
      "По менеджерам" при выборе того же месяца (сверка, не должно расходиться)
- [ ] График по году не падает, если данных меньше 12 точек (начало вёрстки истории)
- [ ] Деплой по обычному протоколу (`clasp pull` -> diff -> push -> create-version -> redeploy
      -> запись в `DEPLOY_LOG.md`)

## Критерии готовности

- [ ] Можно выбрать любой месяц с архивом и увидеть его выручку/ВП/план так же, как сейчас
      видно только для текущего месяца на "Панели"
- [ ] График по году строится без ручного пересчёта, из кэша `История_месяцев`
- [ ] Текущий месяц на графике не отстаёт от реальных цифр (обновляется на каждом `runAll()`)
- [ ] Нет расхождений между этой страницей и уже существующими вкладками за один и тот же месяц

## Риски

- ВП по парку для архивного месяца зависит от `Данные_1С_история` - если за какой-то месяц
  этот архив не был создан вовремя (отчёт парка не был настроен, как ровно сейчас с августом),
  `История_месяцев` для него останется пустой/неточной. Не глушить молча - показывать явно
  "нет данных за месяц", а не 0 или устаревшую цифру.
- `saveMonthSummary_` на каждом `runAll()` - лишняя нагрузка на таблицу, если считать текущий
  месяц через полный `getOrdersDataForPeriod`-путь (разбор архива) вместо `getOrdersData`/
  `getSummaryData`, которые и так уже посчитаны в этом же прогоне - использовать готовое,
  не пересчитывать заново.
- `backfillMonthSummaries()` может быть медленной на большом числе месяцев сразу (Apps Script
  6-минутный лимит на выполнение) - если понадобится, разбить на несколько запусков по частям.

## Открытые вопросы

- Набор метрик - только Выручка + ВП (тралы/длинномеры) + планы, или добавить сюда же Маржу
  найма и Дебиторку? У ДЗ уже есть своя история/тренд на вкладке ДЗ - предлагаю НЕ дублировать
  её здесь, оставить фокус на выручке/ВП/планах. Маржу найма - добавить, если Влад скажет.
- "Динамика по году" - календарный год (январь-декабрь) или "все месяцы, что есть в архиве"
  (сейчас это июнь-июль плюс копится дальше)? Предлагаю показывать всё, что есть в
  `История_месяцев`, без искусственной обрезки по календарю - решить с Владом при ревью плана.
- Нужны ли на этой странице прошлые ГОДА (2025 и раньше) - если для них нет архивов заказов
  в этой таблице, эти данные просто недоступны без отдельного источника. Пока не в скоуп.
